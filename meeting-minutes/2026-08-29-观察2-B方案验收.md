## 三、「光标停末尾 = 既有实现非本次引入」独立复核 —— **同意安栋**

依据：

1. **改动范围实锤**：bfee8192 全 diff 仅一行 `menuAnchor(MenuAnchorType.PrimaryNotEditable)` → `PrimaryEditable`（`git show` 核对），不触碰 selection/值逻辑。
2. **问题代码的引入提交早于修复**：建议行 `onClick = { onChange(item); expanded = false }` 与 String 型 `value`（非 TextFieldValue）均由 **56c7b9db**（feat: 地址编辑接入层级树级联选择）引入（`git log -S` 实证），比 bfee8192 早多个提交。
3. **机理与锚点类型无关**：String 重载 TextField 在外部改值时按旧偏移钳制保留 selection（旧值 `bar` 光标在 offset 3，新值 `Barangay 6` 长 11，偏移 3 原位保留 → 光标停在 `Bar|`），这是 Compose String-value 输入框的固有行为；锚点类型只决定弹窗焦点语义，不改 selection 映射。
4. **旁证**：修复前主路径（空输入点选）同样走 onChange(item)——空值旧偏移 0，点选后光标落值首而非末尾，同一机理在修复前已可观测。

修复方向判定：需 `TextFieldValue` 改造（或点选后显式 `selection = TextRange(item.length)`）并在真机回归 4/6 两条断言，**另行立项合理**，工作量小但涉及 CommunityField 状态结构，不宜混入本次锚点修复。
