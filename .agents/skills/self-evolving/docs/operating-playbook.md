# Self-evolving 工程执行手册

> 目标：把经验、调试、委托、布局和收尾固化为可执行模板。每次任务只增补真实证据，不凭空扩写。

## 1. 开工模板

```text
【任务】<一句话交付物>
【能力域】<A 域> 【Agent】<B> 【internal 包】<C> 【阶段】<N> 【页面】<D 页面清单>
【背景】<现状、用户价值、已知缺陷>
【需求描述】
- <行为级需求>
- <不做/不碰边界>
【起始条件】
- <真实环境、数据、基线、凭证引用>
【结束条件】
- <代码/文档产出>
- <自动化验证>
- <102 真实环境验证>
- <git clean、合并、清理>
【约束】
- worktree 开发，禁止直接修改 main
- 每个独立变更先测试，立即单一提交
- 使用真实 102 后端，不 mock，不在本机启动业务服务
- 合并前 feature 侧同步 main；ff 合并成功后再移除 worktree 和分支
```

## 2. 问题拆解模板

```text
现象：<可复现症状>
证据：<命令/日志/响应/截图路径>
假设：<最多三个可证伪原因>
最小复现：<单测、curl、SQL 或 CDP 步骤>
排除顺序：<先高信号、低成本检查>
修复：<最小范围变更>
回归：<原问题 + 邻近边界 + 真实环境>
未验证：<明确列出缺少的证据，不用“已适配”替代>
```

### 调试顺序

1. 先确认目标 worktree、`git status --short --branch` 和基线提交。
2. 先读契约、实现、测试，再判断问题属于代码、数据、部署还是客户端缓存。
3. 先拿高信号证据：Go 循环看容器日志再查表；API 先查响应信封；UI 先看 CDP console/网络。
4. 用最小复现把代码问题与环境漂移二分；不要用 healthz、build 或截图替代行为证据。
5. 修复后先针对性测试，再全量门禁；每个独立变更立即 commit。
6. 真实环境验证记录 URL、身份、请求、响应和时间；无法验证就记录为缺口。

## 3. 后端/数据调试模板

```text
接口：<METHOD URL>
身份：<account/worker/customer，权限码>
请求：<脱敏 JSON>
响应：<HTTP、业务 code、关键字段>
日志：<容器、时间窗口、关键错误>
数据：<表/查询/行数，必要时清理方式>
结论：<代码正确/部署漂移/数据问题/权限问题>
```

- 102 服务固定为 `http://192.168.0.102:28080`，admin API 使用 `/api/admin/v1`。
- 循环类功能：先 `docker ps` 看容器启动时间，再 `docker logs --since ... | grep 关键字`，最后查表。
- 远端数据库查询优先使用已配置的 pgx 临时程序或远端容器 psql；SQL 必须带结果行数或状态断言。
- nullable 列、时区、占位符类型和真实 ID 都按字段契约核对，不能凭直觉猜。

## 4. 前端/UI 调试模板

```text
页面/主题/语言/视口：<URL + 状态>
DOM：<目标元素、文本、可见性、交互后状态>
网络：<请求 URL、方法、状态、响应字段>
Console：<错误/警告>
样式：<computed token/value>
截图：<路径；模型不能读图时标注人工目测项>
结论：<已证实行为/仍缺证据>
```

- 日常调试使用 `cdp-capture.mjs`；Playwright 仅用于 `e2e/` 自动化。
- 交互必须断言点击后的控件文本、筛选结果和 URL；双主题至少检查计算样式或截图。
- 颜色先 grep token 定义再引用；禁止原生 `<select>`，复用项目 Dropdown。

### 布局技巧固定模板

```text
信息层级：<页面标题 → 区域标题 → 字段/状态 → 主次操作>
布局骨架：<外层/列/滚动容器/固定操作区>
间距节拍：<同组紧、跨语义远；按 4×N 栅格>
尺寸：<触控/点击目标、行高、卡片最小高度；从设计稿量取>
对齐：<按钮文字水平垂直居中；图标与文字基线和视觉重量匹配>
响应式：<断点、列数、溢出与滚动行为>
主题：<背景/文字/边框/焦点/禁用态的成对 token>
验收：<DOM 交互 + computed style + 双主题 + 响应式截图>
```

布局硬规则：按钮文字必须居中并留足四向内边距；元素按语义亲密度采用 4×N 间距；图标大小与相邻文字匹配；容器先检查 box-sizing、flex 最小宽和横向溢出；撑满父级的块不要叠加 `width:100%` 与 padding。

## 5. 经验沉淀模板

每次完成后追加到 `.agents/skills/self-evolving/notes.md`：

```text
## YYYY-MM-DD <任务名>
- 最大坑：<最耗时问题与根因>
- skill 是否预警：<有/无；对应文件或条目>
- 重来一次：<第一步会怎么改>
- 新调试技巧：<场景 → 证据 → 命令/步骤 → 判据>
- 未完成证据：<真实环境或人工验收缺口>
```

只有真实踩坑或查证过的技巧才写入 `references/lessons.md`、`known-issues.md`、`techniques.md`；重复错误同步 `recidivism.md`，次数达到 2 次才升级 SKILL.md 高频红线。经验索引同步更新 `references/knowledge/`，避免新知识只藏在日志里。

## 6. 收尾模板

```text
[ ] worktree 分支已 push 到 gitea
[ ] feature 内 merge main，门禁重新通过
[ ] 主树 ff-only 合并成功
[ ] worktree remove 后 branch -d
[ ] 远端 feature branch 删除
[ ] git worktree list / git status --short 均干净
[ ] 102 实机证据已记录；缺口明确标注
[ ] 反思 notes + references 已 commit 并 push
```
