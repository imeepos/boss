## 6. 授权强制门禁下的部署验收事实(2026-09-26 实测)

```
2026-09-26 实测:102 /healthz 返回 {"status":"ok"}、POST /auth/login(admin/admin123) 返回 code=0
同时,业务 API 整体返回 {"code":"LICENSE_REQUIRED","msg":"system license required"}
(main 已合入 ci(deploy-102) 生产镜像注入授权公钥的强制门禁提交)。
结论:部署/回归验收必须分三层记录——进程存活(/healthz)、登录鉴权(login)、目标业务接口;
前两层通过不代表第三层可用;目标层被授权阻断时如实标记"环境未过验收",
不修改业务代码绕过授权,也不宣称业务回归通过。
```

## 2026-08-29 柜面收款部署事实(102 现行态 + 0010 事故硬规则)

- **部署唯一路径 = push main 触发 gitea CI(Build-Deploy-to-ECS)**:app 启动自动跑迁移(database.Migrate);严禁手动 docker build/compose up——手动构建漏 BOSS_LICENSE_PUBLIC_KEY_HEX(镜像沦为开发态),手动 compose up 项目名与 CI(boss-app)不同会静默换卷(postmortem 0010)。
- **compose 项目名决定卷名**:CI 卷 boss-app_boss_license_data(license.json 所在,uid 1000:1000 640);deployments 项目会新建 deployments_* 空卷。持久化文件"消失"先核对 `docker inspect --format '{{.Mounts}}'`,恢复=从 CI 卷拷回+uid 对齐+重启。
- **server.Dockerfile 公钥 fail-fast(0010 后新增)**:BOSS_LICENSE_PUBLIC_KEY_HEX 为空且未显式 ALLOW_DEV_LICENSE=1 → 构建即失败;本地开发态构建传 `--build-arg ALLOW_DEV_LICENSE=1`。
- **授权指纹绑定容器 hostname**(docker-compose.102.app.yml 固定 boss-server),证书 /var/lib/boss/license.json 在命名卷,容器重建不丢;诊断入口 GET /license/status(activated/enabled/reason)。
- **上线验收清单固定模板**见 templates.md 模板 N(healthz → /license/status → bossctl 分角色断言表 → UI cdp-capture DOM 断言 → 造数清理:流水走退款留痕/参数与回填行删除)。

## worktree .env 自动接入机制(2026-09-04)
- git worktree add 会触发 post-checkout 钩子(实测);core.hooksPath 用相对路径时按「钩子执行 cwd」解析,即每个 worktree 用自己检出的 .githooks,一份配置全仓生效。
- git config 不随 clone 传播:全新 clone 钩子默认不生效,需一次性引导 sh scripts/env-hooks-init.sh;引导脚本按脚本自身位置解析仓库,跨 cwd 调用安全。
- 用户直接调用的工具脚本禁止依赖调用方 cwd——按脚本自身位置(\$0)解析仓库;cwd 敏感逻辑只留给钩子。
- 验证不读 .env 内容:cmp/shasum 字节级断言即可覆盖复制/不覆盖/未变全部验收点;自测脚本 scripts/env-provision-selftest.sh 沙箱五场景。

## 102 部署与并行验收(2026-09-05 W-0907 实证)
- push main 到 gitea 后自动部署管道会更新 102(实证:push 后约 25 分钟 boss-server/admin-web 容器重建,healthz commit 对齐);部署前先 `docker ps` 看容器 uptime + scripts/ops/verify-deploy.sh 核 healthz commit,别急着手工部署。
- verify-deploy「FAIL server commit 差 1 个纯 docs 提交」= 管道在 docs 提交前构建,功能无差;--feature 特征串命中 bundle 即可判功能已上线。
- 多会话并行跑 make check 时,Go 构建缓存锁会让并发的 go test/build 挂到超时;验收脚本改跑范围收窄包(go build ./internal/xxx/... ./cmd/yyy/...)+ 空闲窗口复跑全量。
