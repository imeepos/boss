## 5. 公网隧道链路（2026-08-22 搭建，已验证 200）

```
公网入口: http://43.240.223.138:5180  (nginx sites-enabled/boss-5180, ufw 已放行)
   ↓ proxy_pass
138 loopback 127.0.0.1:15180 (GatewayPorts=no, 远端只能绑 loopback)
   ↓ SSH 反向隧道 (102 systemd: boss-5180-tunnel, restart=always)
102 127.0.0.1:5180
```

- 138 登录: `ssh ops@43.240.223.138`(22 端口, ops 免密 sudo);旧配置 public-box(25446)/2222 均已失效(ufw 未放行)。
- 102 的 key 在 138 authorized_keys 带 `restrict,port-forwarding` 前缀(仅允许转发,禁 shell)。
- 排障顺序: 102 `systemctl status boss-5180-tunnel` → 138 `ss -tln | grep 15180` → 138 `curl 127.0.0.1:15180` → 公网 curl。

### 28080 后端 API 映射（2026-08-22 第二条，同模式复制）

```
公网 http://43.240.223.138:28080 (nginx sites-enabled/boss-28080, ufw 已放行)
  → 138 127.0.0.1:28081 → 102 systemd boss-28080-tunnel → 102:28080
  验证: curl http://43.240.223.138:28080/healthz → {"status":"ok"}
  注意: nginx 公网监听端口不能与隧道远端口相同(28080/28081 错开),否则 loopback 绑定冲突。

### Mac(192.168.0.15):8443 → 138 公网（2026-08-22 第三条，带 Basic Auth）

```
公网 https://43.240.223.138:8443 (自签证书, admin/123qwe)
  → 138 nginx sites-enabled/mac-8443: auth_basic + proxy_pass https://127.0.0.1:18443
  → 138 loopback 18443 → Mac LaunchAgent com.ymm.tunnel-8443 → Mac 本机 nginx 8443
```

- 坑: htpasswd 文件 640 root:root 时 nginx worker(www-data) 读不到 → 认证请求 500(而非 401);修法 chown root:www-data。
- Mac 常驻隧道用 LaunchAgent(KeepAlive+RunAtLoad), 不用 autossh(macOS 无)。
