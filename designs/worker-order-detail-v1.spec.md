# 师傅端·工单详情(worker-order-detail-v1)

> 适用：`mobile/worker` 工单详情页 + `docs/worker/order.html` 落地实现。
> 设计稿：`designs/worker-order-detail-v1.png`(4 屏拼版,1536×1024)。
> 数据契约:`api/openapi/worker/{ticket,schemas}.yaml` 的 `GET /tickets/{ticketNo}` (`TicketDetail` schema)。
> 视觉风格：`docs/worker/UI-SPEC.md`(与用户端 token 同源,主蓝 `#086CF5`)。

---

## 1. 页面定位

师傅在"工单/任务池/任务详情/历史"等路径打开工单后的详情落地页。
**强高频路径**:师傅打开详情页 80% 场景是已领取且作业中的工单(状态=`DOING`),因此 4 屏拼版中以"新装进行中"为视觉主路径,左侧第 1 屏(A)即为该状态。

---

## 2. 4 屏状态拼版(4-state拼版)

| 屏 | 工单类型 | 状态 | 触发场景 | 关键差异 |
|---|---|---|---|---|
| **A** | 新装 (INSTALL) | `DOING` 装维中 | 师傅作业中(默认主路径) | 12 环节时间轴 + 扫码绑定主按钮 |
| **B** | 报障 (REPAIR) | `DOING` + 紧急 SLA | 单户断网等应急工单 | 6 环节时间轴 + SLA 倒计时 + 修复上报主按钮 |
| **C** | 新装 (INSTALL) | `TODO` 待领取 | 任务池/Hall 抢单 | 全灰未开始时间轴 + 单一"领取工单"主按钮 |
| **D** | 新装 (INSTALL) | `DONE` 已完成 | 历史工单/已签 | 全绿已过时间轴 + 完成回执 + 客户签名 |

> 设计决策(频率分层):A 屏虽与 C/D 同宽,但**信息密度最高**——12 环节时间轴 + 完整按钮区全部在场,
> C 屏按 FEEDBACK C 区规则"低频状态收敛为入口级元素",只保留 1 个主按钮。
>
> 频率参考:DOING(80%) >> TODO(15%) >> DONE(5%),但 4 屏等宽以保视觉对照。

## 5. 状态机/契约绑定(实现必查)

```
状态机:
  TODO → (accept) → DOING → (scan/activate/repair) → DONE
                  ↓ (transfer)
                  → 转派/退回任务池

接口契约(GET /tickets/{ticketNo}):
  - 返回 code=0 + data 严格按 schemas.yaml::TicketDetail
  - stages[] 长度 = stageTotal(12 或 6)
  - quad.status ∈ {LINKED, CONFLICT, UNLINKED}
  - riskCheck.blacklistHit/graylistHit 必返,布尔值
```

## 6. 已知禁忌 / 不允许实现编造

- ❌ **环节名禁止改字**:`terms.md` §1 已固化 12 环节命名,任何 UI 文案必须逐字复用
- ❌ **状态名禁止缩写**:不能写"完成"/"待领"等口语,严格用 `statusLabel` 字段值
- ❌ **不允许前端编造四码值**:`quad.*` 为空时显示 `-`,不写"未知"
- ❌ **不允许编造 SLA 时间**:`slaLeftMinutes` 缺失时整块不渲染(只 B 屏报障)
- ❌ **不允许编造客户签名**:D 屏签名位为空时显示虚线框 + 占位文字,不放预置签名
- ❌ **底栏主按钮禁用实心绿色/橙色**:统一蓝实底 `#086CF5`,完成用"绿色 ✓ + 文案",非按钮色
