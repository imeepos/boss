# 用户端·实名认证流程（多步骤+多状态）实现规格（对应 realname-flow-states-v1.png）

> 一图四屏总览：①填写信息 ②证件上传 ③审核中 ④通过/驳回双状态（示例合集）。
> token 事实源：`designs/UI-SPEC.md`；本 spec 与其同源，位图 dp 值以此处为准。

## 给前端的实现提示词（可直接复制）

实现移动端（iOS 视觉语言、H5 或原生均可）的实名认证分步流程，共 3 步 + 4 种状态页，高保真还原附图。

- 整体布局：每屏 = 顶部蓝色渐变 Hero（含 iOS 状态栏安全区、返回箭头、居中标题"实名认证"、三步 Stepper：填写信息-证件上传-审核状态）→ 浅灰 `#F6F8FA` 滚动内容区（白色圆角卡片纵向排列，卡片 10dp 圆角、卡内 padding 16dp、卡片间距 8dp、页边距 16dp）→ 底部主操作区（含 Home Indicator 安全区）。
- Stepper：单一样式组件，当前步实心蓝 `#086CF5`、已完成蓝+对勾、未完成灰 `#AEB4BE`，标签 12sp；四屏复用同一组件，只切换 current。
- 色彩：主蓝 `#086CF5`；Hero 渐变 `160deg #0872F4→#0B82F8→#1698FA`；页底 `#F6F8FA`；卡片 `#FFFFFF`；success `#0AA847`/底 `#EFFFF4`；warning `#F57900`/底 `#FFF5E8`；error `#FF2D2F`；文字 `#171B23`/`#5F6671`/占位 `#AEB4BE`；分割线 `#E7EAF0`。
- 字体层级：H1 卡片标题 16sp/700；H2 条目标题 15sp/600；Body 14sp/400；辅助 12sp；脱敏号码 tabular-nums。
- Screen1 填写信息：安全说明卡（盾牌图标+两行说明）；表单卡内四行：真实姓名 / 身份证号 / 手机号（预填脱敏、只读样式）/ 短信验证码（右侧"获取验证码"文字按钮）；协议勾选行（未勾选时"下一步"禁用置灰 `#AEB4BE`，勾选后启用蓝实底）。
- Screen2 证件上传：拍摄要点提示卡；人像面上传卡与国徽面上传卡（已上传：图片预览+绿色对勾角标+"已上传"文字+点击可预览/重传；待上传：虚线框+相机图标+引导文案）；两面均上传成功前"提交认证"按钮禁用。
- Screen3 审核中：状态卡（蓝色时钟图标+"审核中"+预计 1-2 个工作日，出现一次不重复）；认证信息摘要卡（姓名/证件号/手机号均脱敏、提交时间）；流程时间线（已提交=蓝实心节点，审核中=蓝色高亮节点，认证完成=灰描边节点）。
- Screen4 状态结果（两个互斥页面，图中为合集示意）：已认证页=绿色对勾大图标状态卡+认证时间；驳回页=橙色警示卡+驳回原因+驳回时间+"重新提交"按钮（白底、文字与描边统一用 warning 橙 `#F57900`，不用红）。
- 交互状态：输入行 default/focus（蓝色下划线）/error（红字原因，仅失焦或提交校验后展示）；验证码按钮 default/倒计时（"59s后重发"灰字）/禁用；上传卡 待上传/上传中（进度）/已上传/失败（红角标+重试）；提交按钮 loading（转圈+禁用）。
- 数据接口（字段待后端定义）：realName, idCardNo(masked), mobile(masked), smsCode, idCardFrontUrl, idCardBackUrl, verifyStatus(pending/approved/rejected), rejectReason, submitTime。

## 注意事项

- 第4屏的"通过/驳回"是设计稿的状态合集示意，实现时必须拆为两个互斥页面，按 verifyStatus 条件渲染。
- 图中证件示例文字、姓名"张小明"等均为占位假数据，真实证件图必须脱敏展示并加"示例"水印由后端控制。
- 协议/证件未完成时按钮禁用逻辑图中未严格表达，以本 spec 为准。
- 驳回"重新提交"按钮色彩按 warning 橙统一，纠正图中红/橙混用。
- 位图比例不严格：行高 ≥48dp、按钮 ≥44dp、辅助文字 ≥12sp 以本 spec 数值为验收标准，不按图上比例照抄。
- 响应式：以 375-430dp 宽为基准；深色模式未设计，token 预留 data-theme 扩展。
- 可访问性：辅助文字对比度 ≥4.5:1；状态双线索（颜色+图标+文字）；焦点样式可见。
