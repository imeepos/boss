# 2026-08-22 开放平台应用密钥:HMAC Secret 原文落库

## 决策

Q4 开放平台（openplat 域，迁移 000121）的外部应用凭证采用 **AppId + Secret + HMAC-SHA256 请求签名**，
Secret **原文存放在 `open_apps.secret` 列**，不哈希。

## Why

- 开放面是对外 HTTP API，签名认证（请求级完整性、可防重放）是行业底线，优于裸 bearer token。
- HMAC 验签要求**服务端持有原文**重算 MAC；只存哈希（如内部 api_keys 的 sha256 做法）则无法验签。
  这是与 000042 api_keys 的本质差异，不是疏忽。

## 放弃了什么

- 不沿用 api_keys 的"只存哈希"模式——对外签名场景不可行。
- 不做 Secret 的应用层加密（KMS/envelope）：当前单实例部署 + DB 访问面可控，
  加密密钥仍需落在同环境，收益有限。数据库泄露时 Secret 暴露的风险由 DB 层访问控制 + 审计兜底。
- v1 不做 nonce 去重存储（防重放仅靠 ±5 分钟时间戳窗），沙箱阶段（M4）再评估补齐。

## 影响面

- `open_apps.secret` 列属敏感数据：管理端任何查询接口不回显（仅创建响应返回一次）。
- 轮换策略：停用旧应用 + 新建应用（v1 不做原位轮换）。
- 若未来引入 KMS，只需替换 PGStore 中读写 secret 的两个点，接口不变。
