# order_no 改为 DB 序列生成

日期：2026-08-17（补记于 2026-08-18，来源提交 5fb7cb0）

## 决策

订单号 `order_no` 由进程内自增改为 PostgreSQL 数据库序列（`nextval`）生成。

## why

真实 PG 端到端测试暴露：服务重启后进程内计数器归零，与既有订单撞号。DB 序列在重启、多实例、并发下天然唯一，且实现成本低于其他方案。

## 放弃了什么

- 进程内自增：重启撞号（本次事故直接原因）。
- UUID：对外单号可读性差，客服/装维口头报单不便。
- Redis 计数：多一次网络往返与一个故障域，序列无此负担。
