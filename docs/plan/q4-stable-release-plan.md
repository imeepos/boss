## 执行顺序

1. **契约对账**：以 `api/openapi/*.yaml` 为契约源，对 102 环境实测路由全量对账，输出差异与销项。
2. **SLO/SLI**：定义 API 延迟、认证成功率、订单完成率、消息延迟、话单完整率、报表时效六类指标；确定采集方式（访问日志/DB 聚合）与目标值。
3. **发布列车**：固化版本号规则、变更评审、灰度、回滚、发布后验证清单。
4. **压测**：基于 `scripts/load/api-load.js` 扩展场景，出容量基线。
5. **迁移/灾备/回滚演练**：在 102 之外的隔离环境执行并记录。
6. **1.0 收口**：验收包、运维手册、培训材料，全部文档过 `make check` 门禁后合并。

## 约束

- 所有对账/压测/演练均打真实 102 环境（或其隔离副本），不 mock。
- 每个交付物独立提交，`type(scope): subject` 纪律照旧。
- 契约相关结论与 `docs/contract/alignment-audit.md` 编号体系（D/A/B/E/G#）互通。
