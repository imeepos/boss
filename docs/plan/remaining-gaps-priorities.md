## 2. P1 优先级：可独立执行、无外部资质依赖

### 2.1 数据治理底座（指标目录 + 血缘 + 质量闭环）

- **优先级**：高
- **外部依赖**：无
- **预估工作量**：2—3 周
- **理由**：AI 治理、预测维护、经营驾驶舱全部依赖指标目录和数据质量；先做这一步，后续智能化能力才有事实源。
- **核心任务**：
  - 建立 `metric_catalog` 表（指标名称、定义、公式、维度、负责人、刷新频率、版本、状态）
  - 提供 OpenAPI/handler 进行 CRUD、版本切换、查询
  - 登记现有 analytics/report 指标到目录
  - 建立主题域模型：订单、客户、资源、AAA、账务、CS/AR、渠道、PROMO/LOY
  - 补 ETL/投影任务台账和数据新鲜度看板
  - 数据质量规则：完整性、唯一性、及时性、跨域一致性
  - 质量异常进入 P0 已合并的补偿任务中心
- **验收**：
  - 核心指标 100% 有定义、负责人、版本
  - 报表/驾驶舱口径一致
  - 关键质量异常可发现、派单、修复、复核

### 2.2 PORT 客户门户完整旅程

- **优先级**：高
- **外部依赖**：无
- **预估工作量**：2—3 周
- **理由**：客户自助门户是业务闭环的重要入口；当前 `docs/user` 已有 MVP，但缺少完整端到端流程。
- **核心任务**：
  - 完整客户旅程：浏览产品 → 下单 → 支付 → 查发票 → 查订单进度 → 报障 → 查券/积分
  - 补统一导航和路由
  - 补订单详情页、报障表单、服务变更入口
  - 与三端身份权限对齐（JWT/API key、数据域权限）
  - 弱网、重复提交、支付回调异常测试
- **验收**：
  - 客户独立完成端到端流程
  - 与 admin/worker 三端身份一致

### 2.3 多语言 user/worker 端

- **优先级**：中
- **外部依赖**：无
- **预估工作量**：3—4 周（78 个页面+Android 端）
- **理由**：差距审计明确登记为缺；admin 已有三语基础，可复用模式。
- **核心任务**：
  - `docs/user/*.html`、`docs/worker/*.html` lang 属性三语切换
  - `nav.js` 统一语言切换器
  - 三语字符串集中维护（zh-CN/en-US/ms-MY）
  - 日期、金额、错误文案统一
  - user/worker Android 端 `values-zh`、`values-en`、`values-ms` 资源补齐
- **验收**：
  - 78 个页面在三语下显示一致
  - 关键错误文案无硬编码

## 3. P2 优先级：需要性能/可观测基础

### 3.1 性能与 SLO 优化

- **优先级**：高
- **外部依赖**：无（需本地基准数据）
- **预估工作量**：1—2 周
- **理由**：压测超阈值问题、订单推进核心路径优化、关键真实业务 SLO 收集。
- **核心任务**：
  - 100 VU 读 P95 574ms 慢 SQL 定位
  - 登录 P95 858ms 链路优化
  - 索引、连接池、序列化优化
  - 重压测验证阈值
- **验收**：阈值达标、压测报告

## 4. P3 优先级：依赖外部资质

### 4.1 AI 辅助运营平台

- **优先级**：中（依赖数据治理底座）
- **外部依赖**：**真实 LLM key**
- **预估工作量**：4—6 周
- **核心任务**：
  - AI 网关：模型路由、限额、成本、调用审计、fallback
  - 第一个场景：客服摘要或工单分类（低风险）
  - 评测集和人工确认
- **阻塞**：需 user 提供 AI provider key 或批准使用 demo provider

### 4.2 预测性维护

- **优先级**：中
- **外部依赖**：**设备真实数据**
- **预估工作量**：4—6 周
- **核心任务**：
  - 设备指标/告警/工单特征
  - 故障/容量预测
  - 维护优先级
  - 审批编排
- **阻塞**：需 102 真实设备数据

## 5. P4 优先级：需双区域真实环境

### 5.1 规模复制准备

- **优先级**：低（最后做）
- **外部依赖**：**至少两个真实区域或法人**
- **核心任务**：
  - tenant 模型
  - 多时区、多币种
  - 国际化 tenant 隔离
  - 双区域复制验收
- **阻塞**：必须有真实第二区域或法人环境

## 6. 推荐下一轮开发顺序

1. **数据治理底座**（无外部依赖、是后续智能化基础）
2. **PORT 完整客户旅程**（独立、闭环价值高）
3. **多语言 user/worker**（独立、可借鉴 admin 模式）
4. **性能与 SLO**（依赖业务基线采集）
5. **AI 辅助运营**（需外部资质）
6. **预测维护**（需真实设备数据）
7. **规模复制**（需双区域）
