# 批量数据专用流程设计清单

> 2026-09-03｜本文件是后续开发输入，不授权将以下页面接入普通实体导入器。

## 设计总则

专用导入必须遵循“权限校验→业务前置校验→预览/审批→提交→结果任务→审计/可重试”的链路。每类流程使用本域状态机和权限，不以 `POST /import-tasks` 替代业务执行器，不绕过订单、实名、审核、财务或税务流程。

## 优先级清单

| 优先级 | 页面/对象 | 推荐流程 | 不可绕过的前置 |
|---|---|---|---|
| P1 | 资产/标签/端口 | 置备批次导入：先建批次/资源，再按依赖顺序校验并提交，最后进入可用状态 | 法人、地址、资源/批次、EPC、四码关联、生命周期状态；网络运维/资产权限；逐行审计和失败行重试 |
| P1 | 官网内容/分类 | 文件解析为 CMS 草稿批次，人工确认分类/封面/正文后逐条发布 | slug 唯一、Markdown/附件引用、分类引用、禁止导入即 PUBLISHED；CMS 编辑/发布权限 |
| P1 | 企业员工 | 企业管理员提交邀请批次，逐条校验用户名并生成待接受邀请，接受后才激活账号 | 当前企业边界、角色白名单、密码/邀请安全策略、停用审计；不能复用后台 account 导入 |
| P1 | 师傅/实名 | 注册申请批次只进入审核队列，审核员逐条补齐班组/区域并执行实名核验 | groupId、regionId、实名材料和 PASS 结果；审核通过才建立 worker 主档 |
| P2 | 经营区域 | 先导入树节点草稿，再校验 path/level/父节点，发布后执行法人覆盖 | 四级树顺序、path 唯一、覆盖主体合法性；区域管理员权限 |
| P2 | 配置模板 | 模板文件进入版本草稿，兼容性检查后逐版本启用，支持灰度、回滚 | 法人、设备型号、内容 schema、版本引用、生产变更审批；禁止平面覆盖启用模板 |

## 任务和幂等要求

- 每批生成服务端任务 ID 和客户端幂等键，预览、审批、提交、重试状态分离。
- 失败行保存原始输入、字段错误和业务错误；重试只允许未成功行，不重复执行已确认状态迁移。
- 任务查询须显示操作者、权限主体、输入摘要、成功/失败/跳过、审批人和审计链接。
- 大批量应使用 staging 表或对象存储文件，不由浏览器串行承担长任务；正式提交由后端分块事务处理。

## 非目标

本设计不新增普通导入入口，不改变现有页面状态枚举或 API 语义；实现前必须由对应域负责人确认字段、状态、权限和真实数据清理方案。
