## 4. W1 承包商与工程结算

需求（业务口径，实现方式由执行会话设计）：
1. 供应商档案增加承建类型维度（材料类/施工类），施工类含资质信息与联系人；存量数据兼容，既有页面语义不变。
2. 施工项目可指定承包商（引用供应商档案）；未指定允许，存量项目兼容。
3. 施工明细升级为工程量清单：每条明细可带数量与单价；金额一律后端计算（数量×单价），前端仅展示。
4. 工程结算：项目验收（ACCEPTED）后可发起结算；结算单汇总清单金额形成应付；状态机自行设计但必须登记进 terms.md，作废与重开规则明确；全部写操作入审计，失败路径留可 grep 日志。
5. admin 在既有施工项目管理页内完成承包商指定、清单编辑、结算发起与列表；不新增菜单分组、不动中央登记文件。

验收规则（机械可验）：
1. make check 全绿（含契约同步与迁移撞号检查）；web/admin pnpm typecheck、test、build 全绿。
2. 迁移号预分配 000203（供应商类型）、000204（施工清单与结算），up/down 成对；开工前重跑占号两处核查（本地 ls migrations + git fetch gitea 后逐分支 ls-tree）。
3. 102 环境（http://192.168.0.102:28080，admin 前缀 /api/admin/v1）真实接口验收：建施工类供应商→建项目挂承包商→录清单→推进 ACCEPTED→发起结算→查询结算单；curl 断言金额与状态正确。禁止 mock 数据、禁止本机起服务；CI 未部署时上报负责人等待。
4. 契约三件套同步：terms.md 新枚举、fields.md 页面列、domain-map.md 域归属；契约与登记类改动压独立小提交。

## 5. W2 网格投资测算读模型

需求：
1. 按网格只读聚合四组指标：设施数（按生命周期 PLANNED/IN_BUILD/IN_SERVICE/RETIRED 分组）、覆盖地址数（SERVED/PENDING/UNSERVED）、已结算工程成本（读 W1 结算数据；W1 未合并或网格无数据时显式「未登记」，禁止显示 0）、每可装地址成本（已结算成本÷SERVED 地址数；分母为 0 时同样「未登记」）。
2. admin intel 分组新增「投资测算」页：列表展示上述指标列，支持按任一数值列排序；空数据网格展示空态。W2 是本期唯一允许新增菜单页与触碰中央登记文件（menu.def.ts/App.tsx/i18n types+locale）的工作流。
