## P0 — 数据治理闭环补全（本阶段遗留最后一公里）

### 提示词 1：ETL 新鲜度派单闭环

```
【任务】让 ETL 新鲜度补偿派单在任务恢复后自动关闭
【背景】逾期任务会生成补偿派单（OPEN），但任务恢复新鲜后已存在的派单不会自动关闭；
102 环境现存 6 条滞留 OPEN 派单（含 2 条对应已恢复新鲜的任务），导致看板数据与实际不一致。
【需求描述】
- 任务从逾期恢复为新鲜时，其关联的滞留派单应自动转为关闭，无需人工介入
- 102 环境现存 6 条滞留 OPEN 派单应被清理为关闭状态
- 已恢复新鲜的任务（ar_aging_snapshot、metric_quality_scan）不应再产生新的派单
- 未部署真实执行器的台账任务（order/billing/customer projection、compensation_reconcile）
  维持现状：可产生派单，但不得伪造运行记录
- 不做：不改变派单生成时机、不改变逾期判定标准、不触碰其他补偿任务类型
【起始条件】
- 102 环境可用（http://192.168.0.102:28080），boss-server 容器运行中
- 现存 6 条 etl_freshness OPEN 派单、台账 6 个任务可见
【结束条件】
- 102 实机验证：恢复新鲜的任务其派单自动关闭；6 条历史滞留派单清零；
  连续两个扫描周期无新增误派单；台账运行记录与派单状态一致
- 门禁全绿、git 干净、合并 main 成功
【约束】
- 全程使用 worktree 开发，禁止直接改主分支
- 每完成一项独立变更立即测试并 commit（单一可回滚提交）
- 全部完成后合并到主分支，合并成功后再清理老分支，确保源码安全
- 效率优先：一次到位，不空转、不重复已做工作、不擅自扩大范围
- 全程无需征求用户同意，按上述流程自主执行到结束
```

## P2 — 工程卫生

### 提示词 4：后台周期任务启动时错峰执行

```
【任务】后台周期任务在服务启动后错峰展开，避免集中执行
【背景】执行器循环对从未运行过的任务（LastRunAt 为空）在服务启动后立即全部执行，
任务数量增多时会造成启动风暴（集中写库、集中算快照），影响启动期稳定性。
【需求描述】
- 服务启动后，多个到期任务的首轮执行应在时间上错开，避免同一瞬间集中开始
- 错峰不改变各任务既定的执行频次与判定标准（首次立即执行、之后按周期）
- 不做：不改变单个任务的执行逻辑、不改变任务台账字段、不改变既有调度语义
【起始条件】
- 102 环境可用，执行器循环已部署运行
【结束条件】
- 102 实机验证：重启服务后多任务首轮执行时间分散、无集中爆发；
  台账运行记录完整且与执行时间一致；门禁全绿、git 干净、合并 main 成功
【约束】
- 全程使用 worktree 开发，禁止直接改主分支
- 每完成一项独立变更立即测试并 commit（单一可回滚提交）
- 全部完成后合并到主分支，合并成功后再清理老分支，确保源码安全
- 效率优先：一次到位，不空转、不重复已做工作、不擅自扩大范围
- 全程无需征求用户同意，按上述流程自主执行到结束
```

## 使用说明

1. 按优先级逐条委托，一次一条，避免并行分支冲突（P0 先行，P1/P2 按序）。
2. 每条提示词独立走 worktree → 测试 → commit → 合并 main → 清理分支流程。
3. 委托前先 `git worktree list` 确认无并行会话占用；发现歧义先向用户确认，不自行推断。
