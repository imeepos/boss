# 设计稿 → 页面布局提示词：通用模板

> 用途：拿到一张视觉设计稿（PNG/Figma 导出/截图）后，按本模板填写，产出一份可直接交给编码 AI 生成页面布局的提示词。
> 配套范例：`docs/design/visual-design-prompts.md`（登录页完整产出物，可对照学习怎么填）。

---

## 0. 使用流程（三步）

1. **量取**：用 `read_image` 读设计稿，按第 2 节检查清单从宏观到微观提取信息，边看边记录数值。
2. **填模板**：把量取结果填进第 1 节模板的 `{{ }}` 占位符；量不准的值给区间并注明"允许 ±2px 校准"。
3. **迭代**：代码生成后用 `cdp-capture.mjs` 截图，与设计稿并排对比，把差异（具体 px/色值）写回模板重发。

原则：**量化一切**。禁止"大一点""偏上""蓝色按钮"这类模糊词，一律写具体 px、色值、字重。

---

## 1. 完整模板（复制即用）

```markdown
请根据设计稿实现页面，规格如下：

## A. 任务定位
- 页面名称：{{ 如：订单列表页 }}
- 页面类型：{{ 列表 / 表单 / 详情 / 仪表盘 / 登录 }}
- 所属端：{{ web/admin / web/h5 / android }}
- 设计稿：{{ 附图片路径，或注明"纯文字规格，无图" }}

## B. 技术栈与硬约束
- 技术栈：{{ 如 React + TypeScript + Tailwind / tokens.css 设计令牌 }}
- 颜色一律引用既有令牌：{{ 如 --color-brand-* / --shell-*，禁止硬编码色值 }}
- 复用组件：{{ 如 web/admin/src/components/Dropdown.tsx；禁止原生 <select> }}
- 单文件 ≤ 300 行，函数 ≤ 30 行；不使用 emoji 图标，图标用 SVG

## C. 画布基准
- 设计稿尺寸：{{ 1240 × 768 px }}
- 目标视口：{{ 桌面 1440 / 移动 375 }}
- 容器：{{ 如 width:100vw; min-height:100vh; 内容区 max-width }}}
- 量取公差：±2px / 轻微色差

## D. 整体骨架（布局树，必填）
用缩进树描述，每个节点标注尺寸/排列方式：

Page
├── {{ 区块1：如 Header（高 56px，flex，含面包屑+按钮组）}}
├── {{ 区块2：如 FilterBar（横向，间距 12px）}}
└── Content
    ├── {{ 子区块：如 StatsCards（grid 4 列，间距 16px）}}
    └── {{ 子区块：如 DataTable（行高 48px）}}

## E. 区域精确规格
| 区块 | 位置/尺寸 | 背景 | 圆角 | 阴影 | 内边距 |
|---|---|---|---|---|---|
| {{ 区块名 }} | {{ 如 左:204 上:109 宽:820 高:564 }} | {{ 色值/令牌 }} | {{ px }} | {{ css }} | {{ px }} |

## F. 色板（Token 优先）
| 用途 | Token | 色值 |
|---|---|---:|
| {{ 主色/背景/边框/文字/状态色… }} | {{ token 名 }} | {{ #hex }} |

## G. 字体层级
| 层级 | 字号/行高 | 字重 | 字间距 | 用途 |
|---|---|---:|---:|---|
| {{ H1/正文/辅助… }} | {{ 20px/28px }} | {{ 700 }} | {{ 0 }} | {{ 页面标题 }} |

字体族：{{ 系统无衬线栈 }}

## H. 间距与栅格
- 基础栅格：{{ 4px；刻度 4/8/12/16/24/32/48/64 }}
- 关键间距表：{{ 主标题与说明 6px；输入框之间 12px；区块之间 24px … }}

## I. 组件清单与规格（逐个列）
| 组件 | 尺寸 | 圆角 | 边框 | 背景 | 文字 |
|---|---|---|---|---|---|
| {{ 输入框/按钮/标签/表格… }} | {{ 274×34 }} | {{ 5px }} | {{ 1px solid #D7DDE7 }} | {{ #FFF }} | {{ 12px #4E5664 }} |

## J. 交互状态（设计稿没画的要补全）
- hover：{{ 如 边框 #B4BFCE，行背景高亮 }}
- focus：{{ 如 边框 #31568F + 外环 0 0 0 3px rgba(...,.14) }}
- disabled：{{ 如 背景 #F3F5F8，文字 #A6B1C3 }}
- error：{{ 如 边框 #D94B4B + 下方 11px 错误文案 }}
- 空态/加载：{{ 占位插画 / 骨架屏 / spinner }}
- 键盘可达：所有可交互元素有 :focus-visible

## K. 响应式断点
| 断点 | 策略 |
|---|---|
| {{ ≥1200px }} | {{ 完整双栏，面板保持 }} |
| {{ 768–959px }} | {{ 隐藏装饰，面板 calc(100vw-48px) }} |
| {{ <768px }} | {{ 单栏；触控高度 ≥44px }} |

## L. 数据契约绑定
- 字段/列名对齐：{{ docs/contract/fields.md，列出关键字段 }}
- 状态枚举对齐：{{ docs/contract/terms.md，列出枚举 }}
- 示例数据：{{ 给 2-3 条真实形状的 mock }}

## M. 资产清单
| 资产 | 格式 | 尺寸 | 用途 |
|---|---|---|---|
| {{ logo-x }} | SVG | {{ 62×62 }} | {{ 品牌区 }} |

规则：位图导出 2×；SVG 保留 viewBox；禁止从截图抠图；装饰层 pointer-events:none。

## N. 验收清单
1. {{ 可量化的验收点，如：主面板在 1240×768 下约 820×564 且居中 }}
2. {{ 左右比例 382:438 }}
3. {{ 输入框具备 Hover/Focus/Error/Disabled 四态 }}
...
```

## 2. 量取信息检查清单（从宏观到微观）

填写前逐项过一遍，防止遗漏：

1. **骨架**：什么布局？（侧导航+顶栏+内容 / 居中卡片 / 上下流式）
2. **分区**：内容区分几块？宽高比例？各块距画布边缘的 px？
3. **组件**：每块有哪些标准组件？数量？（几个输入框、几张卡片、几列表格）
4. **纵轴**：关键元素距容器顶部的 px（登录页模板 §3.4 的纵向表就是这么来的）
5. **字阶**：标题/正文/辅助的相对大小粗细；有无 letter-spacing
6. **色板**：主色、背景、面板、边框、文字、状态色；深浅两个主题各取一遍
7. **间距**：内边距、块间距、组件间距，归一到 4px 栅格
8. **圆角/阴影**：每类组件的圆角档位；阴影写完整 css
9. **状态**：设计稿通常只有理想态，hover/focus/disabled/空/载要自己补
10. **资产**：哪些是图片素材（背景/Logo/插画），哪些可用 CSS 实现

## 3. 本项目专用约束块（直接粘贴到 B 节）

```markdown
- 技术栈：web/admin —— React + TypeScript，样式用 tokens.css 令牌体系（--color-brand-* / --shell-*），支持 [data-theme] 双主题
- 下拉一律用 web/admin/src/components/Dropdown.tsx，禁止原生 <select>
- 列表列名、状态枚举先查 docs/contract/fields.md 与 docs/contract/terms.md，禁止自造字段名
- 单文件 ≤300 行（推荐 ≤200），函数 ≤30 行，图标用 SVG 不用 emoji
- 完成门禁：pnpm typecheck && pnpm test && pnpm build；双主题截图目测
```

---

## 4. 迭代技巧

- 差异反馈要写"应该是 X 而非 Y"：`卡片间距应为 16px 而非 24px；表头背景应用 var(--shell-card-bg)`。
- 一次只报一类问题（先结构、再间距、再配色），避免模型顾此失彼。
- 收敛后把最终规格回写到 `docs/design/` 作为该页面的定稿文档（范式见 `visual-design-prompts.md`）。
