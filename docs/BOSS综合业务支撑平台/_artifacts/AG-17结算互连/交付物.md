## 1. 业务对象清单

> 对照 4.2：本域实现 1 个既有对象 **Settlement Contract/Usage**（互连结算合同与话单：合同号、对端、费率、用量、差异；状态集 履行中/对账中/已结算/争议 冻结不变），并新增实现级支撑对象（结算对账、争议单、结算单、结算报表，见 1.3~1.6，建议补充 4.2，见 CHG-SET-004）。4.2 状态集按"合同 × 结算周期"实例化：一个合同在某一结算周期上处于对账中/已结算/争议，合同整体处于履行中/争议。

### 1.1 结算合同（Settlement Contract，对照 4.2 主对象）

**用途**：上游采购 / 对等互连两类结算合同的唯一主档（REQ-SET-001），承载费率、结算周期、SLA 条款与变更审批、生效期控制；是结算话单计价的费率来源与对账、支付、报表的对端维度基准。

| 属性 | 说明 |
|:-----|:-----|
| contractId | 合同号（全局唯一；全链路关联键：话单/对账/结算单/报表均按合同号聚合） |
| counterparty | 对端：上游供应商（UPSTREAM，采购成本方向）或对等运营商（PEER，网间互连方向） |
| contractType | 合同类型：上游采购 / 对等互连 |
| rateItems | 费率项（按合同约定的计量单位与单价，如按分钟/按流量/按带宽；币种、VAT 口径按合同与 BIR 规则） |
| settlePeriod | 结算周期（默认月；SLA 对账/争议/支付时限的基准） |
| slaClause | SLA 条款：对账时限、争议闭环时限、支付时限（合同约定值，作为对账/争议/支付超时升级的依据） |
| effectiveDate / expiryDate | 合同生效日 / 到期日（生效期控制基准） |
| versionNo / rateVersion | 合同版本号 / 费率版本号（费率变更留痕与计价绑定的版本标识） |
| changeApproval | 变更审批记录：变更内容、审批人、审批时间、变更生效日、是否追溯性调整（留痕，SET-001 例外） |
| status | 状态（见状态集） |

**状态集**（4.2 冻结）：履行中 / 对账中 / 已结算 / 争议。按"合同 × 结算周期"实例化：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| ACTIVE 履行中 | 合同在有效期内正常履行，当前周期结算流程未启动或正常推进 | 合同生效；进入对账期/争议/结算完成后回到履行中（进入下一周期） |
| RECONCILING 对账中 | 当前结算周期已生成结算话单、进入双方用量核对与差异处理 | 周期结束、话单生成后进入；差异清零双方确认后置已结算 |
| SETTLED 已结算 | 当前周期对账确认、结算单生成并经审批支付完成、账务已入账 | 对账确认+支付完成+账务一致校验通过 |
| DISPUTED 争议 | 当前周期存在未闭环争议单，该周期结算支付挂起 | 争议单创建；争议 30 天闭环后按结论回到对账中/已结算 |

**关系**：Settlement Contract 1:N 结算话单（1.2，按合同×周期）；1:N 结算对账（1.3，按周期）；1:N 结算单（1.5，按周期）；N:1 上游合同数据（外部/CRM 合同，只读引用，见 CHG-SET-006）。

### 1.2 结算话单（Settlement Usage/CDR，对照 4.2"用量"）

**用途**：网间流量/带宽用量采集记录与按合同×周期聚合生成的结算话单（REQ-SET-002），是计价的唯一用量依据与对账的己方口径。

| 属性 | 说明 |
|:-----|:-----|
| usageId / cdrId | 采集记录标识 / 结算话单标识（唯一；重采集/补采幂等键） |
| contractId / period | 归属合同号 / 结算周期 |
| usageType | 用量类型：网间流量（分钟/字节）/ 带宽（峰值/95 分位等，按合同计量口径） |
| sourceRef | 用量来源引用：AG-06 资源用量记录 / AG-03 计费用量快照（只读引用，不持有副本） |
| usageAmount | 用量值（己方计量） |
| completeness | 采集完整率（= 已采集 ÷ 应采集；SET-002 验收口径，占位符 [X]% 待回填，见 CHG-SET-001） |
| missingFlag | 缺失标记：待补（SET-002 例外：缺失数据标记待补，不臆造用量） |
| rateVersion | 计价绑定的费率版本号（SET-001 生效期控制；追溯性调整换版本） |
| amount | 结算金额（用量 × 费率，含 VAT 口径；由结算话单计价得出） |
| status | 采集记录状态：已采集 / 待补 / 已补采 / 已计价 |

**关系**：Settlement Usage N:1 Settlement Contract；1:N 结算话单明细（按对端交换的粒度分片）；经 sourceRef 引用 AG-06/AG-03 用量数据（只读）。

### 1.3 结算对账与差异清单（Settlement Reconciliation / Diff List）

**用途**：双方用量核对与差异清单（REQ-SET-003）：己方结算话单 vs 对端用量（对端交换/提供）逐周期核对，差异自动标记生成差异清单，是争议处理与 30 天闭环的载体。

| 属性 | 说明 |
|:-----|:-----|
| reconciliationId | 对账记录号（"合同号+周期"幂等，重跑不重复生成） |
| contractId / period | 归属合同号 / 结算周期 |
| ownUsage / peerUsage | 己方用量 / 对端用量（对端提供口径，见遗留事项 6.1） |
| diffAmount / diffRate | 差异量 / 差异率（= 差异量 ÷ 对端或己方用量，口径待确认，见 CHG-SET-002） |
| diffItems | 差异清单明细：差异项（方向、时段/链路/计量点、归因初判：口径差异/计量差异/缺失/其他） |
| autoFlag | 差异自动标记（差异率 ≥ 阈值自动置位，阈值配置化，见 CHG-SET-002；SET-TC1 以 2% 为场景） |
| disputeRef | 关联争议单（差异项升级为争议时引用） |
| confirmTime / confirmBy | 双方确认时间 / 确认人（对账确认留痕） |
| status | 待核对 / 差异处理中 / 已确认 / 已闭环 |

**关系**：Settlement Reconciliation 1:N 差异清单明细；1:0..1 争议单（1.4）；N:1 Settlement Contract。

### 1.4 争议单（Dispute）

**用途**：差异清单中双方无法即时达成一致的差异项进入争议处理流程（REQ-SET-003 争议处理流程；规则例外：差异 [30] 天闭环），记录争议内容、协商过程、结论与闭环留痕。

| 属性 | 说明 |
|:-----|:-----|
| disputeId | 争议单号（唯一；与差异项/对账记录关联） |
| reconciliationRef / diffItemRef | 来源对账记录 / 差异项 |
| disputeReason | 争议原因（对端不认可我方计量 / 我方不认可对端用量 / 口径分歧 / 数据缺失等） |
| negotiationLog | 协商过程留痕：双方意见、往来记录、处理人、时间 |
| dueTime / escalateFlag | 30 天闭环时限（自争议创建起 [30] 天）/ 超时升级标记 |
| conclusion | 结论：按我方调整 / 按对端调整 / 双方折中 / 维持原值（结论即差异处置结果） |
| closedTime / closedBy | 闭环时间 / 闭环确认人 |
| status | 争议中 / 协商中 / 已闭环 |

**关系**：Dispute 1:N Settlement Contract（合同状态置 DISPUTED 时至少一张未闭环争议单）；争议结论回写差异清单并驱动对账确认。

### 1.5 结算单与支付记录（Settlement Bill / Payment Record）

**用途**：对账确认后按合同×周期生成结算单（应付/应收），走审批与支付，记录支付执行状态（REQ-SET-004），实现"结算状态全程可跟踪"。

| 属性 | 说明 |
|:-----|:-----|
| billId | 结算单号（唯一；"合同号+周期+方向"幂等） |
| contractId / period | 归属合同号 / 结算周期 |
| billDirection | 方向：应付（上游采购成本）/ 应收（对等互连收入，按合同约定方向） |
| billAmount | 结算金额（对账确认后的最终金额，含 VAT 口径） |
| approvalRecord | 审批记录：审批流、审批人、审批意见、审批时间（分级审批，金额档位配置化） |
| paymentRef | 支付记录：支付单号（AG-04）、支付方式、计划支付日、实际支付日、支付状态 |
| accountRef | 账务引用：入账凭证/账务流水号（AG-03，报表与账务一致的依据） |
| status | 状态（见状态集） |

**状态集**（实现级，4.2 未定义，见 CHG-SET-004）：待审批 / 已审批 / 待支付 / 已支付 / 已入账 / 已关闭（作废）。

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| PENDING_APPROVAL 待审批 | 结算单生成，进入审批流 | 对账确认后生成；审批通过后置已审批 |
| APPROVED 已审批 | 审批通过，待资金划转 | 审批通过；发起支付后置待支付 |
| PENDING_PAYMENT 待支付 | 已向支付域/财务发起支付，资金未到账 | 发起支付；支付回执后置已支付 |
| PAID 已支付 | 资金划转完成（支付域回执） | 支付回执；账务入账后置已入账 |
| POSTED 已入账 | 账务已入账、报表口径一致 | 账务入账凭证回执，一致性校验通过 |
| VOID 已关闭 | 作废/红冲（追溯性调整场景） | 审批作废或冲销 |

**关系**：Settlement Bill N:1 Settlement Contract；经 paymentRef 引用 AG-04 支付单（只读）；经 accountRef 引用 AG-03 账务（只读）；结算报表（1.6）按单聚合。

### 1.6 结算报表（Settlement Report）

**用途**：REQ-SET-005 分对端结算与成本报表的元数据（生成、推送、下钻入口），内容由结算合同/话单/结算单统计得出，并与账务一致校验。

| 属性 | 说明 |
|:-----|:-----|
| reportId | 报表标识（"类型+期间"幂等） |
| reportType | 分对端结算报表 / 成本报表 / 结算汇总（月报为主，可日/周） |
| period | 报表期间（自然月） |
| indicators | 指标集：分对端应付/应收/已付/未付、上游采购成本、结算单状态分布、对账差异率、争议闭环率（口径见第 2 节） |
| accountConsistency | 账务一致性校验结果：报表合计 vs AG-03 账务（对账通过/差异清单） |
| drillPath | 下钻路径：报表 → 合同/对端 → 结算单 → 对账记录 → 差异清单 → 争议单 |
| pushTarget / status | 推送对象（财务、管理层）/ 状态（生成中/已推送/推送失败待重推） |

## 2. 规则实现说明（SET-001~004 含例外，及 REQ-SET-005 补充）

> 执行顺序按任务基线：**1 结算合同 → 2 结算话单 → 3 对账 → 4 支付 → 5 报表**。前三项为规则实现（SET-001/002/003），第四项 SET-004，第五项为需求补充实现（REQ-SET-005）。本域消费 AG-03/AG-06 用量与账务、上游合同数据（只读），产出结算单据；实际资金划转由支付域（AG-04）执行，本域跟踪状态。

### SET-001 结算合同（费率/周期/SLA，变更审批，生效期控制；例外：追溯性调整需审批留痕）

**实现逻辑**：
1. **合同主档**：上游采购 / 对等互连两类合同统一建档（contractId 唯一）：对端信息、合同类型、费率项（计量单位/单价/币种/VAT 口径）、结算周期（默认月）、SLA 条款（对账/争议/支付时限）、生效日与到期日。上游合同数据来自上游合同数据源（只读引用，来源待明确，见 CHG-SET-006）；对等互连合同由本域直接维护。
2. **变更审批**：费率/周期/SLA 任一要素变更必须走审批流（草稿 → 审批 → 生效），审批通过后生成新合同版本（versionNo、rateVersion 递增），**未经审批不得变更**（REQ-SET-001 验收"合同变更审批"）。
3. **生效期控制**：变更以"变更生效日"控制适用边界——**变更生效日之后的结算周期按新费率/新条款执行，之前周期按原版本执行**；结算话单计价必须绑定"用量发生周期"对应的费率版本快照（与 AG-03 计费规则版本化同源，防止费率变更后计价错配）。
4. **追溯性调整（规则例外原文）**：对**已结算/已入账周期**的费率调整属于追溯性调整，必须：①专项审批（高于常规变更的审批等级，留痕：调整内容、原因、审批人、时间）；②调整后重新计价生成调整结算单/冲销单（Settlement Bill 置 VOID 或红冲路径，受 AG-03 关账约束 BIL-005：已关账账期只允许冲账路径）；③全程留痕可举证（GOAL-8 合规可举证）。
5. **到期管理**：合同到期前提醒续约/终止（到期日控制）；到期未续约则停止生成新周期结算话单，存量周期按原版本处理。

**例外与边界处理**：
- **追溯性调整需审批留痕**（规则例外原文）：调整单独立审批流与留痕，禁止直接改历史结算金额。
- **变更生效期与用量归属冲突**：若变更生效日在周期中间，按合同约定分段计价（变更前段旧费率、后段新费率），与 AG-03 BIL-006 批发"合同月中变更分段计算"口径一致；分段规则以合同条款为准（见遗留事项）。
- **费率版本缺失**：计价时若历史费率版本不可得（无版本记录），该周期话单标记"待补费率版本"，不臆造费率（见遗留事项）。

### SET-002 结算话单（网间流量/带宽用量采集与结算话单生成，完整率 ≥ [X]%；例外：缺失数据标记待补）

**实现逻辑**：
1. **用量采集**：按合同×结算周期采集网间流量/带宽用量，数据源为资源用量（AG-06）与计费框架（AG-03）的网间用量数据（任务基线依赖；只读消费）。用量类型与计量口径（流量分钟/字节、带宽峰值/95 分位等）按合同费率项约定。
2. **采集完整率核查**：完整率 = 已采集用量 ÷ 应采集用量（按合同×周期×计量点统计）；完整率 ≥ [X]%（占位符未回填，建议 99%，参照批发域 WHO-002 完整率 ≥[99]% 与 REQ-CL-005 采集完整率 ≥[99]%，见 CHG-SET-001）；低于阈值不生成正式结算话单，先进入补采。
3. **缺失标记待补（规则例外原文）**：缺失的用量数据标记"待补"，**不臆造、不估算**缺失用量；补采成功后重新计算完整率并生成/更新结算话单（补采幂等：usageId 判重，重复补采不重复计价）。
4. **结算话单生成**：完整率达标的周期按合同×周期聚合生成结算话单（结算话单明细含用量、计价费率版本、金额）；计价绑定 SET-001 生效期控制下的费率版本快照。
5. **话单状态跟踪**：采集记录（已采集/待补/已补采/已计价）与结算话单状态全程可查，作为对账的己方口径（REQ-SET-002 验收）。

**例外与边界处理**：
- **缺失数据标记待补**（规则例外原文）：缺失项不入正式话单、不计价，进入待补清单；补采窗口（周期结束后 [X] 天内，占位符待定，见 CHG-SET-001）内未补齐的，该周期话单标记"不完整"并对账时按差异处理。
- **用量归属边界**：网间流量按计量点/时段归属周期（跨周期边界截点），与对端口径对齐（对账时口径差异归因分类，见 SET-003）。
- **采集数据源语义**：AG-06 资源用量与 AG-03 计费用量对本域"网间用量"的语义覆盖度需联调确认（AG-06 交付物未见网间带宽/流量采集明细，见遗留事项 6.1）。

### SET-003 结算对账（双方用量核对、差异清单、争议处理；例外：差异 [30] 天闭环）

**实现逻辑**：
1. **对账触发**：结算周期结束后按合同逐周期对账（对账记录按"合同号+周期"幂等，重跑不重复生成差异）；对账时限按合同 SLA 条款控制，超时升级。
2. **双方用量核对**：己方结算话单（SET-002 产出）vs 对端用量（对端提供/交换，获取方式见遗留事项）；按计量点/时段/链路逐项核对，输出己方用量、对端用量、差异量与差异率。
3. **差异自动标记**：差异率 ≥ 阈值（阈值配置化并冻结默认值，见 CHG-SET-002）自动标记置位并生成**差异清单**（差异项：方向、计量点、归因初判——口径差异/计量差异/缺失/其他）；非零差异均入清单（SET-TC1"对端用量差异 2%"场景即触发差异清单）。
4. **差异处理**：差异项逐项处理——口径差异（双方计量口径不同）按合同约定口径归一；计量差异（我方缺失/对端缺失）走补采/对端复核；双方无法即时达成一致的差异项**自动升级为争议单**进入争议流程。
5. **争议处理与 30 天闭环（规则例外原文）**：争议单自创建起 **[30] 天闭环**：协商 → 结论（按我方调整/按对端调整/折中/维持原值）→ 结论回写差异清单 → 对账确认；超 30 天自动升级（升级通知结算主管/财务，升级记录留痕）。争议未闭环期间，该合同该周期状态为 DISPUTED（争议），**结算支付挂起**（见 SET-004）。
6. **对账确认**：差异清零或争议闭环后双方确认（confirmTime/confirmBy 留痕），对账记录置已确认，驱动结算单生成（SET-004）。

**例外与边界处理**：
- **差异 [30] 天闭环**（规则例外原文）：30 天为争议闭环硬时限，超时升级；升级后仍无法闭环的转入人工仲裁/合同 SLA 条款处理（升级路径留痕，不无限期挂起）。
- **争议期间结算冻结**：争议未闭环的周期不生成/不支付结算单（防止错付）；争议结论为调整时按结论重新计价后结算。
- **差异率口径**：差异率 = 差异量 ÷ 对端用量（或己方用量，口径待需求方确认，见 CHG-SET-002），影响差异自动标记阈值判定。

### SET-004 结算支付（结算单生成、审批、支付记录；状态全程可跟踪）

**实现逻辑**：
1. **结算单生成**：对账确认后按合同×周期×方向生成结算单（应付：上游采购成本；应收：对等互连收入，方向按合同约定）；金额为对账确认后的最终金额（含 VAT 口径）；"合同号+周期+方向"幂等，重复生成不重复出单。
2. **审批**：结算单进入审批流（分级审批，金额档位配置化；上游应付与对等应收审批流可共用分级规则）；审批通过前不发起支付；审批驳回则退回修改/重生成，全程留痕（REQ-SET-004 验收"审批"）。
3. **支付执行与记录**：审批通过后向支付域（AG-04）/财务发起支付（上游应付：对外付款；对等应收：收款入账）；实际资金划转由 AG-04/财务执行，本域记录支付单号、计划支付日、实际支付日与支付状态，**状态全程可跟踪**（待审批 → 已审批 → 待支付 → 已支付 → 已入账，见 1.5 状态集）。
4. **账务联动**：支付完成后账务入账（AG-03 账务凭证引用），结算单置已入账，与结算报表口径一致（REQ-SET-005 与账务一致的基础）。
5. **状态跟踪视图**：按合同/对端/周期提供结算单状态跟踪（含未支付、超期未付清单与升级），支撑"结算状态全程可跟踪"验收。

**例外与边界处理**：
- **争议冻结**：合同该周期存在未闭环争议单时，结算单不生成或已生成不进入审批（SET-003 争议挂起联动）。
- **追溯性调整**：已支付结算单的追溯性调整（SET-001 例外）走冲销/红冲路径（Settlement Bill 置 VOID + 生成调整单），不直接修改已支付记录，留痕完整。
- **支付域边界**：资金划转执行与支付渠道（GCash/Maya/银行）归 AG-04，本域只跟踪结算支付状态与支付回执（见 CHG-SET-005 边界澄清）。

### 补充实现说明（REQ-SET-005 结算报表：分对端结算与成本报表，与账务一致）

**实现逻辑**：
1. **报表类型与期间**：分对端结算报表（按合同/对端汇总应付、应收、已付、未付、净额）与成本报表（上游采购成本分摊与汇总，与批发毛利口径衔接）；月报为主（次月生成，与结算节奏衔接：周期结束→对账→结算单→报表）。
2. **指标口径**：分对端应付/应收/已付/未付、上游成本、结算单状态分布、对账差异率、争议闭环率（含超时数）。
3. **与账务一致（REQ-SET-005 验收）**：报表合计与 AG-03 账务逐项核对（结算单入账凭证引用），一致通过后报表状态置已推送；不一致生成账务差异清单（与 AG-15 收入差异稽核联动，差异处理闭环）。
4. **可下钻**：报表 → 合同/对端 → 结算单 → 对账记录 → 差异清单 → 争议单 逐级下钻（1.6 drillPath），支撑举证（GOAL-8）。

| 策略 | 业务设计 |

## 3. 用例通过记录（验证设计，未运行）

> 说明：本域无真实运行环境，以下为**验证设计**（Given/When/Then + 预期证据），用于指导 T-2 用例自动化执行阶段；执行结果待回填，未虚构运行结论。

### SET-TC1 结算对账（对端用量差异 2% → 差异清单生成，[30] 天闭环）

**验证场景设计**：
- **Given**：某对等互连合同（contractId 唯一）当月结算周期结束；己方结算话单（己方计量口径）生成完成，采集完整率 100%；对端提供同期用量；**对端用量与己方用量差异率 2%**（差异量落在差异自动标记阈值之上）；差异自动标记阈值已配置。
- **When**：结算对账运行（己方结算话单 vs 对端用量逐计量点核对）。
- **Then**：
  - 差异自动标记置位，生成**差异清单**（差异项：方向、计量点、差异量与差异率 2%、归因初判）；
  - 差异项进入差异处理流程；双方无法即时达成一致的差异项自动生成**争议单**；
  - 争议单 **[30] 天内闭环**：协商结论（按我方/对端调整或折中）回写差异清单 → 对账确认 → 该周期结算单生成进入审批支付；
  - 争议未闭环期间该周期结算支付挂起；合同该周期状态按 履行中→对账中→争议→已结算 流转。
- **预期证据**：对账记录（合同+周期、己方/对端用量、差异量、差异率 2%、自动标记）；差异清单（差异项明细与归因初判）；争议单（争议原因、协商记录、30 天闭环时间戳、结论）；对账确认记录（confirmTime/confirmBy）；结算单（金额=争议结论后最终金额）；状态流转记录（对账中→争议→已结算）；30 天超时升级记录（若超时，含升级对象与留痕）。

**边界注记**：
- 用例"对端用量差异 2%"是**触发差异清单的场景**，未定义差异自动标记阈值（2% 为场景值还是阈值？）与差异率口径（差异量 ÷ 对端 vs 己方）→ 见 CHG-SET-002，阈值配置化并冻结默认值。
- 用例未说明"差异 2% 中哪些项升级争议、哪些项直接协商确认"→ 设计为：双方可即时达成一致（口径归一/补采/复核）的差异项直接处理，无法一致的升级争议单（30 天闭环）。
- "[30] 天闭环"的起算点（争议单创建日 vs 差异清单生成日）未定义 → 设计为**争议单创建日起算**（规则例外原文"差异 [30] 天闭环"按争议单口径实现），请需求方确认（CHG-SET-003）。
