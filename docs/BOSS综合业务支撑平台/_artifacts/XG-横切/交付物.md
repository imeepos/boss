## 2. 规则实现说明（条件→动作→结果）

### 2.1 XG-01 三语本地化（REQ-LAN-001~005 + GEN-007）

**规则原文**：界面三语切换即时生效（3 秒内无内容丢失）；单据三语模板同单据数据一致；报表三语指标口径一致；话术与通知模板三语客服直接可用；默认语言按品牌/区域配置，新文案三语同时维护，缺语言不发布。GEN-007：同一业务数据三语展示以单一数据源为准，翻译只影响展示。

| 条件 | 动作 | 结果 |
|:-----|:-----|:-----|
| 用户切换界面语言 / 门户按品牌区域默认语言进入 | 加载目标语言包渲染全部界面文案（术语查 TermDictionary，一词一义） | **3 秒内切换完成、无内容丢失、无单语残留**；数据区内容（余额/金额/日期/状态等业务数据）不变——GEN-007 单一数据源，翻译只影响文案层 |
| 生成单据（账单/发票/收据/合同/工单）且客户/品牌语言为某语种 | 以同一单据数据（数据源=计费/税务/CRM 主权域）渲染目标语言 DocumentTemplate | **同单据三语数据一致**：金额/税额/期限/单号等数据字段三种语言版本完全一致，仅文案与格式（₱、日期、地址按菲律宾习惯，2.6.1）不同 |
| 生成报表（BI/区域/稽核等） | 同一指标口径数据渲染三语表头与说明 | 三语指标口径一致（数据源相同，仅展示语言不同）；口径解释与数据可下钻 |
| 客服话术/通知模板维护（新文案） | 三语版本同步维护，术语查字典 | 客服直接可用；任一语言缺失 → 发布被拒（REQ-LAN-005 门禁），列出缺失语言清单 |
| 品牌/区域配置默认语言（英/菲，中文可选） | 默认语言随品牌/区域配置生效（PORT-005 联动） | 门户/单据/通知按品牌区域语言默认展示；用户可切换 |

**实现约束**：各域只声明"文案键 + 数据变量"，不自行维护翻译；翻译/术语/模板渲染统一由 XG-01 提供；缺语言发布门禁对界面文案、单据模板、通知模板、话术统一生效（GEN-007 验收：任一语言缺失该文案不得上线）。

## 3. 用例通过记录（验证设计）

> **重要声明**：无真实运行环境，以下均为**验证场景设计 + 预期证据判定准则**（如何验证），执行状态=待执行；实际通过/失败结果由 T-2（用例自动化执行）/T-3（契约联调）阶段按本设计执行后回填。不得将本设计视为已运行通过。验证所需模拟桩：支付渠道（GCash）、短信/App/Messenger/Viber/Email 渠道、客服域工单数据（按 8.10 协议）。

### 3.1 PORT-TC1~3（门户，支撑 REQ-PORT-001~008）

**PORT-TC1 在线充值（支撑 REQ-PORT-002）**：

- **Given**：客户已登录门户（手机号+密码），账户余额 ₱0，GCash 支付渠道模拟桩可用，通知渠道（App/站内信）可用；测试数据含该账户余额流水基线。
- **When**：门户发起充值 ₱500（GCash）→ 支付成功 → 触发到账处理（CT-005）。
- **Then**：
  1. 余额即时到账（到账时延 ≤5 分钟，对齐 CT-005）；
  2. 门户余额展示与计费域核心余额一致；
  3. 充值成功通知按渠道优先级推送（App 优先），送达记录存在；
  4. 另设场景：支付成功但回调延迟 → 门户显示"处理中"，超 30 分钟自动建工单（PORT-002 例外）。
- **预期证据**：余额流水 +₱500（含时间戳）；门户余额快照 vs 计费域余额一致；通知发送记录（渠道/回执）；"处理中"状态与自动建单记录。
- **判定准则**：到账时延达标；余额四方一致（流水/余额/账单/收款，联动 CONS-003）；通知送达；回调延迟例外按 PORT-002 处理。
- **状态**：验证设计（待执行；依赖支付域模拟桩与 XG-04 通知通道）。

**PORT-TC2 工单同步（支撑 REQ-PORT-003）**：

- **Given**：客户在网（资产/端口已绑定），客服域工单数据可访问；门户与客服端展示同一工单数据源。
- **When**：门户提交报障（自动关联客户/资产/端口）→ 客服端受理/处理/关闭。
- **Then**：
  1. 工单进度在门户与客服端**实时一致**（同一数据源，无二次录入）；
  2. 关闭后向客户推送满意度调查。
- **预期证据**：工单状态时间线（门户视图 vs 客服端视图逐环节一致）；关闭后调查推送记录。
- **判定准则**：任一状态变化在两端同时可见（无时延差/无不一致）；调查按关闭事件触发。
- **状态**：验证设计（待执行；依赖客服域数据与 XG-04 通知）。

**PORT-TC3 企业站点权限（支撑 REQ-PORT-008）**：

- **Given**：企业客户含站点 A/B 两站点，站点 A 管理员账号已配置（仅授权站点 A 数据范围）。
- **When**：站点 A 管理员登录企业门户查询账单/发票/用量/专线状态。
- **Then**：仅返回站点 A 数据；站点 B 数据不可见；尝试直接访问站点 B 明细被拒（留痕）。
- **预期证据**：查询结果集（仅站点 A）；越权拒绝记录（对齐 AG-01 越权被拒留痕）。
- **判定准则**：站点管理员仅见本站点（PORT-003 例外）；越权访问 0。
- **状态**：验证设计（待执行）。

### 3.2 NOT-TC1~3（通知，支撑 REQ-NOT-001~005）

**NOT-TC1 余额提醒（支撑 REQ-NOT-003/NOT-001）**：

- **Given**：账户余额低于阈值（₱50，附录 A 建议值，参数化）；客户触达渠道（手机号有效，App/Messenger/Viber/Email 通道模拟桩）可用；余额不足事件（4.5）已配置触发规则。

  1. 按渠道优先级 SMS>App>Messenger>Viber>Email 自动发送（余额提醒模板三语、变量完整）；

- **判定准则**：优先级顺序正确；失败自动切换；送达率 ≥98%；手机号无效场景 → "联系信息待更新"标记客服可见（NOT-001 例外）。
- **状态**：验证设计（待执行；依赖通知渠道就绪，未就绪降级见 R-03）。

**NOT-TC2 变量校验（支撑 REQ-NOT-002）**：

- **Given**：账单通知模板含金额变量；构造异常数据（账单金额缺失）。
- **When**：尝试发送账单通知。
- **Then**：**不发送并告警**（模板变量校验拦截）；告警记录存在（含原因=金额缺失）。
- **预期证据**：发送拦截记录；告警记录（关联模板与单据号）。
- **判定准则**：缺失变量消息零发送；告警可见可跟踪。
- **状态**：验证设计（待执行）。

**NOT-TC3 退订（支撑 REQ-NOT-004/NOT-003）**：

- **Given**：客户已退订营销类通知（退订操作留痕）；该客户被某营销活动目标分组命中。

### 3.3 CONS-TC1~3（一致性，支撑 REQ-CONS-001~008）

- **状态**：验证设计（待执行；T-2 阶段以测试数据执行）。

**CONS-TC2 四码冲突（支撑 REQ-CONS-002）**：

- **判定准则**：冲突 0 或 24h 内处理完（REQ-CONS-002）；闭环可追溯。
- **状态**：验证设计（待执行）。

**CONS-TC3 存量导入（支撑 REQ-CONS-006）**：

- **Given**：存量数据（客户/账户/余额/端口/四码关系）已导入完成（不影响在线业务）；核对任务已配置；纠错流程可用。

- **判定准则**：账实相符率 ≥98%（参数回填后精确断言）；差异逐条闭环；导入过程不影响在线业务。
- **状态**：验证设计（待执行；依赖试点区域存量数据）。
