## 1. 业务对象清单

### 1.1 Channel/Reseller（渠道/经销商档案，4.2）

**用途**：全国渠道网络主数据，覆盖直营/一级经销商/二级经销商/代理/线上五类渠道；承载区域与品牌授权、上级关系、佣金规则组、运营状态，是越区判定、佣金归属、门户数据权限的基准（REQ-CH-001/002）。

| 属性 | 说明 |
|:-----|:-----|
| channelId | 渠道号（本域唯一） |
| channelType | 渠道类型：DIRECT 直营 / RESELLER_L1 一级经销商 / RESELLER_L2 二级经销商 / AGENT 代理 / ONLINE 线上 |
| parentChannelId | 上级渠道（仅 RESELLER_L2 必填，指向发展其的一级经销商；其余类型为空） |
| regionNode | 所属区域（全国→18 大区→81 省→城市→Barangay 多层区域树节点，与 AG-14 区域主数据对齐） |
| brandAuth | 授权品牌（一个渠道可授权多个品牌） |
| commissionRuleGroup | 佣金规则组（新装/续费/企业线索/差额费率档，参数化，见 CH-002） |
| contactInfo | 联系人、证件、银行收款账户（佣金发放目标，发放执行归支付域） |
| status | 状态（见状态集） |

**状态集**（4.2 定义）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| ACTIVE 正常 | 可接单、可结算、可发放 | 建档通过/暂停整改完成恢复 |
| SUSPENDED 暂停 | 暂停接单与发放；暂停原因留痕（如合规违约、代收逾期未登记） | 合规/运营处置 |
| TERMINATED 终止 | 终止合作，不可再产生新佣金；存量未结佣金按终止清算口径处理 | 解约处置（历史可追溯） |

### 1.2 Channel Authorization（渠道授权）

**用途**：区域与品牌授权的明细登记（REQ-CH-001），越区销售判定的唯一依据。

| 属性 | 说明 |
|:-----|:-----|
| authId | 授权记录号 |
| channelId | 渠道 |
| authorizedRegion | 授权区域节点（可多个；含授权层级，见遗留事项） |
| authorizedBrand | 授权品牌 |
| effectiveDate / expireDate | 授权生效 / 失效日期 |
| status | 生效中 / 已过期 / 已撤销 |

### 1.3 Customer Attribution（客户归属）

**用途**：经销商"名下客户"的定义载体（REQ-CH-002/CH-005），门户数据隔离与业绩计量的基础。

| 属性 | 说明 |
|:-----|:-----|
| attributionId | 归属记录号 |
| customerId | 客户（消费 CRM 客户主数据，CT-001） |
| channelId | 归属经销商（= 新装订单渠道来源经销商，见变更建议 CHG-CH-002 口径确认） |
| sourceOrderId | 归属来源订单（渠道来源必填不可改，REQ-ORD-006） |
| attributionTime | 归属生效时间（新装订单竣工激活时点，口径见遗留事项） |
| status | 生效中 / 已解除（归属变更需留痕） |

### 1.4 Commission（佣金单，4.2）

**用途**：多级佣金结算的统一载体，覆盖明细生成、月度结算单、审批发放、争议、冲减全流程（REQ-CH-003）。

| 属性 | 说明 |
|:-----|:-----|
| commissionId | 佣金单号（本域唯一） |
| channelId | 经销商（收款方） |
| period | 结算账期（自然月） |
| totalAmount | 佣金总额（明细行合计；含负向冲减行） |
| disputeRef | 关联争议单号（状态=争议时） |
| paymentRef | 发放回执（关联支付域发放执行，幂等键） |
| status | 状态（见状态集） |

**状态集**（4.2 定义）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| PENDING 待结算 | 佣金明细已生成/汇总中，未出结算单 | 佣金计算完成 |
| SETTLED 已结算 | 结算单已生成（次月 10 日），待审批发放 | 结算单生成/审批通过 |
| PAID 已发放 | 发放执行完成（次月 15 日发放回执） | 发放回执确认 |
| DISPUTED 争议 | 争议受理中，冻结发放；争议处理完成后按结果重算/恢复 | 争议受理/处理完成 |

**佣金明细行（Commission Line）**：佣金单下挂明细，属性含订单号、客户、明细类型（NEW_INSTALL 新装 / RENEWAL 续费 / ENTERPRISE_LEAD 企业线索 / DIFFERENTIAL 差额 / REVERSAL 冲减）、金额、状态（正常 / 冻结待核查 / 已冲减）。越区冻结作用于明细行（CH-TC2）。

### 1.5 支撑对象（4.2 延伸，本域实现所需）

| 对象 | 说明 | 状态集 |
|:-----|:-----|:-----|
| 代收登记（Collection Registration） | 经销商代收客户缴费登记：经销商、客户/账单、金额、登记时间（CH-004） | 已登记 / 已入账（联动 CT-005）/ 逾期未登记 |
| 越区告警/核查单（Cross-region Alert） | 越区销售订单的告警与佣金冻结核查：订单、渠道、安装区域、授权区域、冻结明细 | 已告警 / 冻结待核查 / 已核查解除 / 已核查处理 |
| 佣金争议单（Commission Dispute） | 争议受理与处理：争议单号、佣金单、经销商、争议原因、处理结果（CH-003） | 处理中 / 已解决（维持 / 调整） |
| 业绩看板快照（Performance Snapshot） | 区域/渠道/品牌维度聚合结果（REQ-CH-004），与订单/收款数据核对一致后落快照 | 生成中 / 已核对 / 差异处理中 |
| 合规档案（Compliance Record） | 服务规范签署记录与违约记录（REQ-CH-005） | 待签署 / 已签署 / 有违约记录 |

## 2. 规则实现说明（CH-001~005 含例外；执行步骤：1 渠道体系 → 2 经销商门户 → 3 多级佣金 → 4 业绩看板 → 5 合规）

> 每条按"条件 → 动作 → 结果"描述实现逻辑，并单列例外与边界处理。

### 步骤 1 渠道体系：CH-001 渠道分级与区域/品牌授权（越区销售自动告警）

**实现逻辑（条件 → 动作 → 结果）**：

1. **渠道建档**：五类渠道（直营/一级经销商/二级经销商/代理/线上）统一建档于渠道主数据，登记所属区域节点与授权品牌（与 AG-14 品牌/区域主数据对齐），状态默认 ACTIVE。
2. **一级发展二级**：仅一级经销商（RESELLER_L1）可发起二级经销商建档，二级必填上级一级经销商（parentChannelId）；系统校验：二级的上级必须为一级、一个二级仅一个上级。**三级及以上不成立**：二级不可再发展下级（录入时被拒并提示）。
3. **区域与品牌授权**：每个渠道登记授权区域与授权品牌；授权变更走审批留痕，变更即时生效（生效后新订单按新授权判定）。
4. **越区销售自动告警**：订单创建/受理时（消费 REQ-ORD-006 渠道来源，来源必填不可改）→ 校验「订单安装地址所属区域节点 + 订购品牌」是否落在渠道授权范围 → 不匹配 → **自动告警**：订单标记"越区"、生成越区核查单、该订单佣金明细冻结待核查（联动 CH-003 例外），不阻塞订单主流程（先服务后核查，见边界注记）。
5. **渠道状态联动**：渠道 SUSPENDED 期间不接受新订单渠道来源选择、佣金发放挂起；TERMINATED 后不再产生新佣金，存量未结佣金按终止清算口径处理（口径见遗留事项）。

**例外（CH-001 例外列）**：新装佣金归报装经销商、续费归续费经销商 —— 此为佣金**归属**规则而非越区例外，且与 CH-002 佣金规则归属错位（见变更建议 CHG-CH-001，建议归并至 CH-002）。本交付按其业务语义实现于佣金归属（见 CH-002）。

**边界处理**：越区订单不拒绝受理（保障客户服务），以"佣金冻结 + 核查"方式处理（与 CH-TC2 一致）；越区判定依赖地址→区域树映射，地址不标准时的兜底见遗留事项与风险。

### 步骤 2 经销商门户：CH-005 数据隔离（经销商仅见名下，二级不可见一级全网）

**实现逻辑（条件 → 动作 → 结果）**：

1. **门户登录与认证**：经销商人员账号经统一认证（AG-05 提供身份认证，本域不重复实现）；账号绑定渠道号与角色（经销商负责人/店员），登录后门户数据范围 = 该渠道的数据权限范围。
2. **数据权限范围（CH-005 核心）**：
   - 所有经销商（一级/二级）仅可访问**名下客户**（Customer Attribution 归属本渠道的客户）与**本人佣金**（佣金单收款方 = 本渠道）；
   - 二级经销商：仅见自身名下客户与自身佣金，**一级全网数据不可见**（访问一级全网客户/佣金/业绩被拒）；
   - 跨渠道查询一律被拒并留审计（验证 CH-TC3）。
3. **名下客户管理**：名下客户列表、资料查看、服务状态、账单概览（数据消费 CRM/计费域只读视图）；客户归属变更（如渠道间转移）走审批留痕，避免越权改归属。
4. **代收功能**：名下客户缴费代收登记（见 CH-004）。
5. **业绩与佣金查看**：本人业绩汇总与佣金明细/结算单/发放状态查询；争议发起入口（见 CH-003）。

**边界处理**：一级经销商对其发展二级的数据可见范围基线未定义（差额佣金核对需要二级汇总数据）→ 见变更建议 CHG-CH-003 与遗留事项；当前实现为一级可见其下二级的**佣金汇总与差额明细**（用于差额核对），不可见二级名下客户明细（与 CH-005"仅见名下"最小化口径一致），待需求方冻结。

### 步骤 3 多级佣金：CH-002 佣金规则（多口径、多级差额）

**实现逻辑（条件 → 动作 → 结果）**：

1. **计取依据**：佣金计算消费订单渠道来源（REQ-ORD-006）与订单类型；**新装佣金归报装经销商**（订单渠道来源经销商）、**续费佣金归续费经销商**（续费发生渠道的渠道来源经销商）—— 归属随业务行为发生方，不随客户归属转移（CH-001 例外列的实质语义）。
2. **佣金标准（参数化费率组，默认档）**：
   - 新装：**₱300/户**（报装经销商）；
   - 续费：**₱50/户**（续费经销商）；
   - 企业线索：**合同额 5%**（线索归属经销商；线索归属登记口径见遗留事项）。
3. **多级差额（一级对二级）**：二级经销商名下新装订单，除二级得 ₱300/户外，其上级一级经销商得**差额 ₱100/户**（CH-TC1：B 新装 50 户 → B 得 50×₱300=₱15,000，A 得 50×₱100=₱5,000）。续费与企业线索的差额档基线未定义 → 见变更建议 CHG-CH-002（建议冻结：续费差额与一级对二级差额的适用范围）。
4. **退单冲减（CH-002 例外）**：订单退单致佣金多发 → **次月冲减**：生成负向冲减明细行（REVERSAL），冲减额在次月结算单中抵扣，冲减明细可追溯至原订单与原佣金行。
5. **越区冻结（CH-003 例外在本步骤的执行）**：越区订单佣金明细置"冻结待核查"（不进入发放），核查结论：确属越区按规则处理（如佣金不发放/按协商口径），误判则解除冻结补发。
6. **防重复计取**：以「订单 + 经销商 + 明细类型」为唯一键，同一订单同一类型仅计取一次（重算幂等）。

**边界处理**：新装计取时点（下单/竣工激活）基线未定义，直接影响退单冲减与结算归属期间 → 见变更建议 CHG-CH-005；金额精度按 GEN-006 两位小数四舍五入，与账单/收款同一规则。

### 步骤 3（续）：CH-003 月度结算流程（结算单/审批/发放/争议）

**实现逻辑（条件 → 动作 → 结果）**：

1. **佣金明细生成（账期内滚动）**：账期内新装/续费/企业线索/差额明细随业务事件实时生成，状态 PENDING（待结算）；越区冻结行单独挂起。
2. **次月 10 日生成结算单**：账期结束（次月）第 10 日，按经销商汇总当月佣金（含冲减行、剔除冻结行）生成月度结算单，佣金单状态 PENDING → SETTLED；冻结行不进入结算单，单列"冻结待核查"清单。
3. **审批**：结算单经渠道结算审批链审批（审批留痕）；审批不通过退回重算（差异留痕）。
4. **次月 15 日发放**：审批通过后发放执行（发放动作经支付域执行，回执为发放凭证；以同一结算单号为幂等键，**不重复发放**）；佣金单状态 SETTLED → PAID。
5. **争议（30 天处理）**：经销商对结算单/发放金额有异议 → 发起争议单（受理后佣金单置 DISPUTED，发放挂起）→ **争议 30 天内处理完成**：维持（恢复发放）或调整（重算差额后补发/追回，追回联动次月冲减）。
6. **退单冲减执行**：次月结算单自动含上月退单冲减行（负向），逐行关联原订单可追溯。

**边界处理**：发放失败（支付域回执失败）→ 佣金单保持 SETTLED 并告警重试，不置 PAID、不重复发起（幂等）；争议 30 天含受理日与处理日口径需冻结（见遗留事项）。

### 步骤 3（续）：CH-004 代收登记（24h 内登记，未登记从佣金抵扣）

**实现逻辑（条件 → 动作 → 结果）**：

1. **代收登记**：经销商代收名下客户缴费后，须在收款后 **24 小时内**在门户登记（客户/账单号、金额、收款方式），登记后进入收款流程（与支付域 CT-005 收款到账联动，见契约联调要点）。
2. **逾期未登记检测**：每日扫描经销商代收行为（与支付域收款数据核对）→ 发现收款后 24h 未登记 → 标记"逾期未登记"，金额挂账。
3. **从佣金抵扣**：逾期未登记金额在**当期结算**中从该经销商佣金中抵扣（抵扣额 = 未登记代收金额，可追溯至客户/账单）；后续补登记后按补登记时点处理（抵扣是否退还见遗留事项）。
4. **留痕**：登记、逾期判定、抵扣动作均留审计（登记人、时间、金额、关联账单）。

**边界处理**：经销商代收与支付域代收点（sari-sari/7-Eleven 等）是两个概念：本域管理"经销商人员代收登记"，到账入账执行归支付域（AG-04），两方数据一致性核对见契约联调要点；代收登记与到账的先后口径（登记即视为到账 vs 渠道确认后到账）待冻结 → 变更建议 CHG-CH-004。

### 步骤 4 业绩看板：REQ-CH-004（区域/渠道/品牌维度，与订单/收款数据一致）

**实现逻辑（条件 → 动作 → 结果）**：

1. **数据来源**：业绩指标（新装数/续费数/企业线索/佣金/代收额）消费订单数据（渠道来源，REQ-ORD-006）与收款数据（CT-005），本域不做业务事实的二次定义，只做聚合视图。
2. **维度**：区域（区域树层级）/ 渠道（五类渠道及经销商明细）/ 品牌（授权品牌）三维交叉；支持时间（日/月/账期）切片。
3. **一致性核对**：看板聚合结果与订单域订单数、支付域收款数定期核对（差异归零后落快照发布；差异非零 → 差异处理中，不发布存疑数据）。
4. **数据权限**：看板按查看人数据范围裁剪（经销商仅见名下，区域/品牌维度按 AG-01 角色矩阵授权，见横切与系统管理域）。

**边界处理**：看板口径（"新装"按订单口径还是激活口径）与佣金计取时点一致性问题 → 联动变更建议 CHG-CH-005 统一冻结。

### 步骤 5 渠道合规：REQ-CH-005（服务规范签署与违约记录）

**实现逻辑（条件 → 动作 → 结果）**：

1. **服务规范签署**：渠道（经销商/代理）建档时签署服务规范（版本化），签署记录入合规档案（签署人、版本、时间）；规范版本升级时重新签署（未签署完成前限制接单）。
2. **违约记录**：违约事件（越区销售、代收逾期未登记、服务违规、数据越权等）登记入合规档案，记录违约条款、事实、时间、处理结果，**全程可追溯**（不可删除，仅可追加处理结论）。
3. **联动处置**：违约按等级联动渠道状态（警告 / 暂停 SUSPENDED / 终止 TERMINATED）与佣金处置（如越区冻结、抵扣），处置留痕。

**边界处理**：违约等级与处罚矩阵基线未定义（何种违约对应暂停/终止）→ 见遗留事项；与横切合规域（REQ-COMP，XG 提供）的边界：本域承接渠道签约/违约业务记录，合规审计与上报能力消费 XG。

## 3. 用例通过记录（验证设计）

> 无真实运行环境，以下为**验证设计**：构造（Given）→ 动作（When）→ 断言（Then）+ 预期证据；待 T-2 用例自动化执行阶段实际执行后回填结果。

### CH-TC1 多级佣金（一级 A 发展二级 B，B 新装 50 户 → A 得 50×₱100 差额，B 得 50×₱300）

**验证场景设计**：

- **Given**：一级经销商 A（ACTIVE，授权区域 R）；二级经销商 B（ACTIVE，上级=A，授权区域 R）；B 名下新装订单 50 户全部竣工（渠道来源=B，安装区域在 R 内，非越区，无退单）。
- **When**：当月佣金计算执行 → 按 CH-002 计取：B 新装 50 户 × ₱300/户 = ₱15,000；A 对 B 名下新装差额 50 户 × ₱100/户 = ₱5,000 → 次月 10 日生成双方结算单。
- **Then**：B 佣金 = **50×₱300 = ₱15,000**；A 佣金 = **50×₱100 = ₱5,000**（差额）；两笔佣金明细唯一（无重复计取）；金额两位小数（GEN-006）。

**预期证据**：A、B 佣金明细行（明细类型、户数 50、单价 300/100、金额 15,000/5,000）；双方佣金单（账期、状态 PENDING→SETTLED）；重复计取防重校验记录。

**边界注记**：用例仅覆盖新装差额；续费（₱50/户）与企业线索（5%）的差额档未定义（见 CHG-CH-002）；新装计取时点（下单/激活）未冻结（见 CHG-CH-005），T-2 执行前需冻结口径。

### CH-TC2 越区冻结（越区订单标记 → 当月结算佣金冻结进核查）

**验证场景设计**：

- **Given**：经销商 X（ACTIVE，授权区域 R1）；订单 O 渠道来源=X，安装地址所属区域 R2（R2 ∉ X 授权范围）。
- **When**：订单 O 受理 → 越区校验触发 → 订单标记"越区"、生成越区核查单 → 当月结算计算执行。
- **Then**：订单 O 的佣金明细置"冻结待核查"；当月结算单**不含**该冻结金额；冻结明细进入核查清单（已告警 → 冻结待核查），不进入次月 15 日发放。

**预期证据**：越区告警记录（订单 O、渠道 X、安装区域 R2、授权区域 R1、告警时间）；佣金明细冻结状态变更记录；结算单生成清单（冻结行剔除）；核查单（冻结金额、状态=冻结待核查）。

**边界注记**：核查结论处置（确属越区/误判解除补发）的审批与时限基线未定义 → 见遗留事项；越区判定依赖地址→区域树映射精度（风险见 6.2）。

### CH-TC3 数据隔离（二级经销商登录门户 → 仅见名下，访问一级全网被拒）

**验证场景设计**：

- **Given**：二级经销商 B 门户账号登录成功（认证通过，AG-05）；B 名下客户 30 户；一级经销商 A 全网客户 1,000 户（含 B 名下 30 户）。
- **When**：B 在门户查询名下客户列表 → 再尝试查询/访问 A 的全网客户数据（如跨渠道检索、直接访问一级客户详情）。
- **Then**：名下客户查询仅返回 **30 户**（B 名下）；访问 A 全网数据**被拒**（无数据返回/权限拒绝），越权尝试留审计记录。

**预期证据**：名下客户列表结果集（30 户，均为 B 归属）；越权访问拒绝记录（目标客户、访问者 B、时间、拒绝原因）；审计日志（跨渠道访问尝试）。

**边界注记**：一级对二级数据的可见范围基线未定义（见 CHG-CH-003），当前按"一级可见二级佣金汇总与差额、不可见二级客户明细"实现，需冻结；客户归属变更（渠道间转移）的审批链待定义（见遗留事项）。

## 4. 契约联调要点（CT-001 / CT-004 / CT-005）

### CT-001 客户建档（CRM → 计费/订单/客服/门户/渠道）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **消费者/接收方**：消费客户主数据（品牌、区域）支撑名下客户视图与区域/品牌维度统计；客户主数据以 CRM 为准，本域不得修改 |
| 时延达成 | 客户建档后 [5] 分钟可见（全案基线）；名下客户列表与归属关系同步在时限内刷新 |
| 幂等要求 | 客户归属记录以「客户 + 来源订单」为唯一键；同一订单不重复生成归属 |
| 失败处理 | 客户数据同步延迟 → 名下客户视图待同步标记 + 告警；归属缺失的客户不进入任何经销商名下（防止错挂） |
| 联调验证点 | 新客户建档 → 名下客户可见时延（≤5min）；归属唯一性；客户归属与订单渠道来源一致性（REQ-ORD-006） |

### CT-004 订单-收费（订单 → 计费，支付域收款）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **消费者/间接关联方**：消费订单渠道来源（REQ-ORD-006，必填不可改）用于越区判定、佣金归属、业绩看板；订单数据以订单域为准，本域不修改订单 |
| 时延达成 | 佣金明细随订单关键事件（新装/续费/退单）实时生成（账期内滚动）；业绩看板聚合按日核对 |
| 幂等要求 | 佣金明细以「订单 + 经销商 + 明细类型」为唯一键；重复事件不重复计取；退单冲减行与原订单唯一关联 |
| 失败处理 | 订单事件缺失/延迟 → 对应佣金明细待补标记 + 告警，补单后重算（不重复发放）；越区标记冲突以订单域数据为准复核 |
| 联调验证点 | 渠道来源必填不可改（改单被拒）；越区标记与佣金冻结联动（CH-TC2）；新装/续费/退单事件 → 佣金明细生成/冲减正确性 |

### CT-005 收款-账务（支付 → 计费，消费方含税务/应收/渠道）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **消费者/接收方**：消费收款数据（到账 ≤5 分钟，已评审冻结）用于：①经销商代收登记的 24h 逾期核对（CH-004）；②业绩看板"收款"指标与订单/收款数据一致性核对（REQ-CH-004） |
| 时延达成 | 收款到账事件按 ≤5 分钟 SLA 到达；代收逾期判定按日扫描（24h 窗口） |
| 幂等要求 | 以支付单号为唯一键核对代收登记；同一支付单不重复计入业绩/不重复抵扣 |
| 失败处理 | 收款数据缺失 → 代收登记核对挂起并告警，不贸然判定逾期抵扣（防误扣）；收款与登记金额不一致 → 差异处理清单人工核对 |
| 联调验证点 | 经销商代收登记 → 支付域到账数据一致性（金额/客户/时间）；24h 未登记判定准确；业绩看板收款指标与支付域一致 |

### 佣金发放联动（业务层面，与支付域 AG-04 衔接）

| 要点 | 内容 |
|:-----|:-----|
| 发放执行 | 结算单审批通过后，发放指令经支付域执行（银行转账/电子钱包等）；以**结算单号为幂等键**，同一结算单不重复发放 |
| 回执闭环 | 发放回执到达 → 佣金单 SETTLED → PAID；回执失败 → 保持 SETTLED + 重试告警，不置 PAID |
| 联调验证点 | 结算单 → 发放指令 → 回执闭环；重复发起拦截；发放失败重试与告警；争议中佣金单发放挂起 |

### 关注点（非主契约）

| 契约 | 关注内容 |
|:-----|:-----|
| CT-012 欺诈预警-拦截（FMS → CRM/渠道/订单） | 佣金冻结/发放拦截与防欺诈域联动（如风控名单命中经销商 → 佣金发放挂起），误报经申诉关闭后恢复发放；联调时确认冻结/解除与 CH-003 状态流转衔接 |

| 风险 | 等级 | 说明与缓解 |
