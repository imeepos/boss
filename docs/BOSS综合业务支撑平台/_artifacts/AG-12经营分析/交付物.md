## 1. 业务对象清单

> 说明：4.2 对象模型未单列经营分析域对象行（见 CHG-BI-001），本节为**本域细化建模**（4.2 相关延伸），供需求评审补充 4.2 时引用。金额精度统一按 GEN-006。

### 1.1 核心指标（KPI，核心指标体系）

**用途**：REQ-BI-001 核心指标体系的载体。覆盖收入、ARPU、续费率、流失率、欠费率、端口利用率、DSO、区域 ROI 等经营指标；指标**口径可配置、可解释、可下钻**，且全系统唯一（BI-001）。

| 属性 | 说明 |
|:-----|:-----|
| kpiId | 指标标识（全系统唯一，指标口径字典注册号，BI-001） |
| kpiName | 指标名称（中英菲三语，GOAL-9/REQ-LAN-003） |
| kpiCategory | 指标分类：收入类 / 客户类 / 质量类 / 效率类 / 财务类 / 投资类 |
| formulaRef | 指标口径字典条目引用（定义、公式、统计时点、维度、异常处理，见 1.2） |
| dimensionScope | 允许统计维度（区域/渠道/品牌/套餐/客户群/时间；社区维度见 CHG-BI-008） |
| dataSourceRef | 数据来源域与对象引用（消费方口径，见第 4 章） |
| drillPath | 下钻路径（指标→维度层→明细单据/客户，BI-TC1 验收依据） |
| status | 状态：草稿 / 已发布 / 已停用（发布即口径冻结，变更走审批，见 2.1） |

**关系**：核心指标 1:N 口径字典条目（一指标一条口径定义）；N:1 看板/报告（同一指标被任意看板、报表、报告引用，计算结果一致——BI-TC1）。

### 1.2 指标口径字典（Metric Dictionary）

**用途**：**口径唯一性机制的核心载体**（BI-001"指标口径全系统唯一、可解释、可查阅"）。全系统所有指标定义、公式、统计时点、维度规则、异常处理在此登记，任何报表/看板/报告引用指标时一律引用字典条目，禁止各报表自带口径。

| 属性 | 说明 |
|:-----|:-----|
| metricId | 口径条目标识（= 指标注册号） |
| definition | 指标业务定义（三语，可解释性来源） |
| formula | 计算公式（业务口径级描述，如"收入 ÷ 平均在网用户数"，不含技术实现） |
| numerator / denominator | 分子 / 分母口径说明（含时点口径：期初/期末/日均等，配置化） |
| dimensionRules | 维度统计规则（跨层汇总=各层之和，REQ-REG-004；区域促销波动说明见 2.1 例外） |
| timePointRules | 统计时点与频率（实时/日/月；日报 T+1 08:00，BI-002） |
| exceptionRules | 异常处理口径（促销波动保留口径说明、数据缺失标记等） |
| version / changelog | 口径版本与变更记录（变更审批留痕，历史版本可查——口径唯一且可追溯） |
| approver | 口径发布/变更审批人（总部经营分析负责人，审批留痕） |

**关系**：口径字典 1:N 指标引用记录（可审计"哪些报表引用了哪个口径版本"）；口径变更发布后，引用旧版本的报表/报告按变更规则重新计算或保留口径说明（见 2.1 例外）。

### 1.3 实时经营看板（Dashboard）

**用途**：REQ-BI-002 实时经营看板载体。总部 / 区域 / 渠道 / 品牌多级视图，数据延迟 ≤5 分钟；日报 T+1 08:00 前可用。

| 属性 | 说明 |
|:-----|:-----|
| dashboardId | 看板标识 |
| level | 看板层级：总部 / 区域 / 渠道 / 品牌（区域经理数据权限=本区域，总部=全量，REG-001） |
| kpiSet | 看板指标集（引用口径字典，见 2.2 分级指标集） |
| refreshRule | 刷新规则：实时看板 ≤5 分钟；日报 T+1 08:00 前生成完毕 |
| dataScope | 数据范围（区域树全国→18 大区→81 省→城市→Barangay，按层继承，REQ-REG-004） |
| drillPath | 看板下钻路径（看板指标→多维分析→明细） |
| owner / viewers | 看板属主 / 可见角色（总部经营分析人员、区域运营经理等） |

**关系**：看板 N:1 指标体系（引用口径字典）；看板 N:1 多维分析模型（下钻承接）；看板指标可下钻至 Barangay 粒度（与投资一张图联动）。

### 1.4 多维分析模型（OLAP Model）

**用途**：REQ-BI-003 多维分析载体。维度：时间 × 区域 × 渠道 × 品牌 × 套餐 × 客户群；**汇总结果与明细一致**（一致性校验，BI-TC1 延伸断言）。

| 属性 | 说明 |
|:-----|:-----|
| modelId | 多维模型标识 |
| dimensions | 分析维度：时间（日/周/月/年）/ 区域（区域树层级）/ 渠道 / 品牌 / 套餐 / 客户群（+ 社区维度见 CHG-BI-008） |
| measures | 度量指标集（引用口径字典：收入/ARPU/用户数/续费率/流失率等） |
| granularity | 最细粒度（明细单据级：账单/客户/端口/订单，保证"结果与明细一致"） |
| consistencyCheck | 一致性校验规则（任意维度组合汇总 = 明细聚合，差异 0；跨层汇总=各层之和，REQ-REG-004） |
| exportRule | 导出规则（自定义报表超限限制导出并提示缩小范围，见 2.3 例外） |

**关系**：多维分析模型 1:N 看板（看板下钻承接）；1:N 自定义报表/导出记录（1.12）；维度主数据引用品牌区域域（AG-14）与渠道域（AG-10）配置。

### 1.5 CLV 模型与客户价值分群（CLV Model）

**用途**：REQ-BI-004 客户生命周期中 CLV 计算的载体。基于客户历史消费、续费行为、服务成本估算客户生命周期价值，输出客户价值分群，支撑挽留优先级与营销资源配置。

| 属性 | 说明 |
|:-----|:-----|
| clvModelId | 模型标识 |
| clvFormula | CLV 计算口径（建议：月度贡献毛利 × 预期在网月数折现，折现率与计算时点待冻结，见 CHG-BI-007） |
| inputRef | 输入数据引用（历史收入/续费/用量/客服成本/渠道成本，消费方口径） |
| segmentRule | 价值分群规则（高价值/中价值/低价值，阈值配置化） |
| version | 模型版本（参数调整留痕，可解释） |
| outputRef | 输出引用（挽留名单优先级、营销资源配置建议） |

**关系**：CLV 模型 N:1 流失预警（价值分群决定挽留优先级）；CLV 结果 N:1 挽留名单（高价值客户优先挽留）。

### 1.6 流失预警与挽留名单（Churn Alert & Retention List）

**用途**：REQ-BI-004 / BI-004 流失预警载体。按四类流失信号（停机 >7 天 / 用量骤降 >50% / 30 天投诉 ≥2 次 / 账单异议）自动识别流失风险客户，生成挽留名单；**预警命中率 ≥30%**。

| 属性 | 说明 |
|:-----|:-----|
| alertId | 预警标识 |
| customerId / accountId | 客户 / 账户（命中客户） |
| signalType | 流失信号类型：SUSPENDED_7D 停机超 7 天 / USAGE_DROP_50PCT 用量骤降超 50% / COMPLAINT_2_30D 30 天投诉 ≥2 次 / BILL_DISPUTE 账单异议 |
| signalEvidence | 信号证据（停机日期、用量对比区间、投诉记录、异议单号——可解释，可复核） |
| riskScore | 风险评分（信号加权，权重配置化，可解释） |
| riskLevel | 风险等级：高 / 中 / 低（决定挽留名单优先级与执行批次，见 2.4 例外） |
| alertTime | 预警生成时间 |
| status | 状态：已预警 / 已入名单 / 已生成挽留任务 / 已挽回 / 已流失 / 误报关闭（误报可申诉，参考 FMS-001 误报关闭机制） |

**关系**：流失预警 N:1 挽留名单（1.7）；命中率评估以"预警客户在评估窗口内实际流失"为分子口径（评估口径待冻结，CHG-BI-005）；预警信号消费事件：余额不足、服务已停机/复机、合同即将到期（4.5，消费方含 BI）。

### 1.7 挽留名单与挽留任务（Retention List & Task）

**用途**：流失预警的处置载体（REQ-BI-004"挽留名单"；BI-TC2"入流失名单生成挽留任务"）。按风险分批执行（例外：名单 >10,000 按风险分批，不一次性外呼）。

| 属性 | 说明 |
|:-----|:-----|
| listId | 挽留名单标识（批次） |
| batchRule | 分批规则：按风险等级分批（高→中→低），单批规模上限配置化（例外场景强制分批） |
| customerList | 名单客户明细（含风险评分、价值分群、命中信号） |
| retentionStrategy | 挽留策略（优惠券/话术/套餐调整建议——挽留动作执行方为客服/营销，本域只产出名单与策略建议） |
| executeChannel | 执行渠道（外呼/短信，渠道优先级与频控遵循通知域 NOT-001/NOT-003） |
| status | 状态：待执行 / 执行中 / 已完成 / 已关闭 |
| resultRef | 执行结果回填（是否挽回，用于命中率评估） |

**关系**：挽留名单 1:N 挽留任务（分派客服/渠道执行）；挽留任务 1:N 挽留动作记录（留痕）；任务执行结果回流命中率评估（2.4）。

### 1.8 投资一张图（Investment Map）

**用途**：REQ-BI-005"投资一张图"载体。热力图定位到 **Barangay / 小区** 粒度，展示投资分布与 ROI，支撑扩容投资决策（与 AG-06 建设管理 REQ-OSS-008、GIS 域 AG-11 地图能力协同）。

| 属性 | 说明 |
|:-----|:-----|
| mapId | 投资图标识 |
| geographicLevel | 地图粒度：大区→省→城市→Barangay→小区（区域树 REQ-REG-004 + GIS 地址层级 GIS-001） |
| investmentItem | 投资项目（扩容/专线/灾备建设，来源 REQ-OSS-008 建设管理项目） |
| investmentAmount | 投资金额（来源待冻结，见 CHG-BI-009；GEN-006 精度） |
| roiMetric | 区域 ROI 指标（区域收入贡献 / 区域投入，ROI 口径字典条目） |

| assetRef | 关联资产/端口（四码关系 CT-009 消费，15 分钟时延） |

**关系**：投资一张图 N:1 口径字典（ROI 口径引用）；消费 GIS 域地图与位置数据（AG-11）、资产/资源域数据（AG-06）；投资数据来源缺口见 CHG-BI-009。

### 1.9 维护一张表（Maintenance List）

**用途**：REQ-BI-005"维护一张表"载体。设备/端口维护优先级清单，**排序可解释**（按风险/利用率/故障频率等因子加权排序，因子与权重配置化、可查看）。

| 属性 | 说明 |
|:-----|:-----|
| listId | 维护清单标识 |
| itemRef | 维护对象（资产/端口/小区/Barangay） |
| scoreRule | 排序评分规则（因子：利用率、故障频次、告警级别、客户影响、维护成本；权重配置化，可解释） |
| score | 综合评分（排序依据） |
| rank | 排序位次 |
| maintenanceAction | 建议维护动作（巡检/更换/扩容，动作执行方为装维域） |
| generatedTime | 清单生成时间（按周期或事件刷新） |

**关系**：维护一张表消费监控域告警（AG-08）、资产/资源状态（AG-06）、GIS 位置（AG-11）；与投资一张图同一区域粒度，支撑"哪里该投、哪里该修"的联动决策。

**关系**：报告模板 1:N 报告实例；实例 N:1 口径字典（数据一致）；推送经通知域执行（XG-横切），三语模板与横切域协同（见 6.1 遗留）。

### 1.11 营收预测模型与预测结果（Forecast Model & Result）

**用途**：REQ-BI-007 / BI-006 营收预测载体。基于**历史趋势 / 季节 / 促销**建模，输出营收与用户增长预测，支撑预算编制；**模型可解释，回测误差 ≤[X]%**（阈值待冻结，CHG-BI-006）。

| 属性 | 说明 |
|:-----|:-----|
| modelId | 预测模型标识 |
| factorSet | 预测因子：历史趋势（收入/用户历史序列）、季节因子（菲律宾雨季/旱季、圣诞季等季节波动）、促销因子（促销活动计划，来源产品域促销配置） |
| forecastScope | 预测范围：时间粒度（月/季/年）与维度（全国/区域/品牌，粒度待冻结，CHG-BI-006） |
| output | 预测结果：营收预测值、用户增长预测值（含区间） |
| backtest | 回测记录（历史窗口回测误差、误差分布，可解释性证据） |
| explanation | 预测解释（各因子贡献说明——"预测结果可解释"验收依据） |
| version | 模型版本（参数/因子调整留痕，审批发布） |

**关系**：预测模型 N:1 口径字典（收入口径引用）；预测结果 N:1 报告（自动报告引用预测章节）；促销因子来源产品域促销配置（消费方）。

## 2. 规则实现说明（BI-001~006，含例外）

> 执行步骤映射：1 指标体系 → 2 看板 → 3 多维分析 → 4 CLV/流失预警 → 5 投资一张图/维护一张表 → 6 自动报告（三语）→ 7 营收预测。
> 编号说明：3.2.16 规则编号为 BI-001~006（BI-005=自动报告、BI-006=营收预测），与 REQ-BI-001~007 存在**编号错位**：REQ-BI-005（投资一张图/维护一张表）无对应规则编号 → 见 CHG-BI-002，本交付按规则原文编号实现，投资一张图按 REQ-BI-005 在 2.5 节单独实现。

### 2.1 BI-001 指标口径唯一（步骤 1 指标体系）

**实现逻辑**：
1. **指标注册**：全部核心指标（收入/ARPU/续费率/流失率/欠费率/端口利用率/DSO/区域 ROI 等）在**指标口径字典**（1.2）注册，每条口径含业务定义、计算公式（业务口径级）、分子分母时点、维度规则、统计时点、异常处理，**三语可查阅**（REQ-LAN-003"报表三语、指标口径一致"）。
2. **口径唯一机制**：任何看板、多维分析、自动报告引用指标时，一律引用字典条目（kpiId/metricId），**禁止报表自带口径**；同一指标在任意报表计算结果一致（BI-TC1）。
3. **口径变更审批**：口径发布即冻结；变更走审批（总部经营分析负责人），变更留痕、版本可查、历史口径可追溯；变更后引用方按新口径重算或保留旧口径说明。
4. **可下钻**：每个指标配置下钻路径（指标→维度层→明细单据/客户），保证"指标可下钻、口径唯一"（REQ-BI-001 验收）。
5. **跨层汇总一致性**：区域树跨层汇总=各层之和（REQ-REG-004），指标在任意层级计算一致。

**例外与边界处理**：
- **区域促销致 ARPU 波动**（BI-001 例外）：该区域/时段报表**保留口径说明**——在报表中标注"本期 ARPU 受区域促销影响，按口径字典异常处理规则计算"，说明促销影响范围与计算方式，不修改全局口径定义（口径唯一性不受破坏）。
- **金额精度**：涉及金额指标遵循 GEN-006（PHP 两位小数四舍五入），与计费/税务/应收域一致。
- **ROI/ARPU 具体公式**：基线仅要求"口径可配置可解释"，公式细项（如 ARPU 分母"平均在网用户数"的期初期末/日均口径、ROI 的投入口径）建议需求方冻结后回填口径字典（见 6.1 遗留）。

### 2.2 BI-002 实时经营看板（步骤 2 看板）

**实现逻辑**：
1. **多级看板**：总部 / 区域 / 渠道 / 品牌四级看板；总部=全量，区域经理=本区域（REG-001 数据权限），渠道/品牌视图按维度授权。
2. **实时刷新（≤5 分钟）**：看板指标消费各域事件与数据（4.5 事件、4.4 契约、4.3 主数据矩阵），增量数据到达后 **≤5 分钟**反映到看板（消费时延承诺见 CHG-BI-010）；看板指标引用口径字典，与明细一致。
3. **日报 T+1 08:00 前可用**：日报按日聚合生成，T+1 08:00（马尼拉时区）前完成生成并发布，报告推送按 BI-005/通知域渠道执行。
4. **下钻**：看板指标可下钻到多维分析（1.4）与明细（账单/客户/端口），下钻结果与看板汇总一致。

**例外与边界处理**：
- **自定义报表超限**（BI-002 例外原文）：自定义报表导出超限 → **限制导出并提示缩小范围**（缩小时间/维度范围后重新导出），拦截与提示留痕（1.12）。注：该例外语义属报表/多维分析（REQ-BI-003）而非实时看板，建议调整归属 → CHG-BI-004。
- **上游数据延迟**：看板 ≤5 分钟 SLA 依赖上游域数据时延（4.3 矩阵：客户 5 分钟、资产 15 分钟、端口实时、账务实时）；上游延迟时看板标注数据时点并告警（数据时点可见，不掩盖延迟）。

### 2.3 BI-003 多维分析（步骤 3 多维分析）

**实现逻辑**：
1. **六维分析**：时间 × 区域 × 渠道 × 品牌 × 套餐 × 客户群（REQ-BI-003 维度集）；支持任意维度组合查询；社区（Barangay）维度见 CHG-BI-008（与 GOAL-7"按端口/社区核算"及投资一张图粒度对齐）。
2. **结果与明细一致**：多维汇总结果 = 明细数据聚合（粒度到单据级：账单/客户/端口/订单）；每次查询执行一致性校验（汇总 vs 明细聚合差异 0，BI-TC1 延伸断言）。
3. **下钻路径**：任意汇总值可下钻至下一维度层直至明细，下钻过程值一致。
4. **口径引用**：所有度量指标引用口径字典，维度主数据引用品牌区域（AG-14）/渠道（AG-10）配置。

**例外与边界处理**：
- **流失名单 >10,000 分批**（BI-003 例外原文）：流失名单超过 10,000 时**按风险分批执行，不一次性外呼**（高→中→低分批，批次规模上限配置化）。注：该例外语义属流失预警（BI-004）执行环节，建议调整归属 → CHG-BI-003。
- **超限导出**：自定义报表超限限制导出（与 2.2 例外同一机制，归属调整见 CHG-BI-004）。

### 2.4 BI-004 客户生命周期：CLV / 流失预警 / 挽留名单（步骤 4）

**实现逻辑**：
1. **CLV 计算**：基于历史收入、续费行为、服务成本估算客户生命周期价值（口径建议与冻结项见 CHG-BI-007），输出客户价值分群（高/中/低），支撑挽留优先级。
2. **流失信号识别**（四类信号，任一命中即预警，信号证据可解释可复核）：
   - **停机 >7 天**：消费计费域"服务已停机/复机"事件与状态，停机持续超过 7 天未复机即命中；
   - **用量骤降 >50%**：对比当前周期与历史基准周期用量，降幅超过 50%（对比区间口径配置化）；
   - **30 天投诉 ≥2 次**：消费客服域工单/投诉记录，滚动 30 天投诉 ≥2 次；
   - **账单异议**：消费应收/客服域客户异议（AR-003 例外"客户异议"联动，异议登记即信号）。
3. **风险评分与名单生成**：信号加权生成风险评分（权重配置化、可解释），命中客户入**挽留名单**（1.7）；高价值客户优先（CLV 分群 × 风险等级联合排序）。
4. **挽留任务生成**：名单自动生成挽留任务并分派（客服/渠道执行挽留动作，本域产出名单与策略建议），任务执行结果回流（挽回/流失）用于命中率评估。
5. **命中率评估**：以"预警客户在评估窗口内实际流失"评估命中率，**≥30%**（评估口径：分子=预警且流失客户数，分母=预警客户数，回看窗口待冻结 → CHG-BI-005）。
6. **事件驱动**：消费 4.5 事件"余额不足"（BI 流失预警）、"服务已停机/复机"、"合同即将到期"（流失预警）触发信号检查。

**例外与边界处理**：
- **名单 >10,000 分批**：按风险分批执行，不一次性外呼（2.3 例外同源，归属调整见 CHG-BI-003）。
- **误报关闭**：预警误报可申诉关闭（参考 FMS-001 误报关闭机制），关闭留痕，不计入命中率分母口径（口径待冻结，CHG-BI-005）。
- **挽留动作边界**：本域只产出名单与策略建议，挽留动作（优惠券/话术/改套餐）由客服/营销/忠诚度域执行，挽留成本口径与财务确认（见 6.1 遗留）。

### 2.5 REQ-BI-005 投资一张图 / 维护一张表（步骤 5；规则编号缺失见 CHG-BI-002）

**实现逻辑**：
1. **投资一张图**：热力图按 **Barangay / 小区** 粒度展示投资分布（投资额、区域 ROI、利用率），粒度与区域树（REQ-REG-004）和 GIS 地址层级（GIS-001）对齐；热力分级阈值配置化、可解释。
2. **投资数据来源**：投资项目/金额来源 REQ-OSS-008 建设管理（AG-06）项目数据（数据主权缺口见 CHG-BI-009）；ROI 指标引用口径字典（1.1/1.2）。
3. **维护一张表**：按**可解释排序**生成维护优先级清单——排序因子（利用率、故障频次、告警级别、客户影响、维护成本）加权评分，权重与评分公式配置化、可查看（"清单排序可解释"验收）。
4. **联动决策**：投资一张图（该投哪里）与维护一张表（该修哪里）同粒度联动，支撑扩容/维护预算分配。

**例外与边界处理**：
- 资产/端口位置数据依赖 AG-06（15 分钟时延，CT-009）与 AG-11 GIS；无 GPS 弱电井/杆位手工标注坐标（GIS-003 例外）的热力图点位按近似位置展示并标注。

### 2.6 BI-005 自动报告（步骤 6 自动报告，三语）

**实现逻辑**：
1. **周期可配置**：报告周期（日/周/月/季/年/自定义）与生成时点在模板配置，周期到达自动生成（BI-TC3）；日报满足 T+1 08:00 前可用（BI-002）。
2. **三语生成与数据一致**：每份报告按**中/英/菲三语**模板渲染；三语共用同一数据快照与指标口径（引用口径字典），保证**三语数据一致**（REQ-LAN-003/GOAL-9）；缺语言不发布（REQ-LAN-005）。
3. **按渠道推送**：推送渠道与接收人按模板配置；渠道优先级、送达率、失败重发遵循通知域规则（NOT-001 渠道优先级、NOT-002 送达率 ≥98% 与失败可重发、NOT-003 频次控制）。
4. **报告实例留痕**：每次生成为一条实例（1.10），含生成时间、三语版本、数据快照时点；推送失败可重发。

**例外与边界处理**：
- 促销波动期间报告保留口径说明（与 2.1 例外同机制，防止三语报告间口径漂移）。
- 三语文案来源：报告模板三语文案与横切域（XG）协同维护（见 6.1 遗留）。

### 2.7 BI-006 营收预测（步骤 7 营收预测）

**实现逻辑**：
1. **预测因子**：基于**历史趋势**（收入/用户历史序列）、**季节**（菲律宾雨季/旱季、圣诞季等季节波动）、**促销**（促销活动计划，来源产品域促销配置）建模；因子独立可解释。
2. **预测输出**：营收预测与用户增长预测（全国/区域/品牌维度，粒度待冻结 → CHG-BI-006），支撑预算编制（REQ-BI-007）。
3. **模型可解释**：输出各因子贡献说明（历史/季节/促销各影响多少），预测结果可解释（BI-006"预测结果可解释"）。
4. **回测验证**：模型上线前与定期回测，**回测误差 ≤[X]%**（阈值待冻结 → CHG-BI-006）；回测记录（误差分布、回测窗口）留痕。
5. **版本管理**：模型参数/因子调整留痕、审批发布，版本可追溯（预测口径与指标口径字典同机制）。

**例外与边界处理**：
- 预测结果纳入自动报告（月报/年报预测章节），与实绩对比持续跟踪（预测偏差复盘）。
- 历史数据不足（新区域/新产品）时预测标注"数据积累期，置信度低"，不输出无依据预测（见 6.2 风险）。

## 3. 用例通过记录（验证设计，未运行）

> 说明：本域无真实运行环境，以下为**验证设计**（Given/When/Then + 预期证据），用于指导 T-2 用例自动化执行阶段；执行结果待回填，未虚构运行结论。

### 3.1 BI-TC1 口径一致（ARPU 指标任意报表引用 → 计算结果一致可下钻）

**验证场景设计**：
- **Given**：口径字典已发布 ARPU 指标（kpiId 注册，公式、分子分母时点、维度规则已冻结）；同月计费域账务数据已入账（含区域促销影响区域）。
- **When**：实时看板、多维分析（时间×区域×品牌）、月度自动报告（三语）三处同时引用 ARPU 指标计算，并对任意汇总值执行下钻至明细。
- **Then**：三处计算结果一致（同口径同数据）；下钻路径（看板→多维→账单/客户明细）逐层数值一致；促销影响区域报表保留口径说明。

**预期证据**：口径字典条目（定义、公式、时点、版本）；三处引用记录与计算结果（同一 kpiId、数值一致）；下钻过程快照（各层数值一致）；促销区域报表的口径说明标注；一致性校验记录（汇总=明细聚合，差异 0）。

**边界注记**：ARPU 分子分母时点口径（平均在网用户数算法）基线未冻结 → 6.1 遗留；促销口径说明的展示规则需需求方确认（见 2.1 例外实现）。

### 3.2 BI-TC2 流失预警（停机 10 天未续费 → 入流失名单生成挽留任务）

**验证场景设计**：
- **Given**：某预付客户停机（计费域"服务已停机"事件已消费），停机持续 10 天未续费，无异议、无政府豁免等特殊状态。
- **When**：每日流失信号检查执行 → 停机天数 10 > 7 命中"停机 >7 天"信号 → 风险评分计算 → 生成挽留名单条目。
- **Then**：客户入流失名单（含信号证据：停机日期、持续天数）；自动生成挽留任务并分派（客服/渠道）；名单规模 ≤10,000 时按风险等级正常执行；任务执行结果回填（挽回/流失）供命中率评估。

**预期证据**：信号检查记录（信号类型 SUSPENDED_7D、证据：停机日期/持续天数）；风险评分与等级；挽留名单条目（客户、信号、评分）；挽留任务创建与分派记录（分派人、时间、策略建议）；命中率评估记录（分子/分母口径）。

**边界注记**：命中率 ≥30% 的评估窗口（预警后多少天内流失算命中）未冻结 → CHG-BI-005；名单 >10,000 分批执行参数（批次规模上限）待冻结（2.4 例外）。

### 3.3 BI-TC3 自动报告（月度报告周期到达 → 自动生成推送，三语一致，≤X 分钟）

**验证场景设计**：
- **Given**：月度报告模板已配置（周期=月，三语=中/英/菲，推送渠道与接收人已配置，指标集引用口径字典）；当月数据已入账。
- **When**：月度周期到达 → 自动生成报告（三语版本共享同一数据快照）→ 按配置渠道推送。
- **Then**：报告按期生成（三语实例齐全）；三语数据一致（同数据快照、同指标口径）；推送按渠道优先级执行（送达/失败可重发）；**生成+推送 ≤[X] 分钟**（时限待冻结 → 6.1 遗留）。

**预期证据**：模板配置（周期、三语、渠道、接收人）；三语报告实例（生成时间、数据快照时点、三语同值校验记录）；推送记录（渠道、送达状态、失败重发记录）；生成+推送耗时（≤X 分钟目标）。

**边界注记**：X（生成+推送时限）基线未冻结 → 6.1 遗留；推送频次受通知域 NOT-003 频次控制约束（营销类同客户每周 ≤2 条），报告推送按业务类处理需确认（见 6.1 遗留）。

## 4. 数据依赖与口径（消费哪些域数据 / 口径唯一性机制）

> 本域**只读消费**全域数据（4.1：经营分析域"不产生业务数据，消费各域"），所有指标口径以**指标口径字典**（1.2）为唯一来源，业务数据口径以各主权域为准（4.3 主数据所有权矩阵）。

### 4.1 消费域数据清单

| 数据 | 来源域 | 主权口径（4.3/4.4/4.5） | 本域用途 |
|:-----|:-------|:------------------------|:---------|
| 收入/账务/账单/余额 | 计费（AG-03） | 账务数据以计费域为准，实时；出账 ≤6h（D 档）；CT-007"账单已生成"事件 | 收入/ARPU/欠费率/DSO 指标、营收预测、多维分析（账务口径） |
| 客户主数据/状态流/合同 | CRM（AG-02） | 客户主数据以 CRM 为准，5 分钟；CT-001；"合同即将到期"事件 | 客户群维度、续费率/流失率、CLV、挽留名单 |
| 套餐/价格/促销 | 产品（AG） | 产品与价格以产品域为准，实时 | 套餐维度、促销因子（营收预测）、ARPU 促销口径说明 |

### 4.2 主数据口径（4.3 矩阵对齐）

- **账务/收入**：以计费域为准（实时），收入类指标一律取计费域账务数据，金额 GEN-006 精度；
- **客户**：以 CRM 为准（5 分钟可见），客户群维度与流失状态以 CRM 客户状态流（CRM-002）对齐；
- **资产/端口**：资产 15 分钟、端口实时，端口利用率以资源域端口状态为准（与 AG-06 REQ-OSS-007 利用率预警口径联动）；
- **收款**：以支付渠道凭证为准，收入确认与支付域对账口径一致；
- **工单/投诉**：以客服域为准，流失信号投诉计数以客服域工单记录为唯一来源。

### 4.3 口径唯一性机制（BI-001 落地）

1. **口径字典唯一来源**：全系统指标只在口径字典（1.2）定义一次；看板/多维/报告全部引用字典条目（kpiId/metricId），从机制上杜绝"同指标多口径"；
2. **发布即冻结 + 变更审批**：口径发布后冻结，变更走总部审批、版本留痕、历史可查；
3. **可解释可查阅**：口径定义三语可查阅（REQ-LAN-003），任何报表可反查所引用口径版本；
4. **一致性校验**：多维汇总=明细聚合（差异 0）、跨层汇总=各层之和（REQ-REG-004）、三语报告同快照同口径（BI-TC3）；
5. **审计闭环**：口径变更记录、报表引用记录、导出记录（1.12）均留痕，支撑口径审计（AG-12 验收基线含"口径审计"）；
6. **合规口径**：外资持股 ≤40% 相关报表口径合规（4.7 合规落点：品牌区域/BI），按监管报送口径出具。
