## 1. 业务对象清单

### 1.1 Points Account（积分账户）

**用途**：承载客户积分资产的唯一账户，一切积分赚取/扣减/过期/调整均记账于本账户，是积分余额、对账、兑换、等级评估的共同依据。

| 属性 | 说明 |
|:-----|:-----|
| pointsAccountId | 积分账户标识（全局唯一） |
| customerId | 归属客户标识（N:1，依赖 AG-02 客户模型；一客户一积分账户） |
| subscriptionId | 关联主订购关系（可选；积分归属客户而非单条订购，多订购共用一账户） |
| availablePoints | 可用积分（可兑换/可展示的余额） |
| frozenPoints | 冻结积分（兑换单处理中暂扣，不计入可用余额） |
| totalEarnedPoints | 累计赚取积分（等级评估维度一，**不随兑换扣减**，见 CHG-LOY-002） |
| totalConsumptionAmount | 累计消费金额（等级评估维度二，来源 AG-03 消费/账单数据） |
| expirePolicyId | 有效期策略标识（按赚取批次管理，见 1.4） |
| status | 账户状态（见状态集，4.2） |
| version | 版本号（并发控制：同一账户积分变动串行化的依据） |

**状态集**（4.2：有效/冻结/注销）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| ACTIVE 有效 | 可正常赚取、兑换、参与营销 | 初始状态；解冻后恢复 |
| FROZEN 冻结 | 风控/争议/合规冻结：冻结期间不赚取、不兑换、不参与营销发放 | 风控或管理指令触发；解除后恢复 |
| CANCELLED 注销 | 客户销户时积分清零并归档 | 销户流程触发，清零前发通知（同 AG-03 销户口径） |

**关系**：Points Account N:1 Customer（AG-02）；1:N 积分流水（不可变）；1:N 兑换单；1:N 有效期批次；等级评估基于 totalEarnedPoints + totalConsumptionAmount，与账户可用余额解耦。

### 1.2 积分流水（Points Transaction）

**用途**：一切积分变动的不可变记录，是账户余额、每日对账、规则解释（REQ-LOY-001"规则可解释"）的共同依据。流水不可修改、不可删除，仅可通过冲正流水反向调整。

| 属性 | 说明 |
|:-----|:-----|
| transactionId | 流水标识（全局唯一） |
| pointsAccountId | 积分账户标识 |
| changeType | 变动类型：EARN 赚取 / REDEEM 兑换扣减 / EXPIRE 过期清零 / ADJUST 人工调整 / REVERSE 冲正 |
| changeAmount | 变动数量（正为赚取，负为扣减） |
| balanceBefore / balanceAfter | 变动前余额 / 变动后余额（余额 = 期初 + Σ入 - Σ出） |
| ruleId / ruleVersion | 触发规则标识与版本（规则可解释、可回溯） |
| businessRefNo | 关联业务单号（账单号 / 兑换单号 / 推荐关系单号 / 调整单号） |
| expiryBatch | 关联有效期批次（FEFO 扣减依据） |
| eventTime | 记账时间 |

### 1.3 积分规则（Points Rule）

**用途**：定义积分赚取/扣减的配置化规则（消费/续费/推荐/营销加成），支持规则变更审批与影响预览（LOY-001）。

| 属性 | 说明 |
|:-----|:-----|
| ruleId | 规则标识 |
| ruleType | 规则类型：CONSUMPTION 消费 / RENEWAL 续费 / REFERRAL 推荐 / CAMPAIGN 营销加成 |
| scope | 生效范围：产品/套餐、渠道、客户群、时间窗（可组合配置） |
| calculation | 计算要素：基数（消费/续费金额）、系数（每 1 比索 = X 积分）、封顶（单笔/单日/单月上限）、公式说明 |
| priority | 多规则命中优先级（互斥/叠加策略，见 CHG-LOY-001） |
| status | 规则状态：草稿 / 待审批 / 已生效 / 已失效 |
| effectiveDate / expireDate | 生效日期 / 失效日期（新规则只影响生效后发生的业务） |
| approvalInfo | 审批人、审批时间、影响预览快照（变更审批留痕） |

### 1.4 积分有效期批次（Points Expiry Batch）

**用途**：积分按赚取批次管理有效期，支撑先到期先扣（FEFO）与到期清零（LOY-002）。

| 属性 | 说明 |
|:-----|:-----|
| batchId | 批次标识 |
| pointsAccountId | 积分账户标识 |
| earnedPoints / remainPoints | 批次赚取积分 / 批次剩余积分 |
| expireDate | 有效期至 |
| status | 未到期 / 已过期 / 已清零 |

### 1.5 兑换单（Redemption Order）

**用途**：客户积分兑换的凭证，覆盖抵扣账单/礼品/流量包三类兑换（LOY-003），驱动积分扣减与下游履约，是账实一致核对的锚点。

| 属性 | 说明 |
|:-----|:-----|
| redemptionId | 兑换单标识 |
| customerId / pointsAccountId | 客户 / 积分账户 |
| redemptionType | 兑换类型：BILL_OFFSET 抵扣账单 / GIFT 礼品 / DATA_PACK 流量包 |
| pointsAmount | 兑换积分数量 |
| cashValue | 抵扣金额 / 礼品价值 / 流量包面值（兑换比率见 CHG-LOY-004） |
| billId | 抵扣账单标识（依赖 AG-03；抵扣账单场景） |
| productId | 流量包产品标识（兑换流量包场景） |
| status | 待处理 / 积分已冻结 / 积分已扣减 / 履约中 / 已完成 / 已失败（已冲正） |
| requestTime | 提交时间 |

**状态机**：待处理 → 积分已冻结 → 积分已扣减 → 履约中 → 已完成；任一下游履约失败 → 已失败 → 积分全额冲正返还（冲正流水），账实一致。

### 1.6 等级（Loyalty Tier）

**用途**：客户忠诚度等级（普通/银/金/铂金，具体档位由业务配置），承载升降级规则与权益目录（LOY-004）。

| 属性 | 说明 |
|:-----|:-----|
| tierCode / tierName | 等级代码 / 名称 |
| upgradeRule | 升级规则：按累计赚取积分与累计消费金额双维度阈值（任一达标或双达标，口径见 CHG-LOY-002） |
| downgradeRule | 降级规则：保级周期（建议 12 个月滚动窗口）、观察期（见 CHG-LOY-005） |
| benefits | 权益清单（关联 1.7） |
| effectiveDate / expireDate | 等级定义有效期 |
| status | 状态（4.2：有效/冻结/注销；与账户状态联动） |

### 1.7 等级权益（Tier Benefit）

**用途**：等级对应的权益目录（专属流量包、折扣、服务优先级、双倍积分加成、专属客服等），随等级生效/失效。

| 属性 | 说明 |
|:-----|:-----|
| benefitId | 权益标识 |
| tierCode | 所属等级 |
| benefitType / benefitValue | 权益类型（专属流量/折扣/服务优先级/积分加成/专属客服）/ 权益数值（流量额度、折扣率、加成倍数） |
| effectiveDate / expireDate / status | 权益有效期 / 状态 |

### 1.8 等级变更记录（Tier Change Record）

**用途**：等级升降级/保级的审计与通知依据（LOY-004"等级变更通知客户"）。

| 属性 | 说明 |
|:-----|:-----|

| customerId | 客户标识 |
| fromTier / toTier | 原等级 / 新等级 |
| changeType | 升级 / 降级 / 保级 |
| triggerReason | 触发原因：达标评估 / 人工调整 |

| notifyStatus | 通知状态：已通知 / 未通知（含通知渠道与时间） |

### 1.9 营销活动（Points Campaign）

| 属性 | 说明 |

## 2. 规则实现说明（LOY-001~004，含 REQ-LOY-005 积分营销）

### LOY-001 积分规则（消费/续费/推荐可配置；规则变更审批、影响预览）

**实现逻辑**：
1. **规则配置**：按规则类型（消费/续费/推荐）与生效范围（产品/套餐、渠道、客户群、时间窗）配置；支持营销加成规则叠加（见 REQ-LOY-005）。
2. **消费积分**：依赖 AG-03 消费/账单确认事件触发，积分 = 消费金额 × 消费系数（按产品/套餐差异化）；支持单笔/单日/单月封顶与最低消费门槛（配置化）。
3. **续费积分**：预付续费/后付缴费成功（依赖 AG-03 账务确认）时按续费金额 × 系数赠送；与消费积分是否叠加按配置（见例外）。
4. **推荐积分**：推荐人推荐新客户，新客户完成激活/首充（依赖 AG-02 客户状态）后发放推荐奖励；推荐关系成立判定、奖励数值配置化；防刷校验（同设备/同支付方式/批量注册等，联动 AG-16 防欺诈，见 CHG-LOY-006）。
5. **规则可解释**：每笔积分变动记录 ruleId + ruleVersion + 基数 + 系数 + 公式 + 计算过程说明（写入积分流水），客户/客服可逐笔回溯解释（REQ-LOY-001）。
6. **规则变更**：变更必须走审批（草稿 → 待审批 → 已生效）；提交变更时自动生成**影响预览**（受影响客户范围、新旧规则版本对比、预计积分变化量、生效时点），审批通过后按生效日期切换；已生效规则只影响生效后发生的业务，历史流水不追溯重算（审批留痕于规则对象 approvalInfo）。

**例外与边界处理**：
- **多规则同时命中**（如续费同时命中续费规则 + 营销双倍积分）：优先级与互斥/叠加策略基线未定义 → CHG-LOY-001（建议：基础规则与营销加成**叠加**，多基础规则按优先级**互斥**，配置化）。
- **消费退款/销账**：原消费积分按退款金额冲正（负向流水，REVERSE），冲正不重复发放；退款时积分已被兑换的部分不追回（建议口径，需业务确认）。
- **推荐关系边界**：被推荐人后续销户是否回收推荐积分，基线未定义 → 遗留事项。
- **规则生效时点**：以业务发生（消费/续费/推荐成立）时点的生效规则为准，跨生效时点的进行中业务不追溯重算。

### LOY-002 积分账户、流水、有效期、每日核对（差异 0、当日处理）

**实现逻辑**：
1. **账户体系**：一客户一积分账户（依赖 AG-02 客户模型）；状态集有效/冻结/注销（4.2）；冻结期间不赚取、不兑换、不参与营销发放；注销时积分清零并归档（清零前发通知）。
2. **流水记账**：一切变动（赚取/兑换/过期/调整/冲正）记流水，含变动前/后余额；**账户余额 = 期初 + Σ入 - Σ出**，流水不可变，仅可冲正。
3. **有效期**：按赚取批次设置有效期（1.4）；到期积分自动清零并记流水（EXPIRE）；**扣减顺序 = 先到期先扣（FEFO）**，兑换时优先扣减最先到期批次；有效期策略（统一期限 vs 差异化）见 CHG-LOY-003。
4. **每日核对**：日终批量核对（账户余额 = Σ流水；到期批次 = 清零批次），差异当日生成差异清单并**当日处理**（自动冲正或经审批的人工调整），验收基线差异 0（REQ-LOY-002）。
5. **并发控制**：同一账户积分变动串行化（version 乐观锁 + 流水号唯一），杜绝重复发放/重复扣减。

**例外与边界处理**：
- **冻结期间到期积分**：建议照常过期清零（与账户冻结解耦），需业务确认。
- **注销时未到期积分**：清零或转移（如集团账户归集）基线未定义 → 遗留事项。
- **有效期到期前提醒**：建议 30/7/1 天提醒（与通知渠道联动），基线未定义 → CHG-LOY-003。

### LOY-003 积分兑换（抵扣账单/礼品/流量包；兑换后扣减正确、账实一致）

**实现逻辑**：
1. **兑换类型**：抵扣账单（依赖 AG-03 账单，按兑换积分折算金额核减账单应缴额）；礼品（实物/虚拟礼品兑换，走礼品库存与发放流程）；流量包（兑换为数据流量包，开通至客户订购关系）。
2. **前置校验**：账户状态有效、可用积分充足（含有效期批次校验）、兑换规则满足（最低兑换量、兑换比例、每期兑换上限、限兑商品，配置化）。
3. **处理流程**：提交兑换单（待处理）→ **冻结积分**（frozenPoints，防并发重复兑换）→ 校验通过后**扣减积分**（按 FEFO 扣减批次，扣减后余额 = 扣减前 - 兑换积分）→ 兑换单置"积分已扣减" → 触发下游履约（账单抵扣/礼品发放/流量包开通）→ 履约完成置"已完成"；**任一下游失败 → 兑换单置"已失败"，积分全额冲正返还**（冲正流水），账实一致。
4. **账实一致保障**：积分扣减与兑换单一一对应（兑换单号为幂等键），扣减必伴随流水；每日对账（LOY-002）覆盖兑换扣减，差异当日处理；兑换后账户余额 = 扣减前余额 - 兑换积分（LOY-TC1 验证口径）。
5. **抵扣账单**：兑换成功后生成账单抵扣凭证，AG-03 账单应缴额相应核减；同一账单不可重复抵扣（幂等拦截）。

**例外与边界处理**：
- **并发重复兑换**：冻结机制防重复兑换；冻结积分不计入可用余额；超时未完成自动解冻。
- **流量包开通失败**（开通链路异常）：冲正返还积分，客户无损失；已开通成功但回执丢失：以开通域最终状态为准，不重复发放（见第 4 节契约要点）。
- **礼品库存不足**：兑换单挂起或取消，积分返还。
- **兑换后账单退款/销账**：已抵扣部分不重复退积分（建议口径，需业务确认）。
- **兑换比例**（1 积分 = 多少比索、礼品兑换分值）基线未定义 → CHG-LOY-004。

### LOY-004 等级权益（按积分/消费自动升降；权益生效；等级变更通知客户）

**实现逻辑**：
1. **评估维度**：按**累计赚取积分（totalEarnedPoints）**与**累计消费金额（totalConsumptionAmount，来源 AG-03）**双维度达标自动评估（任一达标或双达标，口径见 CHG-LOY-002）；评估不依赖账户可用积分余额，**兑换扣减不影响等级**。
2. **评估触发**：积分赚取/消费事件发生后实时评估 + 日终批量兜底评估（建议双机制，保障 LOY-TC2"积分达标即升级"时效）。
3. **升级**：达标即升级，生成等级变更记录，**权益即时生效**（或按配置延迟生效，建议即时）。
4. **降级**：按保级周期（建议 12 个月滚动窗口）评估，未达保级门槛触发降级；建议设**观察期**（降级前提醒，观察期内达标可豁免）→ 基线未定义，CHG-LOY-005。
5. **权益生效**：等级权益目录（专属流量/折扣/服务优先级/双倍积分加成等）配置化，等级变更时权益联动生效/失效。
6. **变更通知**：等级变更（升级/降级/保级）触发通知（短信/App 推送，经通知渠道），内容含新等级、生效时点、权益说明；通知状态记录于等级变更记录（notifyStatus）。

**例外与边界处理**：
- **"按积分消费自动升降"表述歧义**：若按账户可用积分余额评估，兑换会导致降级，与兑换/营销业务冲突 → CHG-LOY-002（评估基于累计赚取积分 + 累计消费金额，不随兑换扣减）。
- **降级时当月已享权益**（如已领取专属流量包）：建议不追回、下期按新等级执行 → 遗留确认。
- **等级与账户状态联动**：账户冻结时等级保留（冻结解除后继续评估）；账户注销时等级清除。

### 补充实现说明（REQ-LOY-005 积分营销：限时双倍积分、效果可追踪）

**实现逻辑**：
1. **活动配置**：营销活动（限时双倍积分/定向加赠等）按客户群/产品/渠道/时间窗配置；活动加成与基础规则叠加计算（叠加策略见 CHG-LOY-001）。
2. **发放**：活动期间符合范围的赚取事件按加成倍数发放积分；活动发放积分同样记流水并关联活动标识（campaignId），同样纳入有效期批次管理。
3. **效果追踪**：按活动统计参与客户数、发放积分、兑换转化（兑换单关联活动标识）、活动前后消费对比，支撑活动 ROI 评估（REQ-LOY-005"活动效果可追踪"）。
4. **活动预算**：活动积分预算配置化，预算耗尽后是否继续按基础规则发放（仅停加成）需业务确认 → 遗留事项。

**例外与边界处理**：
- 活动与账户冻结重叠：冻结期间不参与活动发放（与 LOY-002 冻结口径一致）。
- 活动结束边界：以事件发生（消费/续费）时点判定是否在活动窗口内，跨窗口业务不追溯补发。

## 3. 用例通过记录（验证设计，未运行）

> 说明：本域无真实运行环境，以下为**验证设计**（Given/When/Then + 预期证据），用于指导 T-2 用例自动化执行阶段；执行结果待回填，未虚构运行结论。

### LOY-TC1 客户积分 1000 兑换 300 → 余额 700（流水完整、账实一致）

**验证场景设计**：
- **Given**：客户积分账户状态 ACTIVE，可用积分 1000（有效期批次均未到期），兑换规则满足（最低兑换量、兑换比例已配置），存在可抵扣账单（AG-03，应缴额 > 兑换抵扣额）。
- **When**：客户提交抵扣账单兑换 300 积分 → 冻结 300 → 校验通过 → 扣减 300（按 FEFO 扣减批次）→ 兑换单置"积分已扣减" → 账单抵扣生效 → 兑换单置"已完成"。
- **Then**：账户可用积分余额 = 1000 - 300 = **700**；兑换扣减流水完整（changeType=REDEEM，balanceBefore=1000，balanceAfter=700，关联兑换单号）；账户余额 = Σ流水（账实一致）；兑换单状态 = 已完成；账单应缴额按抵扣额核减（AG-03）。

**预期证据**：兑换单记录（300 积分、类型=抵扣账单、状态流转 待处理→已冻结→已扣减→履约中→已完成）；扣减流水（-300，前后余额 1000/700）；账单抵扣凭证（AG-03 回执）；日终对账记录差异 0。

**边界注记**：用例仅覆盖正常路径；并发重复兑换、下游履约失败冲正等负向路径由 LOY-003 例外覆盖，建议 T-2 补充负向用例（重复提交、开通失败冲正）。

### LOY-TC2 客户积分达标 → 自动升级并生效权益（等级变更通知客户）

**验证场景设计**：
- **Given**：客户当前等级=普通（银卡升级阈值：累计赚取积分 ≥ 10000 或累计消费金额 ≥ ₱50000，双维度口径见 CHG-LOY-002）；当前累计赚取积分 8000、累计消费金额未达标。
- **When**：客户发生一笔消费赚取积分 2000（累计赚取积分 = 10000）→ 触发实时等级评估 → 双维度达标判定通过 → 升级为银卡 → 生成等级变更记录 → 银卡权益生效 → 发送等级变更通知。
- **Then**：客户等级 = 银卡；银卡权益生效（如专属流量包/折扣，按权益目录）；等级变更记录完整（fromTier=普通、toTier=银卡、triggerReason=达标评估）；通知已发送（notifyStatus=已通知，含新等级与权益说明）。

**预期证据**：等级评估记录（评估时间、双维度数值、判定结果=升级）；等级变更记录（含通知状态）；权益生效清单（生效时间）；通知发送记录（渠道、时间、内容）。

**边界注记**：升级后发生兑换扣减不影响等级（评估基于累计赚取积分，CHG-LOY-002 口径）；降级/保级场景基线未定义（CHG-LOY-005），建议 T-2 补充降级与观察期用例。

## 4. 契约联调要点（积分变动事件）

> 积分变动事件（Points Change Event）：由本域在**每笔积分变动记账成功后**发布，供计费抵扣（AG-03）/通知/营销消费。本节描述事件业务语义与联调要点，不涉及技术选型与接口路径。

| 要点 | 内容 |
|:-----|:-----|
| 事件内容 | 事件类型（EARN 赚取 / REDEEM 兑换扣减 / EXPIRE 过期 / ADJUST 调整 / REVERSE 冲正）、客户标识、积分账户标识、变动数量（正/负）、变动后余额、业务单号（账单号 / 兑换单号 / 推荐关系单号）、规则标识与版本（规则可解释）、活动标识（营销发放时）、事件时间、幂等键（业务单号 + 变动类型） |
| 本域角色 | **发起方/生产者**：积分记账完成后发布事件；事件失败/丢失**不影响积分账务**（账务为最终事实），通过日终对账与事件补发机制恢复 |
| 时序要求 | 先记账（流水 + 余额）后发布事件；事件发布与下游消费异步，不阻塞积分业务主流程 |
| 幂等要求 | 消费方以**业务单号为幂等键**：重复事件不重复动作（不重复抵扣账单、不重复发通知、不重复累计营销效果）；同一兑换单只允许一条扣减流水（REQ-LOY-002 对账差异 0） |
| 与 AG-03 计费抵扣 | 兑换抵扣账单**以兑换单为准**核销：账单抵扣金额 = 兑换单抵扣额；兑换冲正时联动账单恢复；同一账单不可重复抵扣（幂等拦截）；联调验证点：抵扣后账单金额核减、冲正后恢复、重复事件不重复抵扣 |
| 与通知 | 等级变更通知（升级/降级/保级）、积分变动提醒（可配置是否通知）消费对应事件；联调验证点：通知触发时点、内容（新等级/权益说明）、通知失败重试 |
| 与营销（REQ-LOY-005） | 活动效果追踪消费赚取事件并关联活动标识（参与客户、发放积分、兑换转化）；联调验证点：活动期间加成发放、活动结束边界、效果统计口径 |
| 与客户域（AG-02） | 积分账户开户/销户与客户生命周期联动（销户清零前通知）；推荐积分依赖被推荐人激活状态 |
| 失败处理 | 下游消费失败由各消费方重试（幂等保障）；事件补发以日终对账差异清单驱动；跨域一致性以本域积分账务为准 |
