## 1. 业务对象清单

### 1.1 Fraud Case（欺诈案件，4.2）

**用途**：欺诈案件全流程（创建/调查/处置/归档）的统一载体，承载与客户/订单/佣金的关联关系与案件闭环留痕（REQ-FMS-005）。

| 属性 | 说明 |
|:-----|:-----|
| caseId | 案件号（本域唯一） |
| caseType | 案件类型：DUPLICATE_ACCOUNT 重复开户 / COMMISSION_FRAUD 佣金欺诈 / ABNORMAL_USAGE 异常用量 / LIST_HIT 名单命中 |
| sourceAlertRef | 来源预警号（预警确认后自动转案件时引用） |
| customerIds | 关联客户集合（命中账号的客户，消费 CRM 客户主数据） |
| orderIds | 关联订单集合（涉及开户/销户/新装订单） |
| commissionRefs | 关联佣金单/明细（佣金欺诈案件，消费渠道域佣金数据） |
| riskLevel | 风险等级：高/中/低（按命中账号数、涉及金额、在网时长等评估，规则参数化） |
| conclusion | 处置结论（确认欺诈的处置动作、误报的解除动作，联动留痕） |
| status | 状态（见状态集） |

**状态集**（4.2 定义）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| INVESTIGATING 调查中 | 案件创建后进入调查，调查记录逐条留痕 | 预警确认转案件 / 人工创建 |
| CONFIRMED 已确认 | 调查确认欺诈属实，执行处置动作（佣金冲减/追回、销户建议、加入黑名单等） | 调查结论=欺诈 |
| FALSE_POSITIVE 误报 | 调查确认属误报，关闭案件并解除关联联动动作（解除佣金冻结/拦截），可加入白名单 | 调查结论=误报 |
| CLOSED 已处置 | 处置完成归档，案件闭环，全程可追溯 | 处置动作完成 / 误报关闭 |

### 1.2 Blacklist/Whitelist（风控名单，4.2）

**用途**：黑/灰名单命中拦截或人工审核、白名单豁免的统一载体（REQ-FMS-004）。4.2 对象名为 Blacklist/Whitelist，需求明确黑/灰两类名单；本实现扩展为三类：黑名单（直接拦截）、灰名单（人工审核）、白名单（豁免，承接 FMS-001~003 误报申诉关闭后的豁免，防重复命中）。

| 属性 | 说明 |
|:-----|:-----|
| entryId | 名单项号（本域唯一） |
| listType | BLACKLIST 黑名单 / GRAYLIST 灰名单 / WHITELIST 白名单 |
| valueType | 名单值类型：证件号/手机号/IP/设备指纹/客户号/经销商号（可配置扩展） |
| value | 名单值（归一化后存储，如证件归一化） |
| hitAction | 命中动作：INTERCEPT 拦截 / MANUAL_REVIEW 人工审核 / EXEMPT 豁免放行 |
| effectiveDate / expireDate | 生效日 / 过期日（过期自动失效） |
| source | 来源：案件处置 / 人工添加 / 预警确认（留痕） |
| status | 状态（见状态集） |

**状态集**（4.2 定义）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| ACTIVE 有效 | 命中生效，按 hitAction 执行 | 名单项添加审批通过，生效期内 |
| EXPIRED 过期 | 超过过期日自动失效，不再命中 | 到期自动 |
| RELEASED 已解除 | 审批解除（误伤申诉/案件结论），不再命中，历史命中记录保留可追溯 | 解除审批通过 |

### 1.3 支撑对象（4.2 延伸，本域实现所需）

| 对象 | 说明 | 状态集 |
|:-----|:-----|:-----|
| Fraud Alert（欺诈预警） | 检测规则命中的输出（CT-012 关键数据）：预警号、命中规则（FMS-001~003）、命中维度/值、关联账号/订单/佣金/经销商集合、风险等级 | 已产生 / 已确认 / 误报申诉中 / 已关闭 / 已转案件 |
| Detection Rule Config（检测规则配置） | 检测规则参数化配置：规则编号、检测维度（证件/手机号/IP/设备指纹/模式）、阈值与检测窗口、启用状态；变更审批留痕（REQ-FMS-001 规则可配置） | 启用 / 停用 |
| False Positive Appeal（误报申诉单） | 误报申诉受理：申诉人（客户/经销商）、申诉对象（预警/案件/拦截记录）、理由、处理结果（关闭/维持）；时限见 CHG-FMS-006 | 申诉中 / 已关闭 / 已维持 |
| Interception Directive（拦截指令/名单命中判定记录） | 名单命中判定与拦截指令下发留痕：名单项、命中对象（开户/下单/装维动作）、判定（拦截/人工审核/放行）、推送目标域、时间；本域留痕，执行留痕在消费域（分工见 CHG-FMS-002） | 已判定 / 已推送 / 已执行 / 已解除 |
| Case Investigation Record（案件调查记录） | 案件调查过程留痕：调查动作、发现、证据引用、处理结论；追加不可删除 | — |
| Fraud Stats Report（欺诈统计报表） | 预警/案件/名单命中/命中率/误报率/处置时长统计（REQ-FMS-005 统计报表） | 生成中 / 已发布 |

## 2. 规则实现说明（FMS-001~005 含例外；执行步骤：1 重复开户检测 → 2 佣金欺诈 → 3 异常用量 → 4 风控名单 → 5 案件管理）

> 每条按"条件 → 动作 → 结果"描述实现逻辑，并单列例外与边界处理。

### 步骤 1 重复开户检测：FMS-001（REQ-FMS-001）

**实现逻辑（条件 → 动作 → 结果）**：

1. **检测维度配置**：检测维度（证件号/手机号/IP/设备指纹）可独立启用/停用（REQ-FMS-001 规则可配置），配置变更走审批留痕；每个维度配置命中阈值与检测窗口（如窗口内同证件 ≥3 账号，通用参数见遗留事项）。
2. **数据来源**：消费客户主数据（AG-02，CT-001：客户/账户的证件、手机号）与开户受理数据（开户 IP、设备指纹——采集口径见 CHG-FMS-004）；本域只读消费，不修改客户数据。
3. **检测执行**：按配置周期执行——对启用维度做多账号归并统计（证件/手机号归一化后精确匹配；IP/设备指纹按窗口匹配）→ 同一维度值关联账号数 ≥ 阈值 → **命中**。
4. **命中动作**：生成欺诈预警，**关联该维度值下全部命中账号**（FMS-TC1：同证件 3 账号 → 预警关联 A/B/C 全部账号）；预警含命中规则、维度、命中值、账号集合、风险等级 → 进入人工确认，或按配置自动转案件（见步骤 5）。
5. **白名单豁免**：正当多账号场景（家庭多人同证件/同地址、企业多账户、共享 IP）经确认后加入白名单（1.2），后续同维度命中豁免。

**例外（FMS-001 例外列）**：规则可配置、误报可申诉关闭——命中预警经人工确认属误报（如证件号录入重复、家庭共享）→ 发起误报申诉 → 申诉通过后预警关闭、关联联动动作解除，可加入白名单防重复命中；申诉时限与流程见 CHG-FMS-006。

**边界处理**：证件录入差异（大小写/符号/缺位）归一化后匹配；IP 动态分配/NAT 下多用户共享出口 IP → 依赖窗口与阈值调优 + 白名单，避免大面积误报；设备指纹缺失（老终端）→ 该维度命中受限，以证件/手机号维度为主（CHG-FMS-004）。

### 步骤 2 佣金欺诈：FMS-002（REQ-FMS-002）

**实现逻辑（条件 → 动作 → 结果）**：

1. **数据来源**：消费订单事件（AG-02/订单域：开户、销户、新装）与佣金/渠道数据（AG-10：佣金明细、经销商档案、区域授权）。
2. **检测模式（四类，可配置启用）**：
   - 集中开户：单经销商检测窗口内（如 1 天）新装开户数 ≥ 阈值；
   - 立即销户：开户后短期（如 ≤7 天）内销户户数 ≥ 阈值或销户率 ≥ 阈值；
   - 高频新装：经销商新装频次/数量显著高于其历史基线（历史均值 + 倍数阈值）；
   - 同区域批量：同一区域、短窗口内批量开户（订单区域/安装地址聚合）。
3. **检测执行**：按日/窗口批量执行，各模式独立判定、可组合命中 → 命中任一模式 → 生成佣金欺诈预警，关联经销商、命中订单集合、销户明细。
4. **命中动作**：预警进入案件流程（FMS-TC2：经销商 1 天集中开户 200 户且 10 户立即销户 → 命中 → 进入案件）；同时联动佣金处置：涉及订单佣金明细置"冻结待核查"（与 AG-10 CH-003 越区冻结同类机制衔接，见契约联调要点），待案件结论决定冲减/追回或解除。
5. **指标**：命中率 ≥ 80%、误报率 ≤ 5%（DEV-TPL 参数表建议值，全案 2.3.24/3.2.23 为 [X]%/[X]% 占位符，口径与回填见 CHG-FMS-001）；指标按"预警-人工确认"闭环统计，用于规则阈值调优。

**例外（FMS-002 例外列）**：命中率/误报率指标——阈值参数需在运营中按指标调优（误报率超标 → 提高阈值；命中率不足 → 放宽窗口/阈值），指标统计口径冻结见 CHG-FMS-001。

**边界处理**：正常促销活动（新店开业集中开户）可能误报 → 活动备案豁免（备案期间该经销商阈值放宽，留痕）；立即销户与正常退订区分（按退订率基线）；同区域批量与正常社区营销区分。

### 步骤 3 异常用量：FMS-003（REQ-FMS-003）

**实现逻辑（条件 → 动作 → 结果）**：

1. **数据来源**：用量数据（AG-05 认证会话/话单：流量、时长、接入区域；AG-03 计费：套餐容量、FUP 阈值）、终端/设备台账（AG-08 CPE）、客户与工单（AG-02/AG-07）。
2. **检测模式（三类，可配置启用）**：
   - 超套餐异常流量/带宽：单会话/单日流量或带宽超过套餐容量倍数阈值、突破 FUP 持续使用（消费计费域 FUP 规则结果）；
   - 多设备共享：单账号关联终端数/同时在线终端数 ≥ 阈值（设备指纹集合判定，来源见 CHG-FMS-004）；
   - 越区使用：使用接入区域（认证会话接入位置）与客户登记区域不一致且持续 ≥ 阈值（与 CH-001 越区销售区分，见 CHG-FMS-003）。
3. **命中动作**：生成异常用量告警并**自动关联客户**（带出客户号、账户、套餐、用量明细）；按 FMS-003 例外列**关联工单**——告警给出装维核查工单关联建议（工单创建与执行归客服域 AG-07，本域不直接建单）。
4. **后续处置**：告警进入案件流程（确认违规 → 处置；误报 → 关闭并可入白名单）。

**例外（FMS-003 例外列）**：告警关联客户与工单（见上，客户关联由本域完成，工单关联经客服域执行）。

**边界处理**：家庭多终端正常共享与多设备共享欺诈的区分（阈值 + 白名单 + CPE 台账校验）；漫游/搬迁客户越区使用的正当场景；用量突增可能为正常使用（下载/直播）→ 与历史基线比对而非仅套餐上限。

### 步骤 4 风控名单：FMS-004（REQ-FMS-004）

**实现逻辑（条件 → 动作 → 结果）**：

1. **名单类型与命中动作**（三类名单，见 1.2）：
   - 黑名单（BLACKLIST）：命中 → **拦截**（开户/下单/装维动作直接拒绝）；
   - 灰名单（GRAYLIST）：命中 → **人工审核**（放行或拒绝由人工决定，流程见 CHG-FMS-005）；
   - 白名单（WHITELIST）：命中 → **豁免放行**（承接 FMS-001~003 误报申诉关闭后的豁免，防重复命中）。
2. **名单项管理**：名单值类型可配置（证件号/手机号/IP/设备指纹/客户号/经销商号等）；每个名单项含类型、值、生效期（生效日-过期日）、来源（案件处置/人工添加/预警确认）、状态（有效/过期/已解除，4.2）。
3. **命中判定与拦截（CT-012 实时）**：开户/下单/装维动作发生（CRM/渠道/订单域受理时）→ 实时消费名单判定 → 黑名单返回"拦截"、灰名单返回"人工审核"、白名单返回"放行" → 消费域执行对应动作。**本域不执行拦截动作**（全案 AG-16 非职责），本域留名单命中判定记录（1.3 Interception Directive），执行留痕在消费域（两端分工见 CHG-FMS-002）。
4. **名单变更审批**：名单加入/解除/过期处理均走审批留痕（添加人、审批人、原因、时间）；变更即时生效，按生效期控制。
5. **拦截留痕（FMS-004 例外列）**：命中判定记录（名单项、命中对象、判定结果、时间）+ 消费域拦截执行记录，两端定期对账（见契约联调要点）。

**例外（FMS-004 例外列）**：拦截留痕、名单变更审批（见上）。

**边界处理**：名单命中误伤（证件重号/录入错误）→ 申诉解除通道（联动误报申诉，CHG-FMS-006）；过期名单自动失效；已解除名单不再命中（历史命中记录保留可追溯）。

### 步骤 5 欺诈案件：FMS-005（REQ-FMS-005）

**实现逻辑（条件 → 动作 → 结果）**：

1. **案件创建**：来源（①FMS-001~003 预警确认后自动转案件；②FMS-004 名单命中且人工确认；③人工创建）→ 创建 Fraud Case（案件号、类型、风险等级、来源预警引用），状态 INVESTIGATING。
2. **案件关联**：案件**关联客户/订单/佣金**（关联命中账号的客户集合、涉及订单集合、佣金单与明细——佣金数据消费 AG-10），供调查与报表使用。
3. **调查（调查中）**：调查动作与发现逐条记入调查记录（追加不可删除，留痕）；支持关联证据（预警、订单、用量明细）。
4. **处置结论（状态流转，4.2）**：
   - **确认欺诈（CONFIRMED）**→ 按案件类型联动处置：佣金欺诈 → 佣金冲减/追回（与 AG-10 结算流程衔接）；重复开户/名单命中 → 销户/停服建议（执行归消费域）、加入黑名单（走名单变更审批）；异常用量 → 限速/停机建议、加入黑名单；
   - **确认误报（FALSE_POSITIVE）**→ 关闭案件，解除关联联动动作（解除佣金冻结、解除拦截），可加入白名单，全程留痕。
5. **归档（CLOSED 已处置）**：处置完成归档，案件闭环留痕（状态流转、操作人、时间全程可追溯）。
6. **统计报表**：按周期生成报表（预警数、案件数、按类型/区域/经销商分布、命中率/误报率、处置时长、名单命中与拦截数），供运营与合规消费（事件"欺诈预警命中"→ 合规案件）。

**例外（FMS-005 例外列）**：案件闭环、统计报表可生成（见上）。

**边界处理**：调查/处置时限与升级路径未定义（见遗留事项）；与 RA（AG-15）边界：RA 管话单/批价/收入差异稽核，FMS 管欺诈模式与名单，同一异常可双线处理、互不覆盖，报表层面交叉引用。

## 3. 用例通过记录（验证设计）

> 无真实运行环境，以下为**验证设计**：构造（Given）→ 动作（When）→ 断言（Then）+ 预期证据；待 T-2 用例自动化执行阶段实际执行后回填结果。

### FMS-TC1 重复开户（同证件 3 账号 → 生成预警并关联全部账号）

**验证场景设计**：

- **Given**：客户主数据中同一证件号 X 关联 3 个账号/客户（A、B、C，均在网）；FMS-001 规则启用"证件"维度，阈值=3，检测窗口=30 天（验证场景设定参数）；三账号均不在白名单。
- **When**：重复开户检测运行（窗口内归并统计）。
- **Then**：命中 → 生成欺诈预警（规则 FMS-001、维度=证件、命中值=X、风险等级按配置）；预警**关联全部 3 个账号**（A/B/C）；预警进入人工确认（或按配置自动转案件）；同一窗口内重复运行不重复生成预警（幂等）。
- **预期证据**：欺诈预警记录（预警号、FMS-001、证件 X、关联账号 A/B/C 三笔关联关系）；检测运行日志；去重校验记录。
- **边界注记**：阈值（3）与窗口（30 天）为验证场景设定参数，通用参数基线未冻结（见 6.1）；家庭多人同证件场景需白名单豁免（步骤 1 边界处理）。

### FMS-TC2 佣金欺诈（经销商 1 天集中开户 200 户且 10 户立即销户 → 命中欺诈预警进入案件）

**验证场景设计**：

- **Given**：经销商 D（ACTIVE，授权区域 R）；FMS-002 规则按验证场景设定：集中开户阈值=单日 ≥200 户、立即销户阈值=开户后 ≤7 天内销户 ≥10 户；当日 D 名下新装开户 200 户（渠道来源=D），其中 10 户于开户后 3 天内销户。
- **When**：佣金欺诈检测按日运行。
- **Then**：命中"集中开户 + 立即销户"组合模式 → 生成佣金欺诈预警（关联经销商 D、200 户开户订单、10 户销户明细）→ 预警确认后自动创建欺诈案件（类型=佣金欺诈、状态=调查中、关联订单与佣金明细）→ 联动相关佣金明细冻结待核查（AG-10）。
- **预期证据**：欺诈预警记录（FMS-002、模式命中明细：集中开户 200 户 / 立即销户 10 户）；Fraud Case（关联订单 200 户、佣金明细、状态=调查中）；佣金冻结联动记录（与 AG-10 冻结机制衔接）。
- **边界注记**：集中开户/立即销户的**通用阈值参数**全案未冻结（200 户/10 户为 FMS-TC2 样例参数），T-2 执行前需冻结；命中率/误报率指标（80%/5%）口径与回填见 CHG-FMS-001。

### FMS-TC3 风控拦截（黑名单证件开户 → 拦截并留痕）

**验证场景设计**：

- **Given**：风控名单含黑名单项（名单值类型=证件号、值=X、状态=有效、生效期内）；客户持证件 X 提交开户（CRM 受理）。
- **When**：开户受理触发名单命中判定（CT-012 实时）。
- **Then**：判定返回"拦截" → 开户被拦截（**拦截动作由 CRM 域执行，本域不执行**）→ 本域留名单命中判定记录（名单项、证件 X、判定=拦截、时间），CRM 留拦截执行记录；客户/渠道可见拦截原因（黑名单命中）。
- **预期证据**：名单命中判定记录（Interception Directive：名单项、判定=拦截、时间）；拦截执行留痕（开户单被拒/挂起、原因=黑名单命中）；审计日志（判定与拦截两端记录对账一致）。
- **边界注记**：灰名单"人工审核"流程与名单变更审批链未冻结（CHG-FMS-005）；"拦截留痕"两端分工待确认（CHG-FMS-002）；黑名单误伤（证件重号）走申诉解除（联动误报申诉）。

## 4. 契约联调要点（CT-012）

### CT-012 欺诈预警-拦截（FMS → CRM/渠道/订单）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **提供方/生产者**：产生欺诈预警与风控名单命中判定，实时推送 CRM/渠道/订单域执行拦截（开户拦截、下单拦截、佣金冻结/发放拦截）；本域不执行拦截动作（全案 AG-16 非职责） |
| 时延达成 | 实时：名单命中判定随开户/下单/装维受理动作实时返回；检测规则命中预警实时生成并推送；批量模式检测（重复开户/佣金欺诈/异常用量）按配置周期执行后即时推送 |
| 幂等要求 | 预警以「规则 + 命中维度值 + 检测窗口」为唯一键，同一命中不重复生成；拦截指令以「名单项 + 受理动作」为唯一键，重复受理不重复下发 |
| 失败处理 | 误报申诉关闭（CT-012 失败处理）：申诉通过 → 关闭预警/案件、解除关联拦截与佣金冻结、恢复业务（时限与流程见 CHG-FMS-006）；判定/推送失败 → 重试 + 告警，名单命中判定**不得因推送失败而放行**（拦截从严：先挂起待确认） |
| 联调验证点 | ①开户受理 → 名单命中判定实时返回，黑/灰/白三类结果正确（FMS-TC3）②FMS-001~003 规则命中 → 预警实时生成且关联对象正确（FMS-TC1 关联全部账号）③佣金欺诈预警 → AG-10 佣金冻结/发放拦截联动（与 CH-003 状态流转衔接）④误报申诉关闭 → 拦截解除、佣金恢复发放 ⑤本域命中判定记录 ↔ 消费域拦截执行记录对账一致 ⑥检测运行/推送的幂等与去重 |
