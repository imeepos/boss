## 1. 业务对象清单

### 1.1 设备档案（Device）

**用途**：OLT/交换机/路由器及分光器/端口的统一台账（REQ-DEV-001），是本域监控、告警、影响分析的拓扑基础；与资产台账、GIS 位置三处关联一致（DEV-004）。端口主数据归资源域（AG-06），本域仅叠加监控状态视图（见 CHG-DEV-001）。

| 属性 | 说明 |
|:-----|:-----|
| deviceId | 设备标识（全局唯一） |
| deviceType | 类型：OLT / 交换机 / 路由器 / 分光器（OLT/分光器为接入网关键对象） |
| model / manufacturer / serialNo | 型号 / 厂商 / 序列号（三处一致核对键之一） |
| assetNo | 资产号（关联资产域台账，4.3 主权=资产域） |
| gisRef | GIS 位置引用（坐标/层级地址，GIS-002 变更 [15] 分钟反映） |
| regionId / brandId | 所属区域 / 品牌（区域树：全国→18 大区→81 省，REG-004） |
| layer | 网络分层：核心 / 汇聚 / 接入（REQ-MON-001 分层视图） |
| coreFlag | 是否核心设备（MON-001 严重分级判定） |
| status | 设备状态（见状态集） |
| consistencyStatus | 三处一致性状态：一致 / 不一致（DEV-004 核对结果） |
| monitorView | 监控视图（在线状态、光功率、丢包等实时采集结果，REQ-DEV-002，随设备对象呈现） |

**状态集**：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| ACTIVE 在用 | 在网运行，参与监控与影响分析 | 上线/验收；停用/报废后离开 |
| SUSPENDED 停用 | 停用（维修/冗余），不参与业务 | 停用操作；启用后恢复 |
| RETIRED 报废 | 标记报废、解绑 GIS，历史保留（DEV-003 例外），不参与监控统计 | 报废出库流程 |

**关系**：Device N:1 区域/品牌；Device 1:N 端口（端口主数据消费资源域，本域叠加监控视图）；OLT 1:N 分光器（拓扑）；分光器 1:N 端口；Device N:1 Asset（资产号关联，三处一致校验）；Device 1:N 告警（告警对象）。

### 1.2 CPE 设备（CPE）

**用途**：客户侧设备（ONU/ONT/路由器）的远程管理对象（REQ-DEV-003，TR-069 管理通道），承载状态查询、配置下发、固件升级、重启等批量操作；受安全基线（默认密码/远程管理开关）与白名单约束（REQ-DEV-005、DEV-001）。

| 属性 | 说明 |
|:-----|:-----|
| cpeId | CPE 标识（全局唯一） |
| serialNo / mac | 序列号 / MAC（白名单登记与接入校验键，DEV-001） |
| model / firmwareVersion | 型号 / 当前固件版本（固件升级目标筛选键） |
| subscriptionId / customerId / portRef | 关联订购关系 / 客户 / 接入端口（影响分析与故障诊断锚点） |
| regionId / brandId | 所属区域 / 品牌 |
| whitelistFlag | 白名单登记标记（DEV-001：非白名单拒绝管理） |
| baselineStatus | 安全基线达标状态：达标 / 不达标（默认密码已改、远程管理开关状态） |
| connectStatus | 连接状态（运行态）：在线 / 离线（离线触发未重连跟踪，MON-003 例外） |
| status | 管理生命周期状态（见状态集） |

**状态集**（管理生命周期）：

| 状态 | 含义 |
|:-----|:-----|
| UNREGISTERED 未登记 | 未入白名单，拒绝一切管理操作（接入即告警，DEV-001） |
| REGISTERED 已登记-受管 | 白名单内，可执行状态/配置/固件/重启管理 |
| SUSPENDED 停管 | 白名单移除/停用，停止管理操作（存量配置保留） |
| RETIRED 报废 | 报废解绑，历史保留 |

**关系**：CPE 1:1 白名单登记（DEV-001）；CPE N:1 型号/固件版本（升级任务目标）；CPE 1:1 订阅/客户/端口（业网一致，端口-订阅关系来自资源域）；CPE 1:N 下发记录 / 升级明细；CPE 1:N 告警。

### 1.3 固件升级任务（FirmwareUpgradeTask）

**用途**：固件批量升级的任务化载体（REQ-DEV-003、DEV-003），按批执行、失败重试、成功率统计、清单导出；升级异常自动回滚。

| 属性 | 说明 |
|:-----|:-----|
| taskId | 任务标识 |
| targetFilter | 目标筛选：型号 + 目标固件版本 + 区域/名单（执行时快照锁定，报废设备自动剔除） |
| batchSize | 分批参数（建议 [5,000] 台/批，业务参数） |
| retryLimit | 失败自动重试上限（建议 [3] 次，业务参数） |
| successRate | 最终成功率（口径=成功/应升级，剔除报废与不可达，建议 ≥[98]%，见 CHG-DEV-002） |
| status | 任务状态（见状态集） |
| execSummary | 结果统计：总数 / 成功 / 失败 / 跳过 / 回滚 / 失败原因分布；明细可导出（DEV-TC2） |
| auditRef | 留痕：创建人/时间、审批、执行过程明细（REQ-DEV-003 操作留痕） |

**状态集**：

| 状态 | 含义 |
|:-----|:-----|
| PENDING 待执行 | 已创建未执行 |
| RUNNING 执行中 | 分批执行中 |
| COMPLETED 已完成 | 全部处理完（成功率达标） |
| PARTIAL 部分完成 | 含失败项（重试中或待重跑，可重跑幂等） |
| ROLLED_BACK 已回滚 | 升级致 CPE 离线触发自动回滚旧固件（DEV-001 例外） |
| FAILED 失败中止 | 任务级失败中止，可重跑 |

**关系**：Task 1:N 批次；Task 1:N 升级明细（逐台：成功/失败/跳过/回滚+原因）；回滚明细联动 CPE 台账标记异常。

### 1.4 配置模板与下发记录（ConfigTemplate / ConfigDeployRecord）

**用途**：TR-069 配置参数的标准化模板（REQ-DEV-004），按"型号+套餐+区域/品牌"匹配，支持预下发/自动下发；逐台记录成功/失败并可重试（DEV-002）。

| 属性 | 说明 |
|:-----|:-----|
| templateId / version | 模板标识 / 版本（版本化，变更生成新版本） |
| templateType | 类型：上网参数 / WiFi 参数 / 管理参数等 |
| applyScope | 适用范围：设备型号 + 套餐 + 区域/品牌（下发前匹配校验键，DEV-002） |
| deployMode | 下发方式：预下发（新装/换机先下发再交付）/ 自动下发（模板变更后推送存量） |
| status | 状态：草稿 / 已发布 / 停用 |

**下发记录（ConfigDeployRecord）属性**：目标 CPE、模板版本、下发时间、结果（成功/失败+原因/转人工）、重试次数、生效方式（立即生效 / 重连后生效，DEV-002 例外）。

**状态集**（下发记录）：PENDING 待下发 → DEPLOYING 下发中 → SUCCESS 成功 / FAILED 失败（重试中）→ TRANSFERRED 已转人工（重试 [3] 次仍失败，CT-008 建单）。

**关系**：Template 1:N 下发记录；下发记录 N:1 CPE。

### 1.5 安全基线（SecurityBaseline）

**用途**：CPE 安全基线管理（REQ-DEV-005）：默认密码、远程管理开关、白名单登记；基线不达标产生告警并进入整改闭环（口径见 CHG-DEV-006）。

| 属性 | 说明 |
|:-----|:-----|
| baselineId | 基线项标识 |
| checkItem | 检查项：默认密码已修改 / 远程管理开关 / 白名单登记 |
| checkScope | 检查范围：型号 / 区域 / 品牌 |
| result | 检查结果：达标 / 不达标 / 不适用 |
| lastCheckTime | 最近检查时间（检查频率建议月度，见遗留事项） |
| rectifyRef | 整改闭环引用（不达标告警→整改工单→复检） |

**关系**：Baseline 1:N 检查结果明细（逐 CPE）；检查结果 N:1 CPE（与 CPE.baselineStatus 联动）；不达标联动告警。

### 1.6 告警（Alarm）

**用途**：网络与服务事件的核心对象（4.2 已定义：告警号、级别、对象、时间；状态集 产生/确认/处理中/已关闭），承载分级（MON-001）、同根因合并（MON-002）、影响分析与 CT-008 建单。

| 属性 | 说明 |
|:-----|:-----|
| alarmId | 告警号（全局唯一，CT-008 幂等键） |
| level | 级别：严重 / 主要 / 次要（MON-001 分级） |
| alarmObject | 告警对象：设备（OLT/交换机/路由器/分光器）/ 链路 / 端口 / CPE |
| rootCauseKey | 根因键=上游故障对象+故障类型（MON-002 合并判定；空=独立告警） |
| mainAlarmFlag | 是否主告警（同根因合并后的 1 条主告警，可展开关联明细） |
| affectedCount | 受影响客户数（影响分析结果，MON-003） |
| regionId / brandId | 所属区域 / 品牌 |
| confirmPoll | 误报确认：连续 [2] 次轮询确认仍异常才产生（MON-002 例外，安全类事件口径见 CHG-DEV-004） |
| generateTime / ackTime / processTime / closeTime | 产生 / 确认 / 处理中 / 关闭时间（MTTR 与处理及时率统计基础，MON-005） |
| closeReason | 关闭原因：恢复 / 误报 / 处理完成 |
| ticketRef | 关联工单号（CT-008 自动建单回填） |
| status | 告警状态（见状态集，4.2 口径） |

**状态集**（4.2 已定义，本域细化）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| GENERATED 产生 | 告警已产生（含合并后的主告警） | 异常确认（2 次轮询）；确认/处理/关闭后离开 |
| ACKNOWLEDGED 确认 | 已确认受理 | 值班/客服确认；处理开始后离开 |
| PROCESSING 处理中 | 处理进行中（联动工单处理中） | 处理启动；恢复/关闭后离开 |
| CLOSED 已关闭 | 关闭（恢复/误报/处理完成，区分关闭原因） | 恢复确认/误报判定/处理完成 |

**关系**：Alarm N:1 告警对象（设备/链路/端口/CPE）；主告警 1:N 关联明细告警（可展开）；Alarm 1:0..1 工单（CT-008）；Alarm 1:0..1 受影响客户清单（MON-003）。

## 2. 规则实现说明（DEV-001~004、MON-001~005，含例外）

### DEV-001 CPE 白名单：非白名单管理操作拒绝并告警

**实现逻辑**：
1. **白名单登记**：CPE 以序列号/MAC 登记入白名单方可纳入 TR-069 管理；新装扫码登记联动资产域（与 AG-06 装维扫码流程协同），手工登记需审批；登记信息含型号、固件版本、所属区域/品牌（登记流程口径见 CHG-DEV-003）。
2. **接入校验**：CPE 发起管理操作（状态查询/配置下发/固件升级/重启）前先校验白名单；**非白名单→拒绝全部管理操作**（不下发任何配置与固件、不响应诊断指令），同时产生告警并记录（DEV-TC1 验收）。
3. **告警分级**：非白名单接入属安全类事件，建议按 MON-001 映射为"主要"；安全事件建议**即时告警、不套用 2 次轮询确认**（避免延误安全处置，口径见 CHG-DEV-004）。
4. **留痕**：拒绝操作全程留痕（CPE 标识、时间、操作类型、拒绝原因），可审计（AG-01 审计要求）。

**例外（升级致 CPE 离线自动回滚旧固件并标记异常）**：该例外实际发生在**固件升级环节**——升级后 CPE 离线/无法正常注册时，自动回滚旧固件并在 CPE 台账标记异常（归属错位建议调整，见 CHG-DEV-004）；回滚明细随升级任务留痕可查。

### DEV-002 配置模板预下发/自动下发：下发前校验模板与套餐匹配；失败重试 [3] 次转人工建单

**实现逻辑**：
1. **模板管理**：配置模板按"设备型号+套餐+区域/品牌"定义并版本化；发布后方可用于下发；预下发用于新装/换机（先下发再交付），自动下发用于模板变更后推送存量 CPE（REQ-DEV-004）。
2. **匹配校验**：下发前校验模板与目标 CPE 的套餐/型号匹配；**不匹配→拒绝下发**并提示原因（不产生无效下发）。
3. **下发执行与重试**：逐台记录下发结果（成功/失败+原因）；**失败自动重试 [3] 次**，仍失败**转人工建单**（经 CT-008 建单，工单类型=配置下发失败，附模板版本、目标 CPE、失败原因）。
4. **留痕**：下发记录含模板版本、目标、结果、重试次数、转人工时间，全程可查询、失败项可重试（REQ-DEV-004 验收"失败重试留痕"）。

**例外（批量配置不中断在线会话）**：配置下发**不主动重启/踢断在线会话**；需重启生效的参数标记"重连后生效"，或按授权窗口重启（避开业务高峰）——保证批量配置对存量客户体验无中断。

### DEV-003 固件批量升级：按批 [5,000] 台；失败自动重试；最终成功率 ≥[98]%

**实现逻辑**：
1. **任务建模**：按"型号+目标固件版本+区域/名单"建批量升级任务；报废设备自动剔除（例外）；任务审批留痕（REQ-DEV-003 操作留痕）。
2. **分批执行**：**按批 [5,000] 台**执行；逐台记录结果（成功/失败+原因/跳过）；失败自动重试（重试上限业务参数化，建议 [3] 次）。
3. **成功率口径**：最终成功率=成功台数/应升级台数（**剔除报废与不可达设备**）≥[98]%，任务级统计（建议口径，待需求方确认，CHG-DEV-002）。
4. **回滚与异常**：升级后 CPE 离线/无法注册→**自动回滚旧固件并标记异常**（DEV-001 例外落地于此环节）；任务含回滚状态、回滚清单。
5. **清单导出**：任务明细（逐台结果、时间、重试次数、回滚标记）**可导出**（DEV-TC2 验收）。

**例外（设备报废出库）**：报废设备**标记报废、解绑 GIS，历史保留**——不纳入升级目标、不参与成功率统计；出库流程与资产域协同（AG-06）。

### DEV-004 设备档案与资产/GIS 三处一致，不一致告警

**实现逻辑**：
1. **三处定义**：设备档案（本域台账）vs 资产台账（资产域主权，4.3）vs GIS 位置（资产域/GIS，GIS-002 变更 [15] 分钟反映）。
2. **一致性核对**：**定期（建议日级）+事件驱动**核对三处（设备标识、序列号、位置、状态）；不一致→产生一致性告警（涉及核心设备升级为严重）；新增设备未同步即告警（DEV-TC3 验收）。
3. **消除**：资产域/GIS 同步（或装维回传）后自动复核对账，一致则告警消除（DEV-TC3"同步后消除"）。
4. **端口口径**：端口主数据主权在资源域（AG-06），本域对端口**只读校验并叠加监控状态视图**，不另立台账（CHG-DEV-001）。

### MON-001 告警分级：严重（≥[500]户或核心）、主要（单 OLT/区域）、次要（单客户/端口）

**实现逻辑**：
1. **分级规则**：严重=受影响客户 **≥[500] 户** 或 **核心设备/核心链路**故障；主要=单 OLT 故障/区域级故障；次要=单客户/单端口故障。
2. **采集与分层视图**：核心设备/链路**实时采集**（在线/光功率/丢包，与 REQ-DEV-002 OLT 监控共用采集口径），按核心/汇聚/接入**分层视图**展示，状态与告警实时可见；**离线 [X] 分钟触发告警**（阈值建议：核心 5 分钟/接入 15 分钟，待回填，CHG-MON-001）。
3. **处理闭环**：告警按 4.2 状态集流转（产生→确认→处理中→已关闭）；**闭环超时升级**（REQ-MON-002：超时限未处理自动升级值班/上级，时限分级口径见 CHG-MON-005）。
4. **建单联动**：严重/主要告警经 CT-008 自动建单（≤[30] 分钟）；次要告警不自动建单（避免工单泛滥，口径见 CHG-MON-003）。

**例外（告警风暴合并区域级主告警）**：风暴期（台风/大面积停电导致大量同类告警）**合并为区域级主告警，不逐条派单**（MON-TC2；CT-008 建单口径见 CHG-MON-003），防止告警风暴淹没真实故障。

### MON-002 同根因告警自动合并 1 条主告警，可展开关联

**实现逻辑**：
1. **根因判定**：根因键=**上游故障对象+故障类型**（如 OLT 掉电→其下分光器/端口/CPE 全部离线，同根因）；同根因告警**自动合并为 1 条主告警**。
2. **主告警口径**：主告警级别=关联告警**最高级别**；主告警下关联明细**可展开查看**（REQ-MON-002"可展开关联"）；恢复时主告警统一关闭（关联明细一并关闭，防残留）。
3. **误报控制**：采集异常**不立即告警**——**连续 [2] 次轮询确认**仍异常才产生告警，目标**误报率 ≤[1]%**（误报率=误报告警数/总告警数，月度监控纳入 MON-005 报表口径，见 CHG-MON-002）。

**例外（误报连续 2 次轮询确认才告警）**：见实现逻辑第 3 条；安全类事件（如非白名单接入，DEV-001）是否豁免轮询确认待确认（CHG-DEV-004）。

### MON-003 故障自动计算受影响客户清单，生成公告草稿

**实现逻辑**：
1. **影响计算**：故障告警产生后**沿拓扑自动计算受影响客户**（告警对象→分光器→端口→订阅→客户，端口-订阅关联消费资源域业网一致数据，CONS/CT-009）；清单含客户/联系方式/区域/品牌/套餐/接入端口（REQ-MON-005 验收"清单准确"）。
2. **公告草稿**：自动生成公告草稿（故障原因、影响范围、恢复预估、致歉与自助指引），供客服确认后**一键群发**（发送执行在通知域，NOT-002/005；归属口径见 CHG-MON-004）。
3. **群发跟踪**：群发任务进度与送达率可跟踪（≥98%），失败记录原因可重发（MON-TC3 关联）。

**例外（台风后客户未重连批量复测转装维工单）**：台风过后对**未重连客户批量复测**（远程探测/光功率），复测仍失败→**批量转装维工单**（CT-008），未恢复清单跟踪闭环直至全部恢复。

### MON-004 台风预警触发应急模式：批量公告/恢复复测/值班升级

**实现逻辑**：
1. **触发**：台风预警事件（气象/监管公告，4.5"台风预警触发"）触发**应急模式**；按区域树（REG-004）识别受影响省/市，生成受影响区域清单（多省同时受灾时多区域并行）。
2. **应急任务**：每受影响区域生成应急任务（状态：预警→应急中→恢复中→已结束），**总部统一调度、区域并行处置**（第 5 节详述）。
3. **批量公告**：应急公告（预警/故障进展/恢复通知）按区域**批量群发**，**送达率 ≥98%**（NOT-002 口径），进度可查看、失败可重发（NOT-005）。
4. **恢复复测**：恢复供电/线路后**批量复测**，未恢复转装维工单（MON-003 例外）。
5. **值班升级**：应急期间**值班升级**（区域→总部 7×24），严重故障逐级上报，升级路径与通知留痕。

**例外**：规则表无例外项；告警风暴协同见 MON-001 例外，多省批量处置见第 5 节。

### MON-005 MTTR/MTBF/告警处理及时率月报表

**实现逻辑**：
1. **口径建议**：MTTR=告警**产生至恢复关闭**平均时长；MTBF=设备**两次故障间隔**月均值；及时率=**时限内处理完成**告警占比（时限按级别分级：建议严重 ≤[2]h/主要 ≤[8]h/次要 ≤[24]h，待确认，CHG-MON-005）。
2. **报表生成**：按月自动生成，可按区域/品牌/设备类型/告警级别**下钻**；口径与 BI 域一致（BI-001 口径唯一，可解释可查阅）。
3. **数据来源**：告警状态流转时间（1.6）与工单闭环时间（CT-008 回写）为统计基础；误报率等质量指标随附（MON-002 目标 ≤[1]%）。

**例外**：规则表无例外项。

- **Then**：产生**一致性告警**（核心设备→严重，差异项=资产台账缺失/GIS 缺失）；资产域/GIS 同步后复核对账一致，**告警自动消除**。

**预期证据**：一致性告警记录（时间、差异项明细）；同步回执后告警关闭记录（关闭原因=已同步恢复）。

**边界注记**：核对频率（建议日级）与同步时延（GIS-002 [15] 分钟）待与 AG-06 联调确定。

### MON-TC1 OLT 离线→[X] 分钟告警 + 受影响客户清单

- **Given**：核心 OLT 在线（采集正常），其下分光器/端口/订阅关联完整；离线告警阈值=[X] 分钟（建议核心 5 分钟，CHG-MON-001）。

**边界注记**：根因判定口径（上游故障对象+故障类型）待确认（CHG-MON-002）；风暴期建单口径见 CHG-MON-003。

**边界注记**：公告发送执行在通知域（CHG-MON-004）；送达率口径（成功回执/应达数）与 NOT-002 一致，联调确认。

## 5. 台风应急设计要点（多省同时受灾的批量处置）

> 菲律宾台风季 6-11 月多省同时受灾是常态，本节为 MON-004 的批量处置业务设计；仅描述业务策略，不涉及技术选型与部署架构。

| 策略 | 业务设计 |
|:-----|:---------|
| **预警触发与区域识别** | 台风预警事件（气象/监管公告，4.5）触发应急模式；按区域树（REG-004：全国→18 大区→81 省→市→Barangay）**识别受影响省/市**，生成受影响区域清单（多省同时受灾时清单多区域并行） |
| **应急任务编排（区域并行）** | 每受影响区域**独立应急任务**（预警→应急中→恢复中→已结束）；**总部统一调度、区域并行处置**；单区域故障不阻塞其他区域（区域间互不影响，REG-001 权限：区域经理本区域、总部全量） |
| **批量公告** | 公告内容+目标范围（区域/端口/套餐/品牌，NOT-005）由本域生成草稿、客服确认后交**通知域群发**；渠道按 NOT-001 优先级（SMS>App>Messenger>Viber>Email>站内信），主渠道失败自动切次渠道；**送达率 ≥98%**（NOT-002）；进度可查看、**失败按原因重发**；公告按品牌/区域语言（英/菲） |
| **告警风暴协同** | 台风期间大量离线告警按 MON-001 例外**合并为区域级主告警、不逐条派单**，防止告警风暴淹没真实故障；恢复时区域主告警统一关闭防残留；风暴期建单口径见 CHG-MON-003 |
| **批量复测** | 恢复供电/线路后对**未重连客户批量复测**（远程探测/光功率）；复测仍失败→**批量转装维工单**（MON-003 例外，按区域分批转单防装维工单洪峰）；未恢复清单跟踪闭环直至全部恢复 |
| **值班升级** | 应急期间**值班升级**（区域→总部 7×24）；严重故障逐级上报（区域负责人→总部值班）；升级路径与通知留痕；公告/复测/转单进度纳入总部总览（受影响区域清单、公告送达率、恢复进度） |
| **多省同时受灾批量要点** | ①按区域**并行**处置，区域间互不影响；②公告**按区域分批**发送（每批进度可控，总量不受限）；③复测与转单**按区域分批节流**，防止装维工单洪峰；④总部统一调度视图（总览各区域应急状态） |
| **演练与验收** | **台风应急演练**纳入 AG-08 验收基线（MON-TC3 + 演练）；建议与 REG-005"跨省/跨岛调配与灾备切换演练每季度 1 次"节奏协同；演练记录完整（预警→公告→复测→恢复全流程验证） |
