## 1. 业务对象清单

> 说明：4.2 对象模型未单列应收域对象行（见 CHG-AR-001），本节为**本域细化建模**（4.2 相关延伸），供需求评审补充 4.2 时引用。金额精度统一按 GEN-006。

### 1.1 应收（AR，应收账款）

**用途**：本域核心对象。消费计费域"账单已生成"事件（CT-007 / 4.5 事件）创建，承载账期、未结余额、账龄与催收依据；是账期管理、额度占用、催收、坏账、AR 报表的共同数据源。

| 属性 | 说明 |
|:-----|:-----|
| arId | 应收标识（本域唯一） |
| invoiceNo | 关联账单/发票号（CT-007 账单号，**幂等键**：同一账单不重复建应收） |
| customerId / accountId | 客户 / 账户标识（企业客户账期管理对象） |
| billPeriod | 归属账期（YYYYMM） |
| invoiceDate | 开票日（账期起算日，取账单生成/发票开具日） |
| paymentTermsId | 账期方案引用（合同账期 15/30/45/60 天） |
| dueDate | 到期日 = 开票日 + 账期天数（政府客户按合同豁免顺延） |
| originalAmount / outstandingAmount | 应收金额 / 未结余额（收款核销后递减，GEN-006 精度） |
| disputeId | 关联客户异议（异议期间状态与账龄处理，见 AR-003 例外） |
| version | 版本号（核销/冻结并发控制依据） |

**状态集**：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| OPEN 未结 | 正常应收，未收款 | 账单已生成事件创建 |
| PARTIAL 部分收款 | 已收部分款项未结清 | 收款核销后仍有余额 |
| DISPUTED 异议中 | 客户提出账单异议，暂停催收与停机 | 异议登记；解决后按结果恢复或冲账重建 |
| WRITE_OFF 已核销 | 坏账核销完成，移出应收余额 | 核销单审批通过 |
| CLOSED 已结清 | 全额收款核销完成 | 未结余额归零 |

**关系**：应收 N:1 Account；N:1 账期方案；1:N 收款核销记录（CT-005）；1:N 催收任务；1:0..1 客户异议；核销后 1:N 坏账转回记录。账龄 = 未结余额按开票日至报表日的自然日分段（AR-005）。

### 1.2 账期方案（Payment Terms）

**用途**：账期配置载体（AR-001）。企业客户按合同（CRM Quote/Contract）关联账期方案，本域维护方案配置。

| 属性 | 说明 |
|:-----|:-----|
| termsId | 账期方案标识 |
| termsName | 方案名称（标准/政府合同等） |
| days | 账期天数：15 / 30 / 45 / 60（可配置，冻结为 4 档） |
| remindDays | 到期提醒提前天数（基线冻结为 5 天） |
| exemptFlag | 豁免标记（政府客户 60-90 天按合同豁免，AR-001 例外；豁免天数按合同） |
| status | 状态：ACTIVE 生效 / INACTIVE 停用（历史合同仍按签约时方案） |

**关系**：账期方案 1:N 应收；N:1 合同（CRM 域）；方案停用不影响已签约合同（以合同签订时的方案快照为准，防止历史应收账期被改）。

### 1.3 信用额度（Credit Limit）

**用途**：企业客户信用管控载体（AR-002），承载额度设置、占用与释放。

| 属性 | 说明 |
|:-----|:-----|
| creditLimitId | 额度标识（客户级，一客户一额度） |
| customerId | 客户标识 |
| limitAmount | 授信额度（设置/调整需审批留痕，REQ-AR-002） |
| occupiedAmount | 当前占用 = 未结应收 + 在途订单金额（挂起审批中订单**不**计入，AR-002 例外） |
| availableAmount | 可用额度 = limitAmount − occupiedAmount |
| effectiveDate / expireDate | 生效日 / 有效期至 |
| approver / approvedTime | 最近一次设置/调整的审批人与时间（留痕） |
| status | 状态：ACTIVE 正常 / FROZEN 冻结（风险冻结）/ ADJUSTING 调整审批中 |

**关系**：信用额度 1:N 额度审批单；占用随收款核销（CT-005）释放、随新订单占用（实时校验）；额度冻结时新订单直接挂起进入审批。

### 1.4 信用额度审批单（Credit Approval）

**用途**：超额场景的审批载体（AR-002 例外），支撑"超额拦截或审批留痕"的验收。

| 属性 | 说明 |
|:-----|:-----|
| approvalId | 审批单标识 |
| customerId / orderId | 客户 / 关联订单（挂起订单） |
| requestAmount | 订单金额 |
| currentReceivable | 当前未结应收 |
| occupiedAfter | 审批通过后的预计占用（= 未结应收 + 订单金额） |
| excessAmount | 超额金额（occupiedAfter − limitAmount） |
| approverLevel | 审批层级：区域经理 / 财务主管（适用边界见 CHG-AR-005） |
| result / resultTime / operator | 审批结果 / 时间 / 操作人（留痕） |

**状态集**：PENDING 审批中（订单挂起）→ APPROVED 通过（释放订单继续）/ REJECTED 驳回（订单终止或客户改单）/ CANCELLED 撤销（客户撤单）。

**关系**：审批单 N:1 信用额度；1:1 关联订单（订单域挂起状态联动）；审批全程留痕，超时未审升级机制见遗留事项（审批 SLA 未冻结）。

### 1.5 催收任务（Collection Task）

**用途**：催收分级执行载体（AR-003），承载任务分派、升级与留痕。

| 属性 | 说明 |
|:-----|:-----|
| taskId | 催收任务标识 |
| arId / customerId | 关联应收 / 客户 |
| overdueDays | 逾期天数（策略检查时点值） |
| collectionLevel | 催收等级：L1 短信（1-15 天）/ L2 外呼（16-30 天）/ L3 催收函+暂停新装（31-60 天）/ L4 法务（>60 天） |
| actionType | 本次动作类型（短信 / 外呼 / 催收函 / 暂停新装 / 法务移交） |
| assignee | 分派对象（催收专员 / 区域 / 法务） |
| planTime / finishTime / result | 计划时间 / 完成时间 / 执行结果 |
| operator / operateTime | 操作人 / 操作时间（留痕） |

**状态集**：待分派 / 进行中 / 已完成 / 已升级（跨档自动升级）/ 已关闭（结清或核销后关闭）。

**关系**：催收任务 N:1 应收；1:N 催收动作记录；任务分派记录不可变（留痕即审计依据）。

### 1.6 催收动作记录（Collection Action）

**用途**：催收全动作的不可变留痕明细（REQ-AR-003"任务分配与记录"验收证据）。

| 属性 | 说明 |

| taskId | 关联催收任务 |
| actionType | 短信 / 外呼 / 催收函 / 暂停新装 / 法务移交 / 异议暂停 |
| channel / time | 渠道 / 执行时间 |
| operator | 操作人（系统自动或人工） |
| result | 执行结果（发送成功/通话结果/函件发出/指令回执） |
| attachmentRef | 附件引用（催收函件、异议证据等） |

### 1.7 客户异议（Dispute）

**用途**：异议账单例外场景载体（AR-003 例外），支撑"暂停催收与停机、5 工作日处理"。

## 2. 规则实现说明（AR-001~005，含例外）

> 执行步骤映射：1 账期管理 → 2 信用额度 → 3 催收分级 → 4 坏账 → 5 AR 报表，与本节 2.1~2.5 一一对应。

### 2.1 AR-001 账期管理（步骤 1）

**实现逻辑**：
1. **账期配置**：账期方案 15/30/45/60 天（4 档配置化）；企业客户签约时按合同（CRM Quote/Contract）关联账期方案，以签约时方案快照为准，后续方案调整不影响存量应收。
2. **应收创建**：消费计费域"账单已生成"事件（CT-007 / 4.5，消费方含"应收（账期起算）"）创建应收；**开票日 = 账期起算日**；到期日 = 开票日 + 账期天数。
3. **到期提醒**：每日提醒任务扫描"到期日 − 当前日 = 5 天"且未结清的应收，自动发出到期提醒（通知渠道与通知域协同，中英菲三语模板见遗留事项），提醒自动、留痕。
4. **收款核销**：消费 CT-005 收款到账 → 按账单核销，未结余额递减；全额结清置 CLOSED，部分收款置 PARTIAL。核销冲抵顺序口径见 CHG-AR-010（建议账龄先进先出）。

**例外与边界处理**：
- **政府客户豁免**（AR-001 例外）：政府客户按合同 60-90 天豁免 → 到期日按合同豁免期顺延；豁免期内不计逾期、不触发催收分级与坏账核销条件（衔接口径见 CHG-AR-003）。
- **客户异议**（AR-003 例外）：异议登记后应收置 DISPUTED，暂停该账单的催收与停机联动，5 工作日处理；处理期间建议账龄冻结（CHG-AR-006），防止异议期计入逾期导致误催收/误计提。
- **关账后调整**：计费域关账后账单仅走冲账（CT-007 失败处理），本域联动红冲原应收并按新账单重建（新开票日重新起算账期），冲账联动为事件驱动，防止催收误触发（见 6.2 风险）。

### 2.2 AR-002 信用额度（步骤 2）

**实现逻辑**：
1. **额度设置**：信用专员设置/调整授信额度，设置与调整均需审批留痕（REQ-AR-002"额度设置/审批"）；额度有效期管理（到期自动失效，失效前提醒续授信）。
2. **占用计算**：占用 = **未结应收 + 在途订单金额**（订单提交未完结即计入）；校验条件：占用 ≤ 授信额度。
3. **实时校验与超额处理**：订单提交时实时额度校验；超额 → **订单挂起（不预占资源）** → 自动生成信用额度审批单 → 区域经理/财务主管审批（层级适用边界见 CHG-AR-005）：
   - 审批通过 → 释放订单继续（占用增加、下单流程恢复）；
   - 审批驳回 → 订单终止或客户修改订单；
   - 挂起期间订单不计入占用（AR-002 例外"不预占资源"），且不预占端口等网络资源。
4. **额度释放**：收款核销（CT-005）→ 未结应收减少 → 占用减少、可用额度恢复；订单取消 → 释放在途占用。
5. **拦截与审批两种模式**：REQ-AR-002 验收为"超额拦截或审批留痕"，规则明确超额走审批；"实时拦截"（直接拒绝超额订单）作为可配置模式，适用场景待冻结（CHG-AR-002），默认执行审批模式。

**例外与边界处理**：
- **并发下单**：同一客户并发多笔订单时额度占用以实时占用判定为准（串行判定 + 占用快照），防止并发超占（见 6.2 风险）。
- **额度冻结**：客户风险冻结（FROZEN）时新订单直接挂起进入审批，存量应收不受影响。

### 2.3 AR-003 催收分级（步骤 3）

**实现逻辑**：
1. **逾期判定**：到期日次日 00:00 起计逾期天数（自然日，马尼拉时区）。
2. **每日策略检查**：每日自动扫描逾期应收，按逾期天数匹配分级并执行/分派动作，全程留痕（催收任务 + 催收动作记录）：
   - 逾期 **1-15 天**：自动发送短信提醒（L1）；
   - 逾期 **16-30 天**：外呼（L2），任务分派催收专员，记录通话结果；
   - 逾期 **31-60 天**：催收函 + **暂停新装**（L3），催收函发出留痕，"暂停新装"指令联动订单域（新装/加装订单下单拦截，跨域联调见 4.3）；
   - 逾期 **>60 天**：自动升级法务（L4），案件移交法务（承接方式见遗留事项），留痕。
3. **自动升级**：跨档时自动升级（如 15→16 天、30→31 天、60→61 天），升级动作、任务分派、执行结果全部留痕（不可变）。
4. **任务分派**：按区域 / 客户经理 / 催收专员分派规则自动分派，分派记录留痕（分派人、时间、任务、结果）。
5. **解除**：欠款结清 → 催收任务关闭、暂停新装解除（解除条件见 CHG-AR-007）。

**例外与边界处理**：
- **客户异议**（AR-003 例外）：异议账单暂停催收与停机，5 工作日处理；处理期间催收任务挂起不升级；超时未解决路径见 CHG-AR-006（建议自动升级客服主管/争议仲裁）。
- **政府客户豁免期**：不计逾期，不触发催收分级（与 2.1 一致，CHG-AR-003）。
- **停机档位缺口**：例外原文"暂停催收与**停机**"暗示正常路径存在停机动作，但分级档位未列停机 → CHG-AR-009（建议明确停机档位及与 AG-03 CT-006 的联动，如法务移交时联动停机）。

### 2.4 AR-004 坏账管理（步骤 4）

**实现逻辑**：
1. **计提**：按月计提坏账准备（计提对象 1.8）。基线仅 REQ 提"计提"、规则未定义比例与时点 → 按 CHG-AR-008 建议：以账龄 90+ 未结余额为基数、按配置化比例（待冻结）按月计提，计提留痕。
2. **核销申请**：逾期 ≥90 天（政府豁免期不计，CHG-AR-003）可申请核销 → 生成核销单 → **财务总监审批**（基线冻结，留痕）。
3. **核销执行**：审批通过 → 应收置 WRITE_OFF、移出应收余额；账务处理走计费域冲账/信用单路径联动（CT-007 关账后仅冲账约束），冲账留痕可追溯。
4. **回款自动转回**：核销后收到回款（CT-005）→ **自动转回**：生成转回记录（关联原核销单 + 支付流水号，幂等），坏账冲回可追溯。
5. **核销与催收关系**：核销为财务处理，不豁免法务追偿；核销后回款自动转回即"账销案存"的业务体现。

**例外与边界处理**：
- 核销申请被驳回 → 应收维持 OPEN/PARTIAL，继续催收流程；核销后客户再回款全额/部分 → 均自动转回（按支付流水逐笔）。

### 2.5 AR-005 AR 分析报表（步骤 5）

**实现逻辑**：
1. **账龄分段**：账龄 0-30 / 31-60 / 61-90 / 90+ 四段；账龄 = 报表日 − 开票日（自然日），按未结余额计入对应分段；部分收款按 CHG-AR-010 冲抵口径（建议先进先出）后计余额。
2. **一致性校验**：分段合计 = 总应收余额，与计费域账务核对差异 0（AR-TC3 验收）；异议冻结、核销移出的余额口径与计费域一致（联动 CHG-AR-006 / 4.1）。
3. **逾期率**：逾期余额 / 应收余额（逾期 = 到期日已过且未结清）。
4. **DSO 月计算**：DSO = 期末应收余额 / 当月销售额 × 当月天数（月度口径），公式待冻结（CHG-AR-004）；坏账核销冲减口径随公式冻结一并明确。
5. **报表输出**：月度生成，支持客户 / 区域 / 品牌 / 账期方案维度（业务口径），与账务一致为验收标准（REQ-AR-005）。

**例外与边界处理**：
- 报表口径与计费域出账/关账节奏对齐（出账 6h 内、关账后仅冲账），冲账重建的应收按新开票日重新分段，防止报表与账务短期不一致。

## 3. 用例通过记录（验证设计，未运行）

> 说明：本域无真实运行环境，以下为**验证设计**（Given/When/Then + 预期证据），用于指导 T-2 用例自动化执行阶段；执行结果待回填，未虚构运行结论。

### AR-TC1 信用额度（额度 ₱100K、未结 ₱80K、提交 ₱30K 订单）

**验证场景设计**：
- **Given**：企业客户信用额度 ₱100,000，未结应收 ₱80,000（额度占用 = 80,000），额度状态 ACTIVE。
- **When**：提交 ₱30,000 新装订单 → 实时额度校验（占用 80,000 + 30,000 = 110,000 > 100,000，超额 10,000）→ 订单挂起（不预占资源）→ 自动生成信用额度审批单。
- **Then**：订单置"挂起待审批"且不预占端口/额度；审批单进入区域经理/财务主管审批流；挂起期间占用仍为 80,000（不预占）；审批通过 → 订单继续、占用增至 110,000；审批驳回 → 订单终止。

**预期证据**：额度校验记录（校验时点占用 110,000、超额 10,000）；订单挂起记录（挂起原因=超额、不预占标记）；审批单（订单金额 30,000、超额 10,000、审批人、结果、时间）；审批通过/驳回后的订单状态变更记录与占用变化快照。

**边界注记**：审批层级"区域经理/财务主管"的适用边界（金额/客户等级分级）基线未定义 → CHG-AR-005；"实时拦截"模式适用场景未定义 → CHG-AR-002。

### AR-TC2 催收升级（逾期 45 天）

**验证场景设计**：
- **Given**：应收到期日已过 45 天（未结余额 > 0，无异议、无政府豁免），当前催收等级 L2（外呼已执行）。
- **When**：每日催收策略检查执行 → 逾期 45 天落入 31-60 档 → 自动升级 L3。
- **Then**：生成催收函动作并留痕；下发"暂停新装"指令（订单域拦截该客户新装/加装订单）；催收任务分派至催收专员（分派留痕）；升级动作全留痕。

**预期证据**：策略检查记录（检查时间、逾期 45 天 → 档位 31-60 → L3 升级判定）；催收函发送记录（函件、时间、渠道）；暂停新装指令及订单域回执（跨域联调证据）；任务分派记录（分派人、分派时间、任务）；升级留痕（操作人=系统自动、时间、动作、结果）。

**边界注记**：45 天档位与 AR-003 分级一致（31-60 = 催收函 + 暂停新装）；"暂停新装"解除条件未定义 → CHG-AR-007；正常路径停机档位缺口 → CHG-AR-009。

### AR-TC3 账龄报表（分段合计 = 总应收，差异 0）

**验证场景设计**：
- **Given**：月末账龄报表生成（含应收未结余额、核销、异议冻结等已入账数据，与计费域账务一致）。
- **When**：报表生成后执行一致性校验：各分段合计与总应收余额核对，并与计费域账务数据核对。
- **Then**：分段合计（0-30 + 31-60 + 61-90 + 90+）= 总应收余额，与账务核对**差异 0**。

**预期证据**：账龄报表（四段金额、总应收、逾期率、DSO）；一致性校验记录（分段合计 = 总应收，差异 0）；计费域账务核对记录（差异 0）。

**边界注记**：差异 0 的前提是账龄计算与核销流水一致（CT-005 幂等、到账 ≤5 分钟）且异议冻结、核销移出的口径与计费域一致 → CHG-AR-006 / CHG-AR-010 联动；DSO 公式未冻结 → CHG-AR-004。

## 4. 契约联调要点（CT-005 / CT-007 消费）

> 本域在 4.4 契约矩阵中为 **CT-005 / CT-007 消费方**（CT-005 消费方含"税务/应收"，CT-007 消费方含"应收/客户"），与 4.5 事件"账单已生成"（消费方含"应收（账期起算）"）、"收款已到账"对应。

### 4.1 CT-007 出账-发票（计费 → 税务，本域消费"账单已生成"）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **消费方**：消费"账单已生成"事件创建应收；开票日 = 账期起算日（AR-001） |
| 关键数据 | 账单号、客户/账户、账单金额（含 VAT 拆分，GEN-006 精度）、账期（YYYYMM） |
| 幂等要求 | 以**账单号为幂等键**：同一账单不重复创建应收；重复事件不重复建账 |
| 时延达成 | 依赖计费域出账 ≤6h（D 档，已冻结）；应收创建随事件实时完成，账期/到期日即时可算 |
| 失败处理 | 事件缺失 → 按账单补拉对账（与计费域日对账兜底）；关账后冲账 → 本域联动红冲原应收并按新账单重建（新开票日重算账期），冲账重建事件驱动防催收误触发 |
| 联调验证点 | 开票日=账期起算日；到期日计算（15/30/45/60 + 政府豁免顺延）；账单金额与应收金额一致（含 VAT 拆分）；出账完成 → 应收创建时延；冲账重建不重复建应收 |

### 4.2 CT-005 收款-账务（支付 → 计费，本域消费收款入账结果）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **消费方**：消费收款到账/账单结清结果 → 核销应收、释放额度占用、触发坏账转回 |
| 关键数据 | 支付流水号（幂等键）、收款金额、关联账单、到账时间 |
| 幂等要求 | 以**支付流水号为幂等键**：重复到账通知不重复核销（与 AG-03/AG-04 同一幂等口径） |
| 时延达成 | 依赖到账 ≤5 分钟（已冻结）；本域核销与额度释放随入账结果实时完成 |
| 失败处理 | 核销失败 → 重试 + 列入对账异常清单（与计费/支付域对账闭环），不阻塞后续收款；部分收款按 CHG-AR-010 冲抵口径核销 |
| 联调验证点 | 收款 → 核销 → 未结余额/额度占用更新 → 坏账转回（核销后回款自动转回，关联原核销单）；部分收款核销（先进先出冲抵）；重复到账拦截（核销幂等） |

### 4.3 与其他域的衔接（跨域联调，非契约冻结项）

| 衔接 | 内容 |
|:-----|:-----|
| 暂停新装（AR-003 L3） | 与订单域（AG 订单）联调：暂停新装指令 → 该客户新装/加装订单下单拦截；欠款结清/审批后解除（解除条件见 CHG-AR-007） |
| 停机联动（AR-003 例外及 CHG-AR-009） | 异议暂停停机与正常路径停机档位：与计费域（AG-03）CT-006 停机/复机联动，状态回执闭环 |
| 法务移交（L4） | 逾期 >60 天案件移交法务（系统或线下案件管理承接方式见遗留事项），移交留痕 |
| 催收触达渠道 | 短信/外呼/催收函模板与通知域（AG 通知）协同，中英菲三语模板来源见遗留事项 |
| 额度与合同 | 企业合同账期方案、政府豁免标记来源于 CRM（AG-02）合同/客户属性，同步时延与冲突处理按 4.3 主数据矩阵（客户主数据以 CRM 为准） |
