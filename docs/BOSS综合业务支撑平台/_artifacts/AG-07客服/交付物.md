## 1. 业务对象清单

> 4.2 仅定义 Ticket 一个对象（归属客服域）；本域为实现 REQ-CS-001~006 所需补充的对象清单如下（补充入 4.2 的建议见 CHG-CS-004）。

### 1.1 工单（Ticket，4.2 已定义，本域细化）

**用途**：服务与装维工单的统一载体（4.2 定义"服务与装维工单"），覆盖报障/装维派单/服务变更/余额关怀/回访复核等类型；是 SLA 计时、升级、满意度、质检的挂载主体。

| 属性 | 说明 |
|:-----|:-----|
| ticketId | 工单号（全局唯一；重复报障合并后原工单号保留，见 CS-001 例外） |
| ticketType | 类型：报障 / 装维（订单派单） / 服务变更 / 余额关怀 / 回访复核（满意度低分升级产生） |
| priority | 优先级：普通 / 紧急（单户断网） / 重大（≥500 户或核心，CS-002） |
| customerId / accountId / subscriptionId | 客户 / 账户 / 订购关系（报障类必填；重大工单为受影响客户清单） |
| channel | 来源渠道：电话 / Messenger / Viber / SMS / Web / App / 门店 / 经销商 / 告警自动 / 余额自动（REQ-CS-003） |
| origin | 建单方式：人工 / 自动（告警、余额关怀、重大升级，REQ-CS-004） |
| regionId / brandId | 所属区域 / 品牌（SLA 与 IVR 语种解析维度） |
| cause / symptom | 故障原因分类 / 症状描述（自动建单合并与知识库检索依据，CS-003"同区域同原因合并"） |
| slaLevel | SLA 档位（普通 24h / 紧急 4h / 重大 2h，随 priority 解析） |
| assignee / assigneeGroup | 当前处理人 / 处理组（坐席、装维调度、主管复核） |
| alarmRef / affectedListRef | 关联告警号（CT-008）/ 受影响客户清单引用（重大工单） |
| kbRef | 处理过程中引用的知识库条目（留痕，REQ-CS-005） |
| status | 工单状态（见状态集，CS-001） |

**状态集**（CS-001 冻结，4.2 一致）：新建 → 受理 → 处理中 → 已解决 → 已关闭 → 已回访。

| 状态 | 含义 | 触发/离开 |
|:-----|:-----|:-----|
| 新建 | 工单已生成（人工或自动），待受理 | 建单；坐席/调度受理后离开 |
| 受理 | 已接单、已确认责任人 | 受理动作；开始处理/暂停后离开 |
| 处理中 | 正在诊断/派单/修复 | 处理动作；解决/暂停后离开 |
| 已解决 | 故障修复/问题处理完成，待客户确认或自动复核 | 解决动作；关闭或返工（重新处理中） |
| 已关闭 | 复核通过，工单关闭（关闭起算满意度调查 24h 窗口，CS-005） | 关闭动作（自动复核通过/客户确认）；24h 内发调查 |
| 已回访 | 满意度调查回收或人工回访完成 | 回访完成（评分 <3 分先经主管复核，CS-005） |

**关系**：Ticket 1:N 工单操作留痕；1:1 SLA 计时记录；N:1 客户（报障）；1:N 受影响客户明细（重大）；1:1 满意度调查；1:N 多渠道会话（同一问题经多通道反映，合并到主工单）；Ticket 引用知识库条目（N:M）。

### 1.2 SLA 计时记录（SlaTimer）

**用途**：按优先级分段计时并支持暂停的 SLA 计时载体（CS-001"处理中可暂停等待客户/资源不计 SLA"、CS-002 例外"天气延迟暂停 SLA 恢复续计时"）；升级判定唯一依据。

| 属性 | 说明 |
|:-----|:-----|
| timerId / ticketId | 计时记录标识 / 归属工单（1:1） |
| slaLevel | SLA 档位（普通 24h / 紧急 4h / 重大 2h 响应时限，CS-002） |
| startTime | 计时起点（新建/受理时点，按全案冻结时延口径） |
| elapsed | 已计时时长（暂停段剔除后累计） |
| pauseList | 暂停段明细（起止时间 + 暂停原因：等待客户 / 等待资源 / 天气延迟；天气段通知客户并留痕，CS-002 例外） |
| deadline | 响应时限截止时刻（= startTime + 时限 − 暂停累计） |
| escalateRecord | 升级记录（超时自动升级：时间、升级对象=主管/区域主管、通知留痕） |

### 1.3 工单操作留痕（TicketAction）

**用途**：工单全生命周期操作留痕（"全程留痕"与审计要求，REQ-SYS-003 审计日志消费），也是质检抽检素材。

| 属性 | 说明 |
|:-----|:-----|
| actionId / ticketId | 留痕标识 / 归属工单（1:N） |
| action | 动作：建单/受理/暂停/恢复/解决/关闭/回访/合并/升级/引用知识库等 |
| operator | 操作人（坐席/装维/系统/主管） |
| actionTime / remark | 操作时间 / 说明（暂停原因、合并原工单号等） |

### 1.4 IVR 呼叫会话（CallSession）

**用途**：一次来电从 IVR 进入到结束的全程记录（CS-004"全程留痕"），是接通率/平均等待/放弃率指标的原始数据，也是质检对象之一。

| 属性 | 说明 |
|:-----|:-----|
| callId | 呼叫标识（唯一） |
| callerNumber / customerId | 主叫号码 / 识别后客户（未识别则为匿名） |
| brandId / regionId | 品牌 / 区域（语种解析维度，CS-004） |
| language | 实际语种（英/菲/中，按品牌/区域配置解析，三语内容由 XG-01 提供） |
| ivrPath | IVR 按键路径（逐级留痕） |
| queueId | 进入的队列（如进入坐席队列） |
| waitDuration | 排队等待时长（自入队至接听/放弃/超时） |
| agentId / talkDuration | 接听坐席 / 通话时长 |
| endReason | 结束原因：接通 / 放弃 / 超 60s 回拨 / 留言（CS-004） |
| callbackRef | 回拨/留言单引用（排队超 60s 触发） |

### 1.5 坐席（Agent）与队列（Queue）

**用途**：坐席与队列是呼叫中心人力与分流的基本结构（REQ-CS-002），支持技能（语种/业务）匹配、队列监控与绩效统计。

| 对象 | 关键属性 | 说明 |
|:-----|:---------|:-----|
| Agent | agentId、姓名、技能（语种/业务类型）、归属队列、状态（空闲/忙碌/小休/离线）、排班 | 坐席可属多队列（按技能）；状态变更留痕 |
| Queue | queueId、品牌/区域/语种、入口 IVR 路径、排队策略（超 60s 回拨或留言）、监控指标（排队人数/平均等待/放弃率/接通率） | 队列按"品牌/区域+语种+业务"划分；重大故障时段该队列放弃率不计绩效（CS-003 例外） |

**关系**：Queue N:M Agent（技能匹配）；CallSession N:1 Queue、N:1 Agent；Queue 1:N 绩效统计。

### 1.6 坐席绩效（AgentPerformance）

**用途**：坐席周期绩效（REQ-CS-002"绩效"），供主管查看与考核；重大故障时段放弃率不计入（CS-003 例外）。

| 属性 | 说明 |
|:-----|:-----|
| perfId / agentId / period | 绩效记录 / 坐席 / 统计周期 |
| metrics | 接通量、平均处理时长、满意度平均分、质检得分、放弃率（重大故障时段剔除口径） |
| excludeRef | 绩效剔除记录（剔除时段、原因=重大故障 IVR 公告+群发） |

### 1.7 多渠道会话（ChannelSession）

**用途**：电话/Messenger/Viber/SMS/Web/App/门店/经销商的统一接入会话载体（REQ-CS-003），支撑"渠道来源可统计"与"重复工单自动合并"判定。

| 属性 | 说明 |
|:-----|:-----|
| sessionId | 渠道会话标识（各渠道原文 + 统一标识） |
| channel | 渠道：电话 / Messenger / Viber / SMS / Web / App / 门店 / 经销商 |
| customerId / accountId | 识别后的客户（未识别走 IVR 身份识别或门店/经销商登记） |
| content / attachmentRef | 诉求内容 / 附件（截图、录音） |
| ticketRef | 关联工单（合并后指向主工单，重复报障合并 CS-001 例外） |
| receivedTime / status | 接收时间 / 状态（待处理/已合并/已关联工单/已闭环） |

### 1.8 自动建单触发记录（AutoTicketTrigger）

**用途**：自动建单的触发与判定留痕（REQ-CS-004、CT-008"合并去重"），满足"自动建单率"统计口径与幂等要求。

| 属性 | 说明 |
|:-----|:-----|
| triggerId | 触发记录标识（幂等键：触发源+事件标识，重复事件不重复建单） |
| triggerType | 触发源：告警（CT-008）/ 客户离线（CS-003）/ 余额关怀（REQ-CS-004）/ 重大升级 |

| decision | 判定结果：新建工单 / 合并到既有工单（同区域同原因）/ 跳过（已覆盖） |
| ticketRef / reason | 生成的工单号 / 合并或跳过原因 |

### 1.9 知识库条目（KBArticle）

**用途**：FAQ/SOP 多语言可检索（REQ-CS-005），客服/装维在处理工单时可检索引用；文案与术语三语由 XG-01 提供（已冻结）。

|:-----|:-----|

**用途**：工单关闭后满意度调查与低分升级复核（CS-005、CS-TC3）及服务质量抽检（REQ-CS-006）。

| 对象 | 关键属性 | 说明 |
|:-----|:---------|:-----|
| Survey | surveyId、ticketId（1:1）、发送时间（关闭 24h 内）、渠道（SMS/App/Web/电话）、评分 1-5、回收状态（已回收/未回收/超时）、低分升级标记（<3 分→主管复核并回访） | 回收率口径=回收数/发送数（≥60%）；重复合并工单仅主工单发送（见 CHG-CS-007） |

## 2. 规则实现说明（CS-001~005，含例外）

### CS-001 工单状态流：新建→受理→处理中→已解决→已关闭→已回访；处理中可暂停（等待客户/资源）不计 SLA

**实现逻辑**：
1. **状态流转**：按 1.1 状态集单向推进；**禁止跳转**（如直接改"已关闭"被拒，必须经"已解决"），每步留痕（TicketAction，含操作人与时间戳）。"已解决→已关闭"需复核（自动复核通过或客户确认）；复核不通过返工回"处理中"。
2. **暂停不计 SLA**："处理中"可暂停，暂停原因限定为**等待客户 / 等待资源**两类（防止以暂停规避 SLA）；暂停须记录原因与起止时间，暂停时段从 SLA 计时中剔除（SlaTimer.pauseList），恢复后续计时。
3. **状态与 SLA 联动**：SLA 计时自工单创建（或受理，按全案冻结时延口径）启动；仅"暂停段"不计时；超时自动升级（CS-002）。
4. **装维类工单**：订单派单（AG-02 环节 8"派单"）产生的装维工单复用同一状态流与计时机制（4.2 Ticket 定义含装维）。

**例外（重复报障合并到原工单不重复派单）**：同一客户/同一账户对未闭环的同一问题重复报障（同区域同原因）时，**不新建工单**，合并挂接到原工单（记录合并来源与渠道，TicketAction 留痕），不重复派单、不重复触发 SLA 计时与满意度调查（发送范围见 CHG-CS-007）。

### CS-002 SLA 分级：普通 ≤24h、紧急（单户断网）≤4h、重大（≥500 户或核心）≤2h 响应 + 通知主管

**实现逻辑**：
1. **分级判定**：工单创建时按判定规则解析优先级：紧急=单户断网（报障且影响户数=1）；重大=受影响户数 ≥500 或涉及核心设备/链路（来源：告警影响分析 CT-008、或人工报障汇聚判定）；其余为普通。判定依据与阈值参数化（AG-01 业务参数）。
2. **SLA 计时与升级**：按档位启动响应时限计时（SlaTimer）；**超时未完成响应动作即自动升级**并通知主管（通知对象：紧急→值班主管，重大→区域/总部主管，通知经 XG 通知域，留痕）；重大工单创建即通知主管（不等超时，REQ-CS-001"重大故障通知主管"）。
3. **响应 vs 解决口径**：SLA 时限为**响应时限**（已冻结口径）；"解决时限"基线未定义，升级触发与 CS-TC1 文案的差异见 **CHG-CS-003**。
4. **时限口径**：时延计算按全案冻结口径（业务时间、暂停剔除），本域不另设口径。

**例外（天气延迟标记暂停 SLA 并通知客户，恢复续计时）**：台风等天气导致无法抢修时，工单标记"天气延迟"并暂停 SLA（SlaTimer 暂停段，原因=天气延迟），**同时通知受影响客户**（公告/短信，经 XG 通知域，通知留痕）；天气恢复后解除暂停、续计时（与 CS-002 例外同机制，字段归一到 pauseList）。

### CS-003 客户离线 ≥30 分钟自动建单；同区域同原因合并，重复率 ≤5%

**实现逻辑**：
1. **离线监测与自动建单**：消费监控/认证侧离线事件（客户侧断网判定，CT-008 联动）；**单客户离线持续 ≥30 分钟**自动建单（AutoTicketTrigger，触发源=客户离线），建单前先做合并判定。
2. **合并判定（重复率 ≤5%）**：自动建单先按"**同区域 + 同原因 + 时间窗口**"检索既有未闭环工单：命中→合并（不新建），未命中→新建；合并/新建决策留痕（reason），用于重复率统计与优化合并规则。
3. **重复率口径**：重复率=被合并的重复报障数/自动建单总数（或按 REQ-CS-003"重复工单自动合并率"统计，见 CHG-CS-002 口径确认），目标 ≤5%。
4. **余额关怀/重大升级自动建单**：余额低事件（计费域）触发"余额关怀"工单（人工外呼/通知跟进）；工单或告警升级为重大时按重大工单流程处置（CS-TC2 场景）。

**例外（重大故障 IVR 公告+群发，放弃率不计绩效）**：重大故障（≥500 户或核心）发生时，**IVR 播报公告 + 批量群发通知**（受影响客户清单来自 CT-008 影响分析），该时段/该队列的**放弃率不计入坐席绩效**（AgentPerformance.excludeRef 记录剔除时段与原因），避免非人力因素虚高放弃率。

### CS-004 IVR 语种按品牌/区域配置（英/菲/中）；排队超 60s 回拨或留言；全程留痕

**实现逻辑**：
1. **语种配置**：IVR 语种映射按"**品牌/区域**"维度配置（英/菲/中），来电按主叫归属品牌/区域解析语种；三语文案、术语、语音内容由 **XG-01 横切提供**（已冻结），本域仅消费并配置映射，不自行实现三语。
2. **排队策略**：来电进入队列后开始等待计时；**排队超 60s** 提供两个选项：**回拨**（登记回拨，队列释放）或**留言**（转留言，留痕）；回拨/留言均生成跟踪记录（CallSession.endReason、callbackRef），回拨执行结果回填留痕。
3. **全程留痕**：从 IVR 进入到结束（按键路径、等待、接听、回拨、留言）逐段留痕（CallSession），满足"全程留痕"与质检素材需求。
4. **指标口径**：接通率 ≥90%、平均等待 ≤60s、放弃率 ≤5%（已冻结）；放弃率按 CallSession.endReason=放弃 统计，重大故障时段剔除（CS-003 例外）。

### CS-005 工单关闭 24h 内发满意度调查；评分 1-5，<3 分自动升级主管复核

**实现逻辑**：
1. **调查触发**：工单进入"已关闭"后 **24h 内**发送满意度调查（渠道：SMS/App/Web，经 XG 通知域；调查对象=工单客户；重复合并工单仅主工单发送，见 CHG-CS-007）。
2. **评分与升级**：评分 1-5；**评分 <3 分自动升级主管复核**并触发回访（生成"回访复核"工单，主管复核结论与回访记录留痕）；评分 ≥3 分按正常回访流程（进入"已回访"）。
3. **回收率口径**：回收率=回收调查数/发送调查数，目标 **≥60%**（已冻结）；超时未回收的纳入催答/人工回访清单（见遗留事项）。
4. **质检联动**：质检（REQ-CS-006）抽检对象=通话/工单/渠道会话，质检覆盖率占位待回填（CHG-CS-002）；低分工单与低分通话纳入重点抽检范围（与 CS-005 升级复核衔接）。

## 3. 用例通过记录（验证设计，未运行）

> 说明：本域无真实运行环境，以下为**验证设计**（Given/When/Then + 预期证据），用于指导 T-2 用例自动化执行阶段；执行结果待回填，未虚构运行结论。

### CS-TC1 SLA 升级（单户断网紧急工单→创建→SLA 计时，4h 未解决自动升级通知主管）

**验证场景设计**：
- **Given**：客户 A 报障"单户断网"（电话渠道），系统解析优先级=**紧急**（单户断网），SLA 档位=4h，SLA 计时启动（startTime=T0，无暂停段）；
- **When**：工单进入处理中后持续未解决，计时到达 T0+4h；
- **Then**：系统自动升级工单（escalateRecord 生成）并**通知主管**（通知记录含时间、对象、内容，留痕）；工单状态保持处理中但打升级标记，主管可见待处理升级项。

**预期证据**：工单记录（优先级=紧急、SLA 档位=4h、计时起点）；SlaTimer 计时明细（elapsed=4h、deadline=T0+4h）；升级记录（触发时间=T0+4h、升级对象=主管）；主管通知留痕（发送时间、送达回执）。

**边界注记**：基线 CS-002 时限为"响应时限"，而用例文案为"[4]h **未解决**自动升级"（解决口径）→ 两者存在口径差，已提 **CHG-CS-003**（建议统一为响应时限超时升级 + 增设解决时限）；本验证设计按"超 4h 响应时限未受理/处理即升级"执行，若业务确认解决口径则按解决时限校验。

### CS-TC2 告警合并（同分光器 600 户离线→告警汇聚→生成 1 张重大工单关联 600 户，一键群发）

**验证场景设计**：
- **Given**：监控域（AG-08）告警汇聚判定"同分光器 600 户离线"（受影响客户清单 600 户，经 CT-008 交付本域），影响户数 ≥500 → 重大；
- **When**：自动建单流程处理该告警（AutoTicketTrigger 判定：无既有同区域同原因未闭环工单 → 新建）；
- **Then**：生成 **1 张**重大工单（关联 600 户受影响客户明细，ticketId 唯一）；重大工单创建即通知主管；**一键群发**通知 600 户（公告/短信，经 XG 通知域，送达留痕）；IVR 播报公告，该时段放弃率不计绩效。

**预期证据**：AutoTicketTrigger 记录（触发源=告警、decision=新建、ticketRef）；重大工单（priority=重大、affectedListRef 关联 600 户明细、数量核对=600）；主管通知留痕；群发任务记录（发送数=600、送达率、失败重试清单）。

**边界注记**：CT-008"自动建单 ≤30 分钟"的计时起点为告警接收时点；受影响客户清单准确性由 AG-08 影响分析（REQ-MON-005）保证，清单差异处理见契约联调要点第 4 节。

### CS-TC3 满意度（工单关闭后评 2 分→调查回收→自动升级主管复核并回访）

**验证场景设计**：
- **Given**：工单 B 已关闭，系统在关闭 24h 内发送满意度调查（发送记录生成）；
- **When**：客户回复评分=**2 分**（<3 分）并被回收；
- **Then**：系统自动升级该工单（升级对象=主管复核），生成"回访复核"工单并安排回访；主管复核结论与回访记录留痕；工单最终进入"已回访"。

**预期证据**：调查发送记录（发送时间 ≤ 关闭+24h）；回收记录（评分=2、回收时间）；升级记录（复核对象=主管）；回访复核工单（ticketType=回访复核、回访结果、完成时间）；工单状态链（已关闭→已回访，含复核留痕）。

**边界注记**：回收率 ≥60% 的统计口径（回收数/发送数）与超时未回收催答策略待确认（见遗留事项）。
