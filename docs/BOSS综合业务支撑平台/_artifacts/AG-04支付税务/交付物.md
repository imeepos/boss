## 1. 业务对象清单

### 1.1 Payment/Top-up（支付单）

**用途**：各渠道收款的统一业务记录，是"收款到账"事件的载体，经 CT-005 驱动计费域入账；本域对账、退款、AMLC 标记、资金归集均以支付单为基准。

| 属性 | 说明 |
|:-----|:-----|
| paymentId | 支付单号（本域唯一） |
| channel | 收款渠道：GCASH / MAYA / CARD（银行卡在线+订阅扣款）/ AGENT_COLLECTION（现金代收）/ CASHDESK / VOUCHER（预付券）/ BANK_TRANSFER（银行转账） |
| channelTxnId | 渠道交易号（渠道侧唯一编号，**幂等键**：重复回调/重复导入拦截的依据） |
| customerId / accountId / subscriptionId | 客户 / 账户 / 订购关系标识（收款归属对象；代收点场景可仅凭账单号+姓名定位） |
| amount | 收款金额（PHP，两位小数，GEN-006） |
| currency | 币种（PHP 比索） |
| voucherNo | 券号（渠道=VOUCHER 时必填） |
| agentPoint | 代收点标识（sari-sari / 7-Eleven / Palawan 等） |
| paidTime | 收款成功时间（渠道确认或人工补录） |
| receivedTime | 系统到账入账时间（CT-005 联动） |
| amlFlag | AMLC 标记（大额/可疑，见 PAY-005） |
| sourceRef | 关联单据：账单号 / 退款单号 / 对账批次号 |
| status | 状态（见状态集） |

**状态集**（4.2 定义 + 本域细化）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| PENDING 待支付 | 已发起未获渠道确认（在线渠道用户跳转中/未回调） | 发起收款 |
| SUCCESS 成功 | 渠道确认收款成功，已（或待）通知账务入账 | 渠道回调/人工确认 |
| FAILED 失败 | 渠道拒绝/超时未支付/取消 | 渠道结果 |
| REFUNDED 已退款 | 退款流程完成，原支付单回退 | 退款执行完成 |
| VOIDED 已冲正 | 渠道侧冲正/登记作废（代收登记误录撤销） | 冲正/撤销操作留痕 |

### 1.2 Voucher（预付券）

**用途**：预付券资产的生成、导入、分销、充值、作废全生命周期管理（REQ-PAY-005）；券号 16 位唯一、每券限用 1 次。

| 属性 | 说明 |
|:-----|:-----|
| voucherNo | 券号（16 位，全局唯一，含校验位防错用） |
| faceValue | 面额（PHP，两位小数） |
| batchNo | 制券批次号（批量制券 1 万张 ≤10 分钟的对账单元） |
| brandId | 品牌标识（多品牌隔离，横切 BRAND） |
| effectiveDate / expireDate | 生效日 / 有效期至（过期不可用） |
| soldFlag / soldChannel | 是否已售 / 分销渠道（未售→已售） |
| status | 状态（见状态集） |
| usedPaymentId | 用券支付单号（已用券关联，审计追溯） |

**状态集**（4.2 定义）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| UNSOLD 未售 | 已制券未售出 | 制券完成 |
| SOLD 已售 | 已售出未使用 | 分销/售出登记 |
| USED 已用 | 已成功充值，**不可再用**（终态） | 充值成功 |
| EXPIRED 过期 | 有效期届满自动置入（不可用） | 到期任务 |
| VOIDED 作废 | 管理员作废（不可用，记录原因/操作人） | 作废操作 |

### 1.3 Invoice/Receipt（发票/收据）

**用途**：对外财务单据。Invoice 用于出账开票（CT-007 承接计费域出账），Receipt/OR（官方收据）用于收款证明（代收点 OR 自动生成、Cashdesk 打印 OR）；两者均受 BIR ARN 连续编号约束（TAX-004）。

| 属性 | 说明 |
|:-----|:-----|
| docId | 单据号（本域唯一） |
| docType | 单据类型：INVOICE 发票 / RECEIPT 收据 / OR 官方收据 / WHT_CERT 预扣税凭证 |
| arn | BIR ARN 编号（连续编号，作废保留，见 TAX-004） |
| customerId / accountId | 客户 / 账户 |
| taxGroup | 税务组：应税（VAT 12%）/ 免税（政府/外交 0%）/ 百分比税 / 跨境按合同 |
| netAmount | 折后净额（折扣在净额前扣除，TAX-002） |
| vatAmount | 增值税额（= 净额 × 税率，两位小数四舍五入） |
| totalAmount | 总额（= 净额 + 税额；GEN-006 精度） |
| withholdingAmount | 预扣税额（企业/供应商交易，见 TAX-003） |
| originalDocId | 原单据号（VOID 重开关联，原票保留编号） |
| templateLang | 模板语言（三语，按 REQ-LAN 语言集） |
| issueChannel | 发放渠道：PDF / 邮件 |
| status | 状态（见状态集） |

**状态集**（4.2 定义）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| ISSUED 已生成 | 单据已出具（编号已占用） | 开票/收据生成 |
| VOIDED 已作废 | 作废保留编号（**编号不回收**，记录原因） | VOID 操作（发票重开/登记撤销） |
| SETTLED 已结清 | 对应账单/收款已结清 | 账务结清联动 |

### 1.4 支撑对象（4.2 延伸，本域实现所需）

| 对象 | 说明 | 状态集 |
|:-----|:-----|:-----|
| 退款单（Refund） | 原支付单 + 退款方式（原路/余额/现金）+ 审批链留痕（PAY-004） | 待审批 / 已批准 / 已拒绝 / 已退款 / 已冲正 |
| AMLC 线索（AML Alert） | 大额/可疑交易报告线索：客户、触发交易清单、触发规则、金额、上报状态（PAY-005 / REQ-COMP-003） | 已生成 / 已上报 / 已闭环 |
| 代收登记（Agent Collection） | 代收点收款登记：代收点、账单号/姓名、金额、OR 号、登记时间（REQ-PAY-003） | 已登记 / 已入账 / 已撤销 |
| 银行对账匹配（Bank Reconciliation） | 对账单导入与自动匹配记录：银行流水、匹配状态、差异原因（REQ-PAY-006） | 已匹配 / 未匹配 / 差异处理中 |
| 税务汇总（Tax Summary） | 月度税务汇总：VAT 分类（应税/免税/百分比税）、预扣税、与账务对账差异、导出记录（TAX-005） | 草稿 / 已对账 / 已导出 |

## 2. 规则实现说明（PAY-001~005、TAX-001~005）

> 每条规则按"条件 → 动作 → 结果"描述实现逻辑，并单列例外与边界处理。

### PAY-001 多渠道到账时效与入账（电子钱包/银行卡/预付券实时；现金代收 5 分钟；银行转账按对账批次）

**实现逻辑（条件 → 动作 → 结果）**：
1. **电子钱包（GCash/Maya）在线收款**：客户在门户/App 发起充值 → 跳转渠道支付 → 渠道确认成功（回调）→ 生成支付单（SUCCESS）→ 即时通知账务入账（CT-005，**实时到账**）→ 入账完成回执后支付单置"已入账"，并参与渠道批量对账。
2. **银行卡（信用卡/借记卡）**：①在线支付：与电子钱包同口径，实时到账；②**订阅式自动扣款**：客户授权后，按约定周期（如月）在扣款日批量发起扣款 → 逐笔确认 → 成功即时入账、失败通知客户补缴/重试，扣款记录留痕。
3. **现金代收（sari-sari / 7-Eleven / Palawan 等代收点）**：代收点收款后登记（账单号/姓名 + 金额）→ 系统生成代收登记单并**自动生成 OR** → 5 分钟内完成入账（CT-005 冻结 SLA 覆盖）。
4. **银行转账**：多银行对账单导入 → 自动匹配（金额 + 客户识别号/转账备注）→ 匹配成功按**对账批次**批量入账（不承诺实时）；未匹配单进入人工处理。
5. **重复入账拦截**：以**渠道交易号（channelTxnId）为幂等键**——重复回调、重复导入、重复通知均不重复入账（同一渠道交易号只允许一条支付单与一条入账流水）。

**例外与边界处理**：
- **回调延迟**：超时未收到渠道回调 → 支付单滞留 PENDING/未确认 → 以**渠道凭证**（支付截图、渠道对账单、代收点凭证）**人工确认补入账**；补入账仍走幂等校验，不产生重复。
- **回调金额与请求不符**：拒绝入账并告警，列入对账异常清单，人工核验后处理。
- **银行转账按批次**：到账时效以批次执行为准，不适用"≤5 分钟"实时 SLA（属基线明示例外）；对账差错率 ≤0.1%（任务基线冻结值，全案占位符 [X]% 见 CHG-PAY-005）。

### PAY-002 预付券生命周期（券号 16 位唯一；每券 1 次；作废/过期不可用；批量 1 万张 ≤10 分钟）

**实现逻辑（条件 → 动作 → 结果）**：
1. **批量制券**：制券任务按批次生成券（面额、有效期、品牌），**券号 16 位唯一**（生成时校验唯一性，冲突自动重生成）→ 1 万张制券 ≤10 分钟完成（分批生成 + 批次内唯一性校验）；制券完成后券状态=UNSOLD。
2. **导入/分销**：支持批量导入券（渠道采购）与分销出库；售出登记后状态 UNSOLD→SOLD。
3. **用券充值**：客户在门户输入券号充值 → 系统校验：①券存在 ②状态=UNSOLD 或 SOLD（未用）③未过期 ④未作废 → 校验通过：券置 USED、生成支付单（渠道=VOUCHER）并**即时入账**（CT-005 实时到账）→ 余额即时增加。
4. **作废/过期**：管理员可作废未使用券（记录原因、操作人）；过期券由到期任务自动置 EXPIRED；作废/过期券**不可用**。
5. **错用/重复用为 0**：券状态原子更新（用券与入账同一业务动作），任何状态非"未用"的券一律拒绝并记录尝试日志（防欺诈留痕）。

**例外与边界处理**：
- **重复使用**：已用券再次提交 → 拒绝，返回"券已用"，记录尝试日志（时间、渠道、客户）。
- **作废/过期券**：拒绝并提示状态原因。
- **代收点收错金额**：多收 → 差额**退余额**（生成差额退款入客户余额）；少收 → **催补**（通知代收点/客户补足差额），均留痕。
- 券"已售"环节是否强制（门户直接充值是否要求先售出）基线未定义 → 遗留事项（建议：门户充值允许 UNSOLD/SOLD 均可，分销管控在渠道域）。

### PAY-003 Cashdesk 收款员权限隔离与 OR（仅见姓名/账单号/余额/金额；登记后打印 OR）

**实现逻辑（条件 → 动作 → 结果）**：
1. **数据权限隔离**：Cashdesk 收款员角色查询客户时，**仅可见"姓名 / 账单号 / 余额 / 金额"四字段**；证件号、地址、联系方式、用量、欠费明细等其他数据不可见（功能权限 + 数据权限双重控制，越权访问被拒并留痕）。
2. **登记收款**：收款员凭账单号/姓名定位客户 → 登记收款金额并保存 → 余额**即时更新**（CT-005 入账，实时）→ **自动打印 OR**（连续编号，TAX-004 口径）。
3. **操作留痕**：收款登记单记录收款员、时间、金额、OR 号，可审计追溯。

**例外与边界处理**：
- 账单号/姓名无法唯一定位（重名）→ 按"账单号+区域+品牌"复合条件定位，仍多匹配时禁止登记，转人工核验，杜绝串户错收。
- 权限变更（收款员离职/换岗）即时生效，历史操作留痕不受影响（审计 36 个月，横切）。

### PAY-004 退款（原路/余额/现金；≥₱10,000 主管审批；两级审批）

**实现逻辑（条件 → 动作 → 结果）**：
1. **发起**：客户申请/争议/多收差额触发退款 → 校验：原支付单存在且状态可退（SUCCESS、未全额退过）、退款金额 ≤ 可退金额 → 生成退款单（待审批）。
2. **退款方式**：①**原路**：退回原支付渠道（电子钱包/银行卡）；②**退余额**：计入客户余额（生成余额入账）；③**现金**：柜台现金退还（走 Cashdesk 反向登记，留痕）。
3. **审批**：退款金额 **≥₱10,000 → 主管审批（第一级）+ 更高授权（第二级）两级审批**；审批链全部通过方可执行；任一环节拒绝则退款单终止并通知发起人。审批留痕（审批人、时间、意见）。
4. **执行**：审批通过 → 执行退款 → 原支付单置 REFUNDED → 账务侧生成负向流水（与计费域 CT-005 退款回退联动；**审批通过的退款可产生负余额**，与 BIL-004 例外口径一致）→ 已开票退款联动发票处理（TAX-003：原票 VOID 保留编号 + 重开新票）。

**例外与边界处理**：
- **金额 <₱10,000 的审批要求基线未定义**（"≥1 万主管审批"反推小额可不经主管，但"两级审批"是否全量适用不清）→ 变更建议 CHG-PAY-003（建议：<₱10,000 经办发起 + 主管复核留痕；≥₱10,000 两级审批）。
- 退款金额与账务一致性：退款 ≤ 已收净额（扣除已退款部分）；不允许超退。
- 原路退款渠道失败（渠道侧拒收/账户已注销）→ 转人工，可选改退余额/现金（业务确认后执行，留痕）。

### PAY-005 AMLC 大额/可疑现金交易标记（单笔或当日累计 ≥₱500,000；拆分交易标记可疑）

**实现逻辑（条件 → 动作 → 结果）**：
1. **单笔大额**：现金渠道（代收/Cashdesk）单笔收款 **≥₱500,000** → 自动标记该支付单（amlFlag=大额）。
2. **当日累计**：同一客户**当日现金收款累计 ≥₱500,000**（跨现金渠道合并计算）→ 自动标记当日相关全部现金支付单，并在触发时点（最后一笔登记完成时）即时判定。
3. **动作与结果**：触发后自动**生成 AMLC 报告线索**（客户、交易清单、触发规则、金额、时间）→ **通知合规岗**（REQ-COMP-003）→ 上报动作留痕（线索状态：已生成 → 已上报 → 已闭环）。
4. **拆分交易**：短期内多笔小额现金（单笔 < 阈值、疑似规避）→ **标记可疑**（判定规则参数化：笔数/时间窗/累计金额，见 CHG-PAY-004），同样生成线索通知合规岗。

**例外与边界处理**：
- **累计维度口径**（按客户 / 按账户 / 按收款点）与**拆分判定参数**基线未定义 → 变更建议 CHG-PAY-004（建议按客户跨渠道现金累计；拆分规则配置化并冻结）。
- 本域职责边界：本域**只负责标记与线索生成**，调查/处置归合规/防欺诈域（FMS 联动），不执行冻结等拦截动作。
- "当日"按自然日（00:00-24:00）判定，跨时区口径按马尼拉时区（业务确认，见遗留事项）。

### TAX-001 税务组与税率（应税默认 VAT 12%；免税 0%；百分比税单独配置；跨境按合同）

**实现逻辑（条件 → 动作 → 结果）**：
1. **税务组判定**：客户/产品/合同配置税务组，未配置默认**应税**；判定顺序：合同（跨境）→ 客户类别（政府/外交机构免税）→ 产品类型（百分比税场景）→ 默认应税。
2. **应税**：VAT 12%（= 净额 × 12%，两位小数四舍五入，GEN-006）。
3. **免税（政府/外交）**：税率 0%，发票/收据注明免税标识与免税依据，税额显示 0。
4. **百分比税场景**：单独配置（适用场景、税率、税基，见遗留事项），不混入 VAT 默认处理。
5. **跨境交易**：按**合同约定**税率计取，发票注明约定条款依据。

**例外与边界处理**：税率/税务组配置修改走参数变更留痕；开票时点取**当时有效**税务组（历史单据不回溯变更）。

### TAX-002 发票金额构成（= 折后净额 + VAT；折扣在净额前扣；促销赠送按 BIR 认定）

**实现逻辑（条件 → 动作 → 结果）**：
1. **金额计算顺序**：原价 − 折扣 = **折后净额**（折扣先于税额计算）→ VAT = 净额 × 税率 → **发票金额 = 折后净额 + VAT**（总额两位小数）。
2. **促销赠送**：按 **BIR 认定规则**配置处理（视同销售计税 / 不计税），配置化执行，不臆造口径。
3. **精度**：净额、税额、总额统一分位两位小数四舍五入（GEN-006 冻结），税款单独计算；账单/收据/发票/退款同一规则 → CT-007 对账差异 0 的前提。

**例外与边界处理**：多折扣叠加按业务顺序逐项扣除后取净额；四舍五入只发生在金额入账/出单时点，中间计算不截断。

### TAX-003 预扣税（企业/供应商 1%-5% 代扣出凭证；个人不适用；发票重开原票 VOID）

**实现逻辑（条件 → 动作 → 结果）**：
1. **适用判定**：收款方为企业/供应商且合同配置预扣税率（1%-5% 区间）→ **代扣**；**个人收款方不适用**（不代扣）。
2. **计算与凭证**：支付金额 × 合同税率 = 代扣税额 → 支付时**代扣** → 自动**出具预扣税凭证**（WHT_CERT：税率、税额、支付方/收款方信息），凭证编号同受编号管理约束。
3. **发票重开**：发票需要重开时，**原票置 VOID 保留编号**（不回收），**重开新票**（新 ARN 连续编号），原票作废原因留痕。

**例外与边界处理**：代扣后实付口径（含税支付中代扣 vs 净额支付）按合同约定执行（见 TAX-TC2 注记）；预扣税凭证补打/重打不影响已代扣金额。

### TAX-004 ARN 连续编号（发票/收据编号连续；作废 VOID 保留）

**实现逻辑（条件 → 动作 → 结果）**：
1. **发号**：发票与收据各自维护**连续编号序列**（ARN 前缀/序列配置化；建议分序列，见遗留事项）；发号**串行**（同一时刻只允许一个单据占用一个编号），保证**连续无跳号、无重复**。
2. **作废**：单据作废 → 标记 **VOID 保留编号**（编号不回收、不重用），记录作废原因、操作人、时间。
3. **重开**：VOID 原票后重开新票取下一个连续编号（TAX-003 联动）。

**例外与边界处理**：并发开票（300 万级出账联动）下编号连续性靠串行发号保证（见第 6 节风险）；编号序列与品牌/区域/门店维度是否分号段（BIR 口径）基线未定义 → 遗留事项。

### TAX-005 月度税务汇总（VAT 分类/免税/预扣税；与账务一致可导出）

**实现逻辑（条件 → 动作 → 结果）**：
1. **汇总范围**：按账期（自然月）汇总全部发票/收据/预扣税凭证：VAT 分类（应税销售、免税销售、百分比税）、预扣税合计、收据合计。
2. **对账**：汇总金额与账务流水（计费域 CT-005/007 关联数据）逐项核对，**差异必须为 0**；差异非 0 → 进入差异排查清单（禁止带差异导出申报）。
3. **导出**：对账一致后**导出 BIR 口径月度报表**（支撑申报，格式映射见遗留事项），导出记录留痕（导出人、时间、期间）。

**例外与边界处理**：月中关账后调整（冲账/信用单）→ 红冲/重开单据计入当期汇总的冲减项，保证汇总仍与账务一致；关账后不允许直接修改历史汇总，调整走重算。

**验证场景设计**：
- **Given**：客户当日已有现金收款 ₱300,000（Cashdesk 登记，单笔 <₱500,000 未触发）；当日再通过代收点登记现金收款 ₱300,000。
- **When**：第二笔现金收款登记完成（入账确认时点）→ 系统执行 AMLC 判定：当日现金累计 = 300,000 + 300,000 = **₱600,000 ≥ ₱500,000**。

**预期证据**：AMLC 线索记录（客户、两笔交易清单、触发规则=当日累计、累计金额 600,000、生成时间）；两笔支付单 amlFlag=大额；合规岗通知记录（通知时间、接收人）。

**边界注记**：用例单笔 30 万均未超阈值、累计触发，验证"当日累计"维度成立；"当日"按自然日（马尼拉时区）口径需冻结（见遗留事项）。

### PAY-TC3 Cashdesk 登记收款（余额即时更新、OR 生成、收款员不可见其他数据）

- **When**：收款员按账单号定位客户 A（界面仅展示姓名/账单号/余额/金额四字段）→ 登记收款 ₱500 并保存。
- **Then**：客户 A 余额即时更新（+₱500，≤5 分钟）；OR 自动生成（连续编号）；收款员不可见证件号/地址/用量等其他数据（越权访问被拒）。

**预期证据**：收款登记单 + 入账回执（CT-005）；OR 记录（编号、金额 500、收款员、时间）；字段可见性配置生效记录；越权访问尝试被拒的审计记录（如有）。

### TAX-TC1 发票金额与编号（净额 ₱999 → 999 + VAT 119.88 = ₱1,118.88，编号连续）

**验证场景设计**：
- **Given**：账单净额 ₱999，税务组=应税（VAT 12%）；发票编号序列当前末号 N。
- **When**：出账完成事件（CT-007）触发开票 → 计算：VAT = 999 × 12% = **119.88** → 发票金额 = 999 + 119.88 = **₱1,118.88** → 占用下一连续编号 N+1。
- **Then**：发票金额 = 净额 + VAT = 1,118.88（两位小数，GEN-006）；编号 = N+1（连续无跳号）。

**预期证据**：发票记录（净额 999.00、税额 119.88、总额 1118.88）；编号序列记录（N→N+1，无跳号）；CT-007 开票完成回执。

**边界注记**：本用例金额恰好两位小数精确（与 GEN-006 无冲突）；若净额为不整除值，按四舍五入两位处理（账单/收据/发票同一规则，CHG-BIL-002 已冻结）。

### TAX-TC2 预扣税（企业合同 2% → 支付 ₱50,000 代扣 ₱1,000 出凭证）

**验证场景设计**：
- **Given**：企业客户合同配置预扣税率 2%（收款方为企业/供应商）；当期支付金额 ₱50,000。
- **When**：支付成功 → 预扣税计算：50,000 × 2% = **₱1,000** → 代扣并出具预扣税凭证。
- **Then**：代扣 ₱1,000；出具凭证（税率 2%、税额 1,000）；个人收款方场景不代扣（对照验证）。

**预期证据**：预扣税计算记录；预扣税凭证（WHT_CERT：支付方、收款方、税率 2%、税额 1,000）；账务流水（代扣额）；个人场景无代扣凭证的对照记录。

**边界注记**：代扣后实付口径（含税支付中代扣 vs 净额支付）按合同约定执行，T-2 需按合同样例断言；税率须落在 1%-5% 区间（配置校验）。

### TAX-TC3 月度税务汇总（与账务对账差异 0，可导出 BIR 格式）

**验证场景设计**：

## 4. 契约联调要点（CT-005 / CT-007）

### CT-005 收款-账务（支付 → 计费）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **生产者/发起方**：本域产生"收款到账"事件并驱动计费域入账（充值/缴费），收款数据以本域为准 |
| 时延达成 | **到账 ≤5 分钟（已评审冻结）**：电子钱包/银行卡/预付券实时；现金代收 5 分钟内；银行转账按对账批次（基线明示例外，不适用 5 分钟 SLA）；入账完成回执本域后支付单闭环 |
| 幂等要求 | 以**渠道交易号（channelTxnId）为幂等键**：重复回调/重复通知/重试不重复入账（重复入账拦截=验收基线）；同一渠道交易号仅一条支付单与一条入账流水；金额不一致拒绝并告警 |
| 失败处理 | 入账失败（计费侧回执失败）→ 支付单标记待重试并告警，重试上限 3 次；仍失败 → 列入对账异常清单，次日对账处理；回调延迟 → 以渠道凭证人工确认补入账（幂等校验后执行）；不阻塞后续收款 |
| 联调验证点 | 实时渠道到账时延（≤5min）；重复回调拦截；金额不符拒绝；退款回退（负向流水 + 原支付单 REFUNDED）；银行对账批次匹配与差错率（≤0.1%）；现金代收 5 分钟到账 |

### CT-007 出账-发票（计费 → 税务）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **消费者/接收方**：承接计费域"出账完成"事件（账期+批次），执行发票出具；账单数据由计费域锁定（BIL-005），本域不得修改 |
| 时延达成 | **出账完成后 6h 内完成发票（本任务基线冻结口径）**：出账（02:00 启动，≤6h，08:00 前完成）完成即触发开票，开票批量按批次推进，最迟出账完成 6h 内全部完成；全案 CT-007 记录为 [4]h 占位、AG-03 按 4h 承接 → 口径差异见 CHG-PAY-001 |
| 幂等要求 | 以**"账期 + 批次"为幂等键**：同一账期不重复开票；发票金额 = 账单金额（净额 + VAT 拆分一致，GEN-006 两位小数）→ 对账差异 0 |
| 失败处理 | 开票失败 → 本域重试（上限 3 次）→ 仍失败列入开票异常清单人工处理；开票期间账单数据不变更（计费域已锁定）；关账后冲账/信用单调整 → 联动发票处理：**原票 VOID 保留编号 + 重开新票**（TAX-003/004 口径），月度汇总同步重算 |
| 联调验证点 | 发票金额 = 账单金额（净额/税额/总额逐项一致）；出账完成 → 开票启动时延（6h 时限）；同一账期不重复开票；VOID 重开联动；月度汇总与账务差异 0 |
