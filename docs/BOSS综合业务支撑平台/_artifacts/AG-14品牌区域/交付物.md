## 1. 业务对象清单

> 对照 4.2：**Brand/Region（多品牌多区域维度；品牌号、区域号、配置）为本域既有对象**（4.2 状态集列为"—"，本设计显式化状态集，见 1.1/1.2，不改变 4.2 对象定义与主权归属）。1.3 辅助对象为实现 REQ-REG-001~005 的设计补充，同样不改变 4.2 定义。所有业务对象带"品牌+区域"维度（4.2 业务关系：Customer N—N Brand（订单账务按品牌独立）、Customer N—1 主区域）。组织树（Organization）维度主数据主权在本域（AG-01 交付物 1.6 已确认），本域维护品牌/区域/部门树，AG-01 消费用于数据权限联动。

| 项 | 说明 |
|:---|:-----|

## 2. 规则实现说明（BRAND-001~002、REG-001~005，逐条含例外）

> 按设计步骤组织：2.1 品牌隔离与配置 → 2.2 多层区域树 → 2.3 区域价格 → 2.4 跨区调配 → 2.5 与权限联动。

### 2.1 品牌隔离与品牌配置（BRAND-001 / BRAND-002，支撑 REQ-BRAND-001~002）

**BRAND-001 规则原文**：品牌间客户/订单/账务/资产数据完全隔离；跨品牌访问显式授权。例外：客户跨品牌多产品：档案共享、订单账务按品牌独立。

**业务实现逻辑**：

| 条件 | 动作 | 结果 |
|:-----|:-----|:-----|
| 品牌 A 运营人员查询/操作客户、订单、账务、资产数据（任何业务域功能） | 按数据权限判定：数据品牌维度=品牌 A 集合；对象品牌 ≠ 授权品牌集合 → 拒绝 | **跨品牌访问 0**（REQ-BRAND-001 验收口径：未授权访问恒为 0）；越权尝试产生"越权被拒"审计记录（供举证，AG-01 SYS-003 消费） |
| 特殊业务确需跨品牌访问（例外通道） | 显式授权：总部管理员在数据权限规则中显式加入目标品牌集合（授权范围/时限/用途），授权操作需审批+留痕+可撤销 | 仅被显式授权的账号在授权范围内可跨品牌访问；授权与访问全程审计；撤销即时生效；**授权通道不影响"跨品牌访问 0"验收口径**（授权流程细节见 BCR-AG14-03） |
| 客户跨品牌多产品（BRAND-001 例外） | 客户档案（360°档案）跨品牌共享（CRM 主权，Customer N—N Brand）；订单、账务、资产按品牌独立建档 | 共享档案可见但**订单/账务/资产明细按品牌隔离**；访问他品牌订单/账务仍须显式授权 |
| 品牌停用（Brand 状态=停用） | 品牌下线审批+留痕；存量数据保留只读 | 该品牌不再接受新订单/变更；历史数据可追溯；隔离基线不变 |

**BRAND-002 规则原文**：套餐/价格/促销/门户/通知/话术/单据按品牌独立配置。例外：—（无例外）。

**业务实现逻辑**：

| 条件 | 动作 | 结果 |
|:-----|:-----|:-----|
| 配置套餐/价格/促销/门户/通知/话术/单据 | 以品牌为独立配置单元（BrandRegionConfig 承载），各品牌配置互不影响、独立生效（REQ-BRAND-002 验收"独立生效"） | 品牌 A 的套餐/价格/促销/门户白标/通知模板/话术/单据模板变更不影响品牌 B；各品牌按自身配置运行 |
| 品牌配置变更（敏感，GEN-009） | 审批+二次确认+留痕；按生效时间发布（AG-01 参数/审批能力消费） | 配置变更可回溯；生效可预期 |
| 各域消费品牌配置 | 门户白标/默认语言（XG-04 PORT-006，配置源=本域）、单据/话术/术语按品牌（XG-01）、通知模板按品牌（XG-04 NOT-002）、套餐价格促销（产品资费域） | 品牌化展示与运营统一由品牌配置驱动，各域不自建品牌配置（硬性约束：横切能力统一消费） |

### 2.2 多层区域树与区域运营（REG-004 / REG-001，支撑 REQ-REG-004/001）

**REG-004 规则原文**：多层区域树：全国→18 大区→81 省→城市→Barangay；跨层汇总=各层之和；权限按层继承。例外：区域层级变更审批，历史保留。

**业务实现逻辑**：

| 条件 | 动作 | 结果 |
|:-----|:-----|:-----|
| 区域树初始化/维护 | 维护 5 层区域树（全国→18 大区→81 省→148 市→~4.2 万 Barangay），节点带父节点与层级路径；初始化数据依赖权威行政区划（见 R-03） | 区域树完整可用；任意节点可定位其全部上级/下级 |
| 跨层汇总（区域报表/经营分析） | 按区域树层级聚合：任一层汇总=其直接下级各节点之和=最末级明细之和（跨层汇总=各层之和，REQ-REG-004 验收） | 汇总口径唯一、可下钻至 Barangay 明细；汇总=各区域之和（REG-TC1 判定准则） |
| 区域权限按层继承（REG-004 + AG-01 REQ-SYS-005） | 数据权限规则授权某区域节点=含**全部下级节点**（按层继承）；区域运营经理=本区域含下级（AG-01 权限矩阵第 12 行） | 权限继承正确（REG-004 验收）；上层节点数据对本区域经理可见，平级/他区不可见 |
| 区域层级变更（新增/合并/拆分/调整归属，REG-004 例外） | 提交 RegionChangeRequest → 审批（记录审批人/时间/意见）→ 变更生效（节点状态=变更中过渡）→ 变更前后区域树快照**永久保留** | 历史可追溯（含变更前权限与报表口径）；生效后权限即时按新树重算（AG-01 联动）、报表口径切换（AG-12 联动） |

**REG-001 规则原文**：区域经理数据权限=本区域；总部=全量；区域报表=区域数据。例外：客户跨区域迁址：历史保留原区域并标注迁移。

**业务实现逻辑**：

| 条件 | 动作 | 结果 |
|:-----|:-----|:-----|
| 区域运营经理访问数据/报表 | 数据权限=本区域（含全部下级，按层继承）；仅见本区域数据 | 区域报表=本区域数据（REG-001）；他区数据不可见（AG-01 权限矩阵验证 A） |
| 总部经营分析访问报表 | 总部=全量（全国全品牌，只读） | 总部汇总=各区域之和（REQ-REG-001 验收）；口径与区域独立报表一致（REG-TC1） |
| 客户跨区域迁址（REG-001 例外） | 迁址执行（CRM/订单，ORD-004 已评审冻结）；本域在区域维度标注"原区域历史保留 + 已迁移"（CustomerRegionMoveRecord） | 客户新区域生效；原区域历史数据保留并标注迁移，可追溯迁址前后归属 |
| 区域数据权限调整（组织/人员变动） | 保存即生效，会话实时重算（AG-01 权限服务） | 越权被拒并审计（REQ-SYS-001 联动） |

### 2.3 区域价格差异（REG-002，支撑 REQ-REG-002）

**REG-002 规则原文**：区域价格差异需区域负责人+总部审批。例外：区域促销与总部冲突：区域价格优先，需区域确认。

**业务实现逻辑**：

| 条件 | 动作 | 结果 |
|:-----|:-----|:-----|
| 同品牌某区域申请差异化价格（REQ-REG-002） | 创建 RegionPrice 档位（品牌+区域范围+产品/套餐+区域价格）→ **区域负责人审批 → 总部审批**（两级审批，审批人/时间/意见留痕）→ 生效 | 两级审批通过后区域价格生效；未通过不生效并留痕；区域价格正确（REQ-REG-002 验收） |
| 区域价格生效后取价（订单/计费） | 产品资费/计费域按"品牌×区域"取价：命中区域价格档位用区域价格，否则回退总部价格基线 | 同品牌不同区域差异化价格正确；取价口径唯一（职责边界见 BCR-AG14-04） |
| 区域促销与总部促销冲突（REG-002 例外） | **区域价格优先**，且需区域确认（确认人/时间/生效范围记录在档位"冲突处理标记"） | 区域促销按区域价格生效，冲突处理留痕可追溯 |
| 区域价格档位停用/到期 | 审批+留痕；到期自动失效 | 回退总部价格基线；历史档位保留可回溯 |

### 2.4 跨区调配与灾备切换（REG-003 / REG-005，支撑 REQ-REG-003/005）

**REG-003 规则原文**：跨区域调配需总部审批，记录（来源/目标/数量/时间/审批人）完整。例外：—（无例外）。

**REG-005 规则原文**：跨省/跨岛调配与灾备切换需总部审批，切换演练每季度 1 次成功。例外：演练记录完整。

**业务实现逻辑**：

| 条件 | 动作 | 结果 |
|:-----|:-----|:-----|
| 区域 A 资源不足，申请区域 B 端口等资源（REG-TC2） | 创建 TransferRequest（来源=A、目标=B、资源类型、数量、原因）→ **总部审批**（审批人/时间/意见）→ 审批通过后执行调配 | 调配记录完整：**来源/目标/数量/时间/审批人**五要素齐备（REG-003 验收"记录可追溯"）；审批不通过则驳回并留痕 |

| 跨省/跨大区/跨岛调配（REQ-REG-005） | 同 REG-003 流程，并按岛维度（Luzon/Visayas/Mindanao）标注跨岛属性；总部审批门槛一致 | 跨岛调配记录完整、可追溯 |
| 灾备切换（NFC-7 三地多活，任一岛故障其他岛接管） | **总部审批**后执行切换（切换预案按 O-1 运维手册；备份/恢复执行属 AG-01 SYS-004） | 切换有审批记录；业务连续性达标（NFC-1~3/5） |
| 切换演练（REG-005：每季度 1 次成功） | 每季度（=每 3 个月，与 NFC-4/AG-01 SYS-004 恢复演练周期一致）组织 1 次灾备切换演练 → 演练记录（计划/范围/结果/复盘） | 演练通过 → DisasterSwitchDrillRecord=通过；未通过 → 复盘整改直至通过（例外：演练记录完整），整改闭环留痕（协同见 BCR-AG14-05） |

## 3. 用例通过记录（验证设计）

> **重要声明**：无真实运行环境，以下均为**验证场景设计 + 预期证据判定准则**（如何验证），执行状态=待执行；实际通过/失败结果由 T-2（用例自动化执行）/T-3（契约联调）阶段按本设计执行后回填。不得将本设计视为已运行通过。

### 3.1 BRAND-TC1 品牌隔离（支撑 BRAND-001 / REQ-BRAND-001）

**验证场景 BRAND-TC1-S01**：

- **Given**：品牌 A 运营人员账号（数据权限=品牌 A）；系统中存在品牌 A 与品牌 B 的客户、订单、账务、资产数据（测试数据按 8.9 生成，两品牌数据互不重叠）。
- **When**：品牌 A 运营人员查询客户列表，并尝试直接访问品牌 B 客户档案、订单、账务、资产明细。
- **Then**：
  1. 查询客户列表仅返回品牌 A 数据（品牌 B 数据 0 条）；
  2. 直接访问品牌 B 任何数据 → 被拒，返回无权访问；
  3. 每次越权尝试产生"越权被拒"审计记录（含操作人/对象/时间，AG-01 SYS-003）。
- **预期证据**：查询结果集（仅品牌 A）；越权拒绝回执；审计"越权被拒"记录清单。
- **判定准则**：品牌 A 视角跨品牌访问数=0（REQ-BRAND-001 验收"跨品牌访问 0"）；拒绝回执与审计记录齐全。
- **状态**：验证设计（待执行；依赖 AG-01 权限服务与审计服务）。

**验证场景 BRAND-TC1-S02（例外：客户跨品牌多产品）**：

- **Given**：客户 X 同时使用品牌 A 与品牌 B 产品（跨品牌多产品，BRAND-001 例外）；品牌 A 运营人员账号（未获品牌 B 显式授权）。
- **When**：品牌 A 运营人员查看客户 X 档案与品牌 B 订单/账务。
- **Then**：客户档案（共享部分）可见；品牌 B 订单/账务/资产明细不可见（被拒+留痕）；订单账务按品牌独立。
- **预期证据**：档案可见记录；品牌 B 明细拒绝回执 + 审计记录。
- **判定准则**：档案共享、订单账务按品牌独立（例外语义成立）；未授权跨品牌明细访问=0。
- **状态**：验证设计（待执行；档案共享依赖 CRM 主数据）。

### 3.2 REG-TC1 汇总一致（支撑 REG-001 / REG-004 / REQ-REG-001）

**验证场景 REG-TC1-S01**：

- **Given**：区域 A、区域 B 均有客户与业务数据（含多层级：各含省/市/Barangay 节点数据）；总部经营分析账号（全量只读）；区域 A 经理账号（本区域含下级）。
- **When**：生成全国汇总报表（总部），并分别生成区域 A、区域 B 独立报表；区域 A 经理查询本区域报表。
- **Then**：
  1. 总部汇总=区域 A 数据+区域 B 数据（汇总=各区域之和，REQ-REG-001）；
  2. 任一层级汇总=其下级各节点之和=Barangay 明细之和（跨层汇总=各层之和，REQ-REG-004）；
  3. 区域 A 独立报表=区域 A 数据（区域报表=区域数据）；
  4. 区域 A 经理仅见区域 A（含下级），区域 B 数据不可见（权限按层继承）。
- **预期证据**：汇总报表与各区域明细比对结果；区域独立报表结果；区域 A 经理查询结果集（仅区域 A）。
- **判定准则**：汇总=各区域之和且可下钻至明细；区域独立报表正确；区域经理仅见本区域。
- **状态**：验证设计（待执行；依赖 AG-12 报表口径与 AG-01 数据权限）。

### 3.3 REG-TC2 跨区调配（支撑 REG-003 / REG-005 / REQ-REG-003）

**验证场景 REG-TC2-S01**：

- **Given**：区域 A 资源不足（端口库存不足），区域 B 有可调配端口；区域 A 提交跨区域调配申请；总部审批人账号可用；AG-06 资源域端口状态可联动（模拟桩/联调）。
- **When**：区域 A 提交申请（来源=A、目标=B、资源类型=端口、数量、原因）→ 总部审批通过 → 执行调配。
- **Then**：
  1. 审批记录完整：审批人/时间/意见留痕；
  2. 调配记录完整：**来源/目标/数量/时间/审批人**五要素齐备（REG-003 验收）；
  3. 资源状态同步：目标区域 B 端口状态变更（可预占/在用）、来源区域 A 库存释放（REG-TC2"资源状态同步"断言，执行方 AG-06）；
  4. 全程审计留痕。
- **预期证据**：TransferRequest/TransferRecord 记录（五要素）；总部审批记录；AG-06 端口状态变更记录；审计时间线。
- **判定准则**：审批通过后调配执行；五要素记录完整可追溯；资源状态同步一致。
- **状态**：验证设计（待执行；依赖 AG-06 端口状态联动，联调见 R-07）。

**验证场景 REG-TC2-S02（拒绝路径）**：

- **Given**：同上，总部审批人驳回申请。
- **When**：驳回。
- **Then**：申请单状态=已驳回，驳回意见/时间/审批人留痕；不执行任何资源状态变更。
- **预期证据**：驳回记录；无端口状态变更记录。
- **判定准则**：未审批通过不调配（总部审批门槛成立）。
- **状态**：验证设计（待执行）。

### 4.3 联调方式（8.10 协议）

- 本域不在 CT-001~012 业务契约编号内（DEV-TPL 参数表契约列=横切）；通过"维度主数据 + 维度变更事件"被全域消费，各域以"契约即接口"方式取维度（业务层面口径见 4.1/4.2）；
- 本域未就绪时，下游域使用模拟桩（静态维度快照：样例 3 品牌 + 区域树全量 + 默认配置），联调后换真实维度服务；
- 维度变更事件（品牌停用/区域层级变更/区域价格生效等）供消费方幂等消费（重复处理不产生重复结果）；事件清单缺口见 BCR-AG14-02；
- 联调执行由集成验证 Agent 按 7.3 流程集中执行，本域交付"维度服务定义 + 验证场景设计"（第 3 章）供联调消费。
