## 1. 业务对象清单

### 1.1 Balance（余额账户）

**用途**：承载预付客户的全部可用资金（充值、赠送、信用额度），是预付扣费与停机判定的唯一余额依据。

| 属性 | 说明 |
|:-----|:-----|
| balanceId | 余额账户标识（全局唯一） |
| subscriptionId | 归属订购关系标识（预付一订阅一余额；集团账户可挂多订阅共用） |
| balanceType | 余额类型：预付余额 / 赠送余额 / 信用额度（信用单入账） |
| currency | 币种（PHP 比索） |
| amount | 可用余额金额（可为负，仅限审批通过的信用单/退款场景，见 BIL-004 例外） |
| freezeAmount | 冻结金额（退款/争议待处理时冻结） |
| effectiveDate / expireDate | 生效日期 / 有效期至（到期未续费按 BIL-002 处置） |
| status | 余额状态（见状态集） |
| version | 版本号（并发控制：扣费/充值/入账串行化的依据） |

**状态集**：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| ACTIVE 有效 | 可正常扣费与消费 | 初始；解冻/复机后恢复 |
| FROZEN 冻结 | 争议退款、信用单待审批期间冻结可用额 | 审批通过入账或驳回后解除 |
| EXPIRED 已过期 | 有效期届满且未在 0-30 天窗口续费 | 到期日自动置入 |
| CLEARED 已清零 | 销户（>90 天未续费）时余额清零归档 | 销户流程触发，清零前发通知 |

**关系**：Balance N:1 Subscription（1 订阅可挂多个余额账户：预付+赠送）；Balance 1:N 账务流水（每笔扣费/充值/退款/信用单均产生流水）；余额变动唯一记账依据为账务流水（余额 = 期初 + Σ入账 - Σ扣减）。

### 1.2 Subscription（订购关系/订阅）

**用途**：客户对产品/套餐的订购实例，是计费的最小执行单元；承载计费模式、有效期、用量配额与 FUP 配置。

| 属性 | 说明 |
|:-----|:-----|
| subscriptionId | 订购关系标识 |
| customerId | 客户标识（N:1） |
| accountId | 账户标识（后付/集团：一账户多订阅；集团多账户聚合） |
| productId | 产品/套餐标识（资费来源于产品域 PROD） |
| billingType | 计费模式：PREPAID 预付 / POSTPAID 后付 / WHOLESALE 批发 |
| pricePlanId | 资费/合同标识（批发：合同价、MoU 承诺量、阶梯档位、超量单价） |
| effectiveDate / expireDate | 订购生效日 / 有效期至 |
| status | 服务状态（见状态集） |
| cycleStartDate / cycleEndDate | 当前账期起止（后付自然月；预付为套餐周期） |
| quota | 用量配额：FUP 阈值（限速/停机档）、加购包可用额度、批发 MoU 承诺量 |
| groupFlag / shareRule | 是否集团聚合成员 / 分摊规则（按账户、按比例） |

**状态集**：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| ACTIVE 有效 | 正常服务 | 初始；复机后恢复 |
| SUSPENDED_BALANCE 余额停机 | 预付余额不足/到期停机 | 扣费后余额=0 或不足；缴费/续费后复机 |
| SUSPENDED_AR 欠费停机 | 后付欠费超期（BIL-004 第 30 天；企业按合同） | 缴清欠费后复机 |
| SUSPENDED_ADMIN 管理停机 | 运营商主动停机（合规/工单） | 管理指令 |
| REACTIVATING 复机中 | 复机指令已下发待认证域回执（CT-006） | 回执成功后置 ACTIVE |
| CANCELLED 销户 | 预付 >90 天销户 / 后付 60 天法务销户 | 销户流程，余额清零前置通知 |

**关系**：Subscription N:1 Customer；N:1 Account（集团：多 Account 聚合到集团账户）；1:N Balance；1:N 账务流水；集团聚合下 Subscription 的分摊关系挂在 Account/集团账户上（REQ-BIL-007）。

### 1.3 账务流水（AccountTransaction）

**用途**：一切资金/费用变动的不可变记录，是余额、账单、对账、关账锁定的共同依据。

| 属性 | 说明 |
|:-----|:-----|
| transactionId | 流水号（全局唯一，幂等键之一） |
| transType | 类型：扣费 / 充值 / 退款 / 信用单 / 冲账 / 红冲 / 收据关联 / 余额调整 |
| direction | 方向：入账（+）/ 扣减（-） |
| amount | 金额（含正负） |
| vatAmount | 增值税金额（VAT 12%，账单/收据/发票共用拆分口径） |
| currency | 币种（PHP） |
| transTime | 记账时间（业务时间，含账期归属） |
| billPeriod | 归属账期（YYYYMM；关账锁定按账期） |
| status | 流水状态（见状态集） |
| sourceRef | 来源单据号：账单号 / 收据号 / 信用单号 / 退款单号 / 支付流水号（CT-005 幂等键） |
| relatedBalanceId / subscriptionId | 关联余额账户 / 订购关系 |
| reason | 冲账/调整原因（审批留痕） |

**状态集**：

| 状态 | 含义 |
|:-----|:-----|
| PENDING 待入账 | 已生成未过账（如出账中、退款审批中） |
| POSTED 已入账 | 正式过账，余额/账单已更新 |
| REVERSED 已冲销 | 被冲账红冲（原流水反向标记，金额清零，留痕） |
| RECONCILED 已对账 | 已与支付/税务域对账一致（CT-005/007） |

**关系**：账务流水 N:1 Balance；N:1 Subscription；经 sourceRef 与账单/收据/信用单/退款单/支付流水关联；关账后当期流水禁止直接修改，调整只允许新增冲账/红冲/信用单流水（BIL-005）。

## 2. 规则实现说明（BIL-001~006）

### BIL-001 预付扣费（按日 00:05 扣费；余额不足当日 23:55 停机；周期套餐起始日扣整期）

**实现逻辑**：
1. **按日套餐**：每日 00:05 启动日费扣费任务，扫描当日应扣费且状态为 ACTIVE 的预付订阅；逐户扣减日费，成功即生成负向账务流水并更新余额。
2. **周期套餐**（月/季/年）：套餐周期起始日扣整期费用；扣费日余额不足 → **不扣费、不生成流水**，直接进入停机判定（"不足停机不扣费"）。
3. **停机判定**：当日 23:55 对"扣费失败或扣费后余额=0/不足"的订阅执行停机（置 SUSPENDED_BALANCE 并联动 CT-006 下发停机指令）；余额恰好为 0 视为不足。
4. **停机后不再扣费**：日费任务跳过非 ACTIVE 订阅；停机期间不产生扣费流水。

**例外与边界处理**：
- **跨月按日套餐**：日费按自然日计费，月末、月初各扣一次，不重复不遗漏。实现上以"应扣费日"为幂等键（每订阅每自然日至多一条日费扣费流水），跨月时按日历日推进，不做账期折算。
- **退款致负余额**：仅允许审批通过的信用单/退款单入账产生负余额（BIL-004 例外）；负余额不阻塞后续扣费判定——扣费先冲抵负余额，冲抵后余额仍不足则照常触发停机。
- **出账与充值并发**（后付场景同规则）：以记账顺序为准（BIL-003 例外原文）。同一余额账户内扣费/充值/入账串行处理（version 乐观锁 + 流水号唯一），保证余额=流水合计，杜绝重复扣/漏扣。
- **停机与复机衔接**：停机当日已扣费不退还；复机后自次日 00:05 恢复扣费，停机期间费用**不追扣**（口径待业务确认，见遗留事项）。

### BIL-002 到期提醒、续费保留、销户清零（提醒 3/1 天；0-30 天续费保留余额；>90 天销户清零）

**实现逻辑**：
1. **到期提醒**：到期前第 3 天、第 1 天各生成一次提醒任务（短信/推送，经通知渠道），触发条件=expireDate 倒计时。
2. **到期自动停机**：到期日服务停止（置 SUSPENDED_BALANCE，联动 CT-006）；余额保留在 Balance（EXPIRED 态挂起）。
3. **0-30 天续费窗口**：到期后 30 天内续费 → 账号余额**原额保留**，有效期顺延（自续费日起按新周期重算），订阅即时复机（续费 [X] 分钟复机，建议即时）。
4. **>90 天销户清零**：到期后超过 90 天未续费 → 触发销户流程：**先发清零前通知**（提前通知余额将被清零），再清零余额（Balance 置 CLEARED）、归档订阅（CANCELLED）。
5. **批量延期**：支持对一批到期订阅批量续费/批量延期（运营商活动场景），批量处理逐订阅独立判定，互不影响。

**例外与边界处理**：
- **同时欠后付 + 预付余额为 0**：两账务维度**独立处理**——预付维度按本规则（到期/续费/销户），后付维度按 BIL-004（欠费催缴/停机），不互相耦合，不因一维度处置而牵连另一维度。
- **30-90 天窗口**：基线上未定义该区间余额处置（0-30 保留、>90 清零，中间段悬空）→ 列入遗留事项与变更建议（建议：30-90 天余额继续保留但服务不恢复，或按产品策略配置，需需求方确认）。

### BIL-003 后付批量出账（账期自然月；次月 1 日 02:00 出账；300 万账单 ≤6h；出账期间用量计入下期）

**实现逻辑**：
1. **账期**：自然月（每月 1 日 00:00 - 月末 24:00）。
2. **出账时点**：次月 1 日 02:00 启动批量出账；流程=账期用量/费用汇总 → 计价（月费 + 用量费 + VAT 12%）→ 生成账单 → 触发开票（CT-007）。
3. **出账期间用量计入下期**：出账启动前（01:00）冻结账期用量快照，02:00 起新产生的用量挂入下期账期，保证出账期间无并发写本期数据（BIL-003 例外："出账与充值同时发生以记账顺序为准"同口径）。
4. **合并/分拆账单**：同一账户多订阅默认合并一张账单；可按订阅、按产品、按合同分拆（配置化），合并账单金额=各分项合计。
5. **300 万账单 ≤6h**：批处理策略见第 5 节。

**例外与边界处理**：
- **出账与充值并发**：充值入账不影响本期账单金额（账单金额只基于账期用量与资费合同，不基于实时余额）；充值在出账快照前入账 → 计入当期余额流水，快照后入账 → 下期；以流水记账顺序为准。
- **出账中账户锁定**：出账中的账户禁止并发修改（写锁/状态标记），防重复出账、防遗漏。
- **零金额/无用量账户**：是否出零账单未定义（影响账单量统计与 300 万口径）→ 遗留事项（建议出零账单保持账务连续性，需确认）。

### BIL-004 后付欠费催缴与停机（逾期 7 提醒 / 15 催缴 / 30 停机（企业按合同）/ 60 法务销户）

**实现逻辑**：
1. **欠费计时起点**：账单到期日（出账日 + 账期约定宽限天数；具体天数基线未定义 → 遗留事项）。
2. **催缴阶梯**：逾期 7 天发提醒（首次）；逾期 15 天发催缴（升级话术/渠道，可多次）；逾期 30 天停机（个人客户；**企业客户按合同约定**执行，合同可约定豁免或加宽限）；逾期 60 天转法务/销户（企业按合同）。
3. **停机/复机联动**：停机置 SUSPENDED_AR 并下发 CT-006；**缴清欠费后即时复机**（REQ-BIL-001"续费 [X] 分钟复机"同口径）。
4. **缴费冲抵顺序**：部分缴费按"先欠费、后当期"顺序冲抵；欠费未清零前不解除停机。

**例外与边界处理**：
- **退款致负余额**：仅允许审批通过的信用单场景产生负余额（例外原文）；负余额视同欠费进入催缴计时（口径需确认，见遗留事项）；普通退款在退款审批环节即被拦截，不得制造负余额。
- **停复机幂等**：同一订阅重复触发停机/复机指令不重复执行（CT-006 幂等，见第 4 节）。

### BIL-005 关账与账期锁定（次月 3 日 24:00 关账；调整走冲账/信用单审批）

**实现逻辑**：
1. **关账时点**：每月 3 日 24:00 对上一账期执行关账；账期状态置"已关账/已锁定"。
2. **锁定范围**：当期账单、账务流水、用量数据全部只读；禁止直接修改金额、删除流水、改账单。
3. **关账后调整路径**：仅允许①**冲账**（红冲原流水 + 生成反向流水，双记录留痕）或②**信用单**（审批通过后入账），两条路径均需审批留痕，且联动发票红冲（CT-007）。
4. **时序编排**：2 日出账 → 3 日 24:00 关账，3 日全天为重出账/补漏窗口；关账时点前必须完成当期全部重出账，超时账户进入异常清单（遗留事项）。

**例外与边界**：关账为一次性批量操作，与当日其余账务（扣费/充值）互不影响——关账只锁历史账期，不锁当日实时账务；关账失败重跑幂等（已锁定账期跳过）。

### BIL-006 批发计费（合同价 + 用量阶梯 + MoU；未达 MoU 按 MoU；超额按超量单价；阶梯按月重置）

**实现逻辑**：
1. **合同维度资费**：批发客户按合同维护 pricePlan（合同价、MoU 承诺量、阶梯档位与对应超量单价、VAT 口径）。
2. **月度计量**：当月实际用量逐日累计（计量口径：月累计或 95 分位未定义 → 遗留事项，建议月累计）。
3. **计费判定**：
   - 实际用量 < MoU → **按 MoU 计费**：收取合同价（不按实际用量打折）；
   - 实际用量 ≥ MoU → 合同价 + 超出量 × 超量单价（超出量落入对应阶梯档位取该档单价，阶梯单价随档位递增或按合同约定）。
4. **阶梯按月重置**：每月 1 日用量归零、档位重新从第 1 档起算。
5. **出账**：随后付批量出账流程（次月 1 日）生成批发账单，金额含 VAT 拆分。

**例外与边界**：MoU 达标判定取整规则（如 99.9Mbps 是否达标）与阶梯档位配置来源（产品域）需确认；合同月中变更（调整 MoU/合同价）按合同生效日**分段计算**（变更前段按旧合同、后段按新合同）→ 遗留事项。

### 补充实现说明（REQ-BIL-004 FUP/加购、REQ-BIL-007 集团聚合）

**FUP 与加购（REQ-BIL-004，P0）**：
- 订阅配置 FUP 阈值与超量动作（限速 / 停机）；用量达到阈值时触发动作并联动网络（经认证/资源域生效），触发记录留痕。
- **加购包实时生效**：数据加购包购买成功后立即增加可用额度（quota 即时更新，建议 [X] 分钟内生效，力争实时）；超限状态即时解除（限速解除/停机解除）；加购与 FUP 判定的并发以"当前可用额度"为准，先到先判。

**集团聚合计费（REQ-BIL-007，P1）**：
- 集团客户下多账户各自独立计费与出账（不改变账户级账务）；
- 出账后按**分摊规则**（按账户 / 按比例，配置化）汇总生成集团合并账单；
- **集团支付**按合并账单金额入账，再按分摊规则分账到各账户（生成账户级入账流水）；
- 校验：合并账单金额 = 各账户分项合计（对账差异 0）。

## 3. 用例通过记录（验证设计，未运行）

> 说明：本域无真实运行环境，以下为**验证设计**（Given/When/Then + 预期证据），用于指导 T-2 用例自动化执行阶段；执行结果待回填，未虚构运行结论。

### BIL-TC1 预付扣费停机（余额 150 / 日费 50 / 连续 3 天）

**验证场景设计**：
- **Given**：预付订阅 1 条，Balance 余额 ₱150，日费 ₱50/天，订阅状态 ACTIVE，当日为账期第 1 天。
- **When**：
  - 第 1 天 00:05 日费任务扣费 ₱50 → 余额 ₱100；
  - 第 2 天 00:05 扣费 ₱50 → 余额 ₱50；
  - 第 3 天 00:05 扣费 ₱50 → 余额 ₱0（=0 判定为不足）；
  - 第 3 天 23:55 停机判定执行 → 订阅置 SUSPENDED_BALANCE，停机指令下发（CT-006）；
  - 第 4 天 00:05 日费任务再次运行。
- **Then**：第 3 天扣费后余额为 0 且停机；停机后（第 4 天起）不再产生扣费流水。

**预期证据**：扣费流水 3 条（-50 / -50 / -50，各带自然日应扣费日标记）；余额快照序列（100 / 50 / 0）；停机事件记录（时间戳=第 3 天 23:55，类型=余额不足）；CT-006 停机指令及认证域回执记录；第 4 天无该订阅扣费流水。

**边界注记**：用例表述"第 3 天扣费后余额 0 停机"与规则"余额不足当日 23:55 停机"存在判定时点差异 → 变更建议 CHG-BIL-001（即时判定 + 23:55 批量兜底）。

### BIL-TC2 后付出账金额与 VAT（月费 999 + VAT 12%）

**验证场景设计**：
- **Given**：后付订阅月费 ₱999，VAT 税率 12%，账期上月 1 日-月末，已过出账时点。
- **When**：次月 1 日 02:00 批量出账，对该订阅执行计价。
- **Then**：账单金额 = 999 + 999×12% = **₱1118.88**，按金额精度规则输出（两位小数 ₱1118.88，或元位取整 ₱1119——以精度配置值为准，见 CHG-BIL-002）。

**预期证据**：账单记录（总额 / VAT 拆分：净额 ₱999、税额 ₱119.88、总额 ₱1118.88）；精度规则配置值；出账批次记录（该账户所属批次、完成时间戳）。

**边界注记**：用例原文同时给出 1118.88 与 1119 两种口径，金额精度规则未统一 → 变更建议 CHG-BIL-002（建议账单/收据/发票统一分位两位小数，四舍五入，避免 CT-007 对账差异）。

### BIL-TC3 批发 MoU 计费（MoU 100Mbps 合同价 ₱50000，实际 80Mbps）

**验证场景设计**：
- **Given**：批发合同 MoU=100Mbps，合同价 ₱50000（含 VAT 口径按合同），订阅状态 ACTIVE；当月累计实际用量 80Mbps。
- **When**：月末用量汇总 → MoU 达标判定（80 < 100，未达标）→ 批发计费。
- **Then**：按 MoU 计费，收取合同价 **₱50000**（含 VAT），不按实际用量折扣，阶梯档位不触发。

**预期证据**：月度用量计量记录（80Mbps）；MoU 达标判定记录（未达标，按 MoU 收费）；批发账单（金额 ₱50000，VAT 拆分）；阶梯档位未触发标记。

### BIL-TC4 关账后数据锁定（修改被拒，仅走冲账/信用单）

**验证场景设计**：
- **Given**：上月账单已关账（账期状态=已锁定，BIL-005）。
- **When**：尝试直接修改上月账单金额、或直接删除上月账务流水。
- **Then**：操作被拒绝（返回原因：账期已关账锁定）；调整仅允许通过**冲账**（红冲+反向流水）或**信用单**（审批通过后入账）路径。

**预期证据**：拒绝记录（操作类型、原因、时间戳、操作人）；冲账/信用单审批流程记录（含审批人、通过时间）；关账后无任何直接修改类流水（对账差异 0）。

## 4. 契约联调要点（CT-005 / CT-006 / CT-007）

### CT-005 收款-账务（支付 → 计费）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **接收方/消费者**：消费支付域"收款到账"事件，执行入账（充值/缴费） |
| 时延达成 | 收款到账 [X] 分钟内完成入账（X 待支付域确认，**建议 ≤5 分钟**）；入账即生成账务流水并更新余额，入账完成回执支付域 |
| 幂等要求 | 以**支付域流水号为幂等键**：重复到账通知不重复入账（重复入账拦截）；同一支付流水号只允许一条充值流水（REQ-BIL-005 对账差异 0） |
| 失败处理 | 入账失败 → 余额/流水回滚并告警重试（上限 3 次）；重试仍失败 → 列入对账异常清单，次日对账处理；不阻塞支付域后续收款 |
| 联调验证点 | 正常入账、重复通知拦截、金额不符（拒绝并告警）、退款回退（负向流水+冻结）、并发充值+扣费（记账顺序） |

### CT-006 余额-服务状态（计费 → 认证）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **发起方/生产者**：停机/复机指令的生产者，驱动认证域变更服务状态 |
| 时延达成 | 停机/复机 [X] 分钟生效（建议：**停机即时下发**（余额不足判定/欠费到点即发），**复机缴清欠费后即时下发**；批量场景（300 万级）按批次节流下发）；认证域回执后订阅状态置 ACTIVE/对应停机态 |
| 幂等要求 | 指令携带"订阅标识 + 事件序号"；重复指令不产生重复动作；目标状态=当前状态时跳过（判等幂等）；停机/复机状态与余额一致性以**本域（计费）账务数据为准** |
| 失败处理 | 指令下发失败 → 重试（上限 3 次）→ 超限升级人工处理；无回执指令列入未闭环清单跟踪；批量下发失败批次支持重跑（与第 5 节断点续跑同机制） |
| 联调验证点 | 余额不足停机→认证拒绝服务；缴费复机→服务恢复；停机后不再扣费（与 BIL-TC1 联动）；批量停机/复机与认证域 30-50 万并发能力匹配 |

### CT-007 出账-发票（计费 → 税务）

| 要点 | 内容 |
|:-----|:-----|
| 本域角色 | **发起方/生产者**：出账完成事件触发开票，由税务域（AG-04）执行发票出具 |
| 时延达成 | 出账 4h 内完成发票：出账（≤6h，02:00-08:00 窗口）完成即发出账完成事件并锁定账单数据，开票时限由税务域承接；本域保证账单数据出账后不再变更（BIL-005 锁定） |
| 幂等要求 | 出账完成事件按"账期+批次"唯一；同一账期不重复触发开票；发票金额=账单金额（含 VAT 拆分一致） |
| 失败处理 | 开票失败由税务域重试，本域账单数据不受影响（已锁定）；关账后冲账/信用单调整 → 提供调整依据并联动税务域红冲发票 |
| 联调验证点 | 发票金额=账单金额（净额+VAT 拆分一致）；出账完成→开票启动时延；关账后调整的红冲发票联动 |

## 5. 出账性能设计要点（300 万账单 ≤6h，业务层面）

> 目标基线：D 档全国旗舰，300 万账单出账 ≤6h（次月 1 日 02:00-08:00 窗口）。本节仅描述**业务批处理策略**，不涉及技术选型。

| 策略 | 业务设计 |
|:-----|:---------|
| **分批** | 按账户/客户维度分片成批（如按客户编号区间或区域分片，大客户单独成批避免长尾）；每批独立走完"用量汇总→计价→生成账单→写流水"全流程；批次内账户间串行（保证记账顺序，BIL-003 例外），批次间无依赖 |
| **并行** | 批次间业务相互独立（账户间无共享账务），多批次并行执行；并行度受"出账与充值并发以记账顺序为准"约束——同一账户只在一个批次内，杜绝同账户双写 |
| **断点续跑** | 每批记录处理状态（未开始/处理中/已完成/失败）；失败批次从断点重跑；以"账期+账户"为幂等键判定是否已出账，已出账账户直接跳过，**不重复出账**；出账完成后输出批次报告 |
| **预计算与快照** | 出账启动前（01:00）完成账期用量汇总快照并冻结；出账期间新用量计入下期（BIL-003），从业务上消除出账期数据并发写 |
| **校验与对账** | 出账完成后校验：账单数=应出账账户数、Σ账单金额=Σ用量计费（含 VAT 拆分），差异批次重跑；抽查准确率口径按 REQ-BIL-002 验收基线执行（准确率阈值占位待回填，见 CHG-BIL-003） |
| **调度窗口编排** | 00:05 预付日费扣费 → 01:00 用量快照 → 02:00 后付批量出账启动 → 出账完成触发 CT-007 开票（4h 内）→ 次月 3 日 24:00 关账；6h 出账时限在 02:00-08:00 内完成，与 00:05 扣费窗口错开 |
| **批处理保障** | 批次级失败不影响其他批次（隔离）；出账批次与关账（BIL-005）衔接：3 日 24:00 前重出账/补漏窗口，超时账户入异常清单 |
