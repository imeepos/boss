# T-3 契约联调设计（CT-001~012 联调场景清单）

> 配套：《需求全案》V1.3 第四篇 4.4 + 7.3 联调表 + 各域交付物"契约联调要点"
> 用途：集成验证 Agent 在联调阶段逐契约执行，与 R-2 的 200 场景配套
> 状态：设计态（待真实环境执行）｜日期：2026-08-17

---

## 一、联调执行规则

| 规则 | 说明 |
|:-----|:-----|
| 契约即接口 | 跨域数据交互仅通过 CT-001~012；禁止直接改他域数据 |
| 模拟桩 | 对端未就绪时用模拟桩（按契约切片返回预设数据），联调后换真实实现 |
| 幂等验证 | 重复事件/重复请求不产生重复结果（幂等键验证） |
| 时延断言 | 每契约时延按冻结值断言（见各契约"时延断言"列） |
| 失败处理 | 每契约失败处理按规则验证（见"失败处理验证"列） |
| 通过标准 | 数据一致 + 时延达标 + 幂等正确 + 失败处理符合规则 = 通过 |

## 三、逐契约联调场景

### CT-001 客户建档（一期）

| 项 | 内容 |
|:---|:-----|
| 参与域 | AG-02（产生方）→ AG-03/05/07/XG-04（消费方） |
| 数据 | 客户主数据、品牌、区域（多层区域树） |
| 联调场景 | 新建个人/企业客户 → 各消费方 [5] 分钟内可见 |
| 时延断言 | 消费方可见 ≤ 5 分钟（冻结值） |
| 幂等键 | 客户唯一标识（手机号/TIN+企业名）——重复建档被拒 |
| 失败处理 | 同步失败 → 待同步队列 + 告警，重试直至成功 |
| 验证点 | ①建档→CRM/计费/客服可见 ②品牌/区域字段正确 ③重复建档拒绝 |

### CT-002 订单-资源核查（二期）

| 项 | 内容 |
|:---|:-----|
| 参与域 | AG-02（发起）→ AG-06（返回） |
| 数据 | 核查请求、核查结果（有/无/需扩容）、可选方案 |
| 联调场景 | 新装下单 → 资源核查返回（引用 T-1 数据：640 端口基线） |
| 时延断言 | 实时（核查响应 < [2]h，实际应秒级） |
| 幂等键 | 订单号+地址 |
| 失败处理 | 超时按 ORD-001 重试；无资源进待资源队列 |
| 验证点 | ①核查结果与端口真实状态一致 ②无资源→待资源队列 ③并发核查互斥 |

### CT-003 端口预占（二期）

| 项 | 内容 |
|:---|:-----|
| 参与域 | AG-02（发起）→ AG-06（执行） |
| 数据 | 端口、订单、时效 |
| 联调场景 | 2 单并发预占同一端口 → 仅 1 成功（OSS-TC1 场景） |
| 时延断言 | 实时；预占超时 [72]h 自动释放 |
| 幂等键 | 订单+端口唯一预占 |
| 失败处理 | 并发冲突 → 返回占用+可选方案；取消→释放（10min 回空闲+5min 冷却） |
| 验证点 | ①互斥正确 ②超时释放 ③取消释放 |

### CT-004 订单-收费（一期）

| 项 | 内容 |
|:---|:-----|
| 参与域 | AG-02 → AG-03/04（收款确认） |
| 数据 | 订单、应收金额 |
| 联调场景 | 未收费订单 → 禁止派单（ORD-TC1/INST-TC1） |
| 时延断言 | 实时；[72]h 未收费自动取消释放端口 |
| 幂等键 | 订单号收款确认唯一 |
| 失败处理 | 收费未确认 → 订单停留环节 4；豁免需专项审批标记 |
| 验证点 | ①未收费不派单 ②收费确认→进入预绑定 ③72h 自动取消 |

### CT-005 收款-账务（一期）

| 项 | 内容 |
|:---|:-----|
| 参与域 | AG-04（产生方）→ AG-03（账务更新） |
| 数据 | 支付单、余额、账单 |
| 联调场景 | GCash/现金/券收款 → 账务更新（PAY-TC1 券充值、PAY-TC3 Cashdesk） |
| 时延断言 | 到账 ≤ 5 分钟（冻结值）；电子钱包/券实时 |
| 幂等键 | 渠道交易号（重复回调不重复入账） |
| 失败处理 | 回调延迟 → 人工凭渠道凭证补入账；重复入账拦截 |
| 验证点 | ①各渠道到账时效 ②重复回调拦截 ③退款冲抵正确 |

### CT-006 余额-服务状态（一期）

| 项 | 内容 |
|:---|:-----|
| 参与域 | AG-03（产生方）→ AG-05（执行） |
| 数据 | 停机/复机状态 |
| 联调场景 | 预付余额不足 → 即时停机（BIL-TC1）；续费 → 即时复机（AAA-TC1） |
| 时延断言 | 即时生效（冻结值） |
| 幂等键 | 账户状态变更事件（重复事件不重复执行） |
| 失败处理 | 停机强制下线（宽容规则：[5] 分钟窗口不追讨用量） |
| 验证点 | ①停机即时生效 ②复机即时恢复 ③停机客户认证被拒 ④宽容窗口 |

### CT-007 出账-发票（一期）

| 项 | 内容 |
|:---|:-----|
| 参与域 | AG-03（产生方）→ AG-04（开票） |
| 数据 | 账单、税额、ARN |
| 联调场景 | 出账完成 → 发票生成（BIL-TC2/TAX-TC1 金额断言：999+119.88=1118.88） |
| 时延断言 | 出账 [6]h 内完成发票（D 档冻结值） |
| 幂等键 | 账单号+发票批次 |
| 失败处理 | 关账后仅冲账；ARN 连续作废保留 |
| 验证点 | ①出账→发票时限 ②金额含 VAT 正确（GEN-006 两位小数）③ARN 连续 |

### CT-008 告警-工单（二期）

| 项 | 内容 |
|:---|:-----|
| 参与域 | AG-08（产生方）→ AG-07（建单） |
| 数据 | 告警、受影响客户清单 |
| 联调场景 | OLT 离线 → 自动建单（MON-TC1/CS-TC2：同分光器 600 户 → 1 张重大工单） |
| 时延断言 | 自动建单 ≤ 30 分钟（交付时限，区别于 CS-003 的 30 分钟触发阈值） |
| 幂等键 | 告警号+根因（同根因合并 1 张主工单） |
| 失败处理 | 告警风暴 → 合并区域级主告警不逐条建单 |
| 验证点 | ①自动建单 ②合并去重 ③影响清单准确 ④SLA 计时启动 |

### CT-009 资产-资源-客户（二期）

| 项 | 内容 |
|:---|:-----|
| 参与域 | AG-02/AG-06 → AG-11（GIS）+ BI |
| 数据 | 四码关系（资产-客户-端口-地址） |
| 联调场景 | 资产状态变更 → 四码联动 → GIS 地图更新（AMS-TC1 拆机拦截、GIS-TC1 状态联动） |
| 时延断言 | 关系同步 [15] 分钟；反查响应 ≤ 3 秒 |
| 幂等键 | 资产号+端口唯一绑定 |
| 失败处理 | 冲突按 CONS-004（每日核对，冲突 0 或 24h 处理完） |
| 验证点 | ①四码一致 ②拆机必扫码拦截 ③地图 15 分钟同步 ④反查 3 秒 |

### CT-010 用量-批发计费（三期）

| 验证点 | ①用量采集完整 ②MoU/超量计费正确 ③缺失标记 ④争议冻结 |

## 四、联调通过标准

1. 12 契约全部联调通过，无契约悬空；
2. 每契约：数据一致 + 时延达标 + 幂等正确 + 失败处理符合规则；
3. 与 R-2 场景联动：涉及契约的用例（INST/PAY/BIL/AAA/CS/MON/WHO/RA/FMS 等）在联调后复跑通过；
4. 联调记录归档 `_artifacts/联调/`，含证据（场景执行结果/时延快照）。
