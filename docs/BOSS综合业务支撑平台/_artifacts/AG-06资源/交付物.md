## 1. 业务对象清单

> 对照 4.2：本域实现 4 个既有对象（Port/Network Resource、IP Address、Asset、Inventory），并新增实现级支撑对象（见 1.5，建议补充 4.2，见 CHG-OSS-002）。所有对象带"品牌 + 区域"维度（多层区域树：全国→18 大区→81 省→城市→Barangay）。

### 1.1 端口/网络资源（Port/Network Resource，对照 4.2）

**用途**：可分配网络资源的最小单元（端口），是核查/预占/释放/在用/故障状态机（OSS-001）与预占互斥（OSS-002）的作用对象；承载节点（OLT/分光器）为端口的容器，纳入资源台账（REQ-OSS-004）。

| 属性 | 说明 |
|:-----|:-----|
| portId | 端口标识（全局唯一） |
| nodeId / nodeType | 承载节点（OLT/分光器）标识与类型；端口按"节点-板卡-口"层级定位 |
| regionId / brandId | 所属区域（多层区域树）/ 品牌（区域权限与跨区调配维度） |
| addressRef | 服务地址/小区/楼栋/Barangay 定位（核查入口，REQ-OSS-001） |
| status | 端口状态（见状态集） |
| reservationRef | 有效预占引用：订单号、预占时效（72h 起止，OSS-001） |
| bindingRef | 在用绑定：订阅/客户/资产/地址（四码关系组成部分，AMS-003） |
| utilizationBucket | 利用率归属桶（按承载节点/分光器统计，OSS-004 预警） |
| faultReason / repairTime | 故障原因与修复时间（OSS-003 例外：现场回传） |

**状态集**（4.2 定义 空闲/预占/在用/故障 四项；"释放中"为实现 OSS-001 例外（取消释放 10 分钟回空闲、5 分钟冷却）必需的中间态，见 CHG-OSS-003）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| IDLE 空闲 | 可核查、可预占 | 释放完成/故障修复；预占成功后离开 |
| RESERVED 预占 | 被一有效订单占用（互斥，OSS-002） | 预占成功；超时 [72]h / 订单取消 / 装维完成转在用 |
| IN_USE 在用 | 业务已开通，绑定订阅/客户（业网一致） | 装维完成、配置自动下发成功（REQ-OSS-003）；退订/拆机后释放 |
| FAULT 故障 | 不可预占（OSS-001）；现场发现故障回传改状态（OSS-003 例外） | 故障上报（现场/监控）；修复验证后回空闲 |
| RELEASING 释放中 | 释放流程执行中：取消/超时/退订触发；**[10] 分钟回空闲，其中前 [5] 分钟冷却期不可预占**（OSS-001 例外、OSS-TC2） | 释放触发；满 10 分钟回空闲 |

**关系**：Port 1—0..1 Asset；Port 1—0..1 Subscription（业网一致，REQ-CONS-001：已付费客户无端口为禁止状态）；Port N:1 承载节点；预占/释放过程产生 1:N 预占记录（1.5）。

### 1.2 IP 地址资源（IP Address，对照 4.2）

**用途**：IPAM 地址分配/回收的对象（REQ-OSS-005）：企业静态 IP 全生命周期（申请→分配→绑定→回收）与动态地址池（PPPoE/DHCP 池，供 AG-05 消费）。

| 属性 | 说明 |
|:-----|:-----|
| ipAddress | IP 地址 |
| subnetId | 所属地址段/子网（见 1.5 Subnet） |
| ipType | 类型：企业静态 IP / 动态池地址（按区域+品牌规划，静态与动态隔离） |
| status | 状态（见状态集） |
| customerRef / subscriptionRef | 绑定客户/订购关系（同一 IP 同时一客户，OSS-005） |
| allocOrderRef | 分配来源订单/申请单 |
| recycleTime | 回收中状态的到期时间（退订后 [7] 天，OSS-005） |

**状态集**（对照 4.2 空闲/已分配/回收中，补充"预占"支撑申请流程）：

| 状态 | 含义 | 触发/解除 |
|:-----|:-----|:-----|
| IDLE 空闲 | 可分配 | 分配成功离开 |
| RESERVED 预占 | 申请已受理、待绑定（防并发冲突） | 申请受理；绑定完成转已分配 |
| ALLOCATED 已分配 | 已绑定客户/订阅 | 绑定完成；退订触发回收（解绑立即执行，CHG-AAA-007） |
| RECYCLING 回收中 | 退订后 [7] 天回收期，期内不可再分配 | 退订事件；7 天后回空闲 |

### 1.3 资产（Asset，对照 4.2）

**用途**：设备资产主数据（REQ-AMS-002 档案）；电子标签（一资产一标签，二维码必选/RFID 可选，REQ-AMS-001）；生命周期状态机（AMS-001）；四码关系（AMS-003）；机房设备（机柜/电源/空调）统一纳入本对象台账（REQ-AMS-007，室内外一体化，见 CHG-AMS-006）。

| 属性 | 说明 |
|:-----|:-----|
| assetId | 资产号（唯一） |
| tagNo | 标签号（电子标签：二维码必选，RFID 可选；一资产一标签） |
| assetType | 类型：CPE/ONU/光猫/机顶盒/OLT/分光器/机柜/电源/空调/其他 |
| model / serialNo | 型号 / 序列号（标签损坏时手工录序列号核验补标，AMS-001 例外） |
| locationRef | 位置：机房/小区/楼栋/客户地址（含室内外统一模型） |
| portRef / customerRef / addressRef | 关联端口 / 绑定客户 / 地址（四码，AMS-003） |
| supplierRef / batchNo / warranty | 供应商 / 批次 / 质保（与库存批次联动，AMS-004） |
| status | 状态（见状态集） |
| lifeLog | 生命周期变更记录（触发条件+留痕，AMS-001） |

**状态集**（AMS-001 状态流）：

| 状态 | 含义 | 触发 |
|:-----|:-----|:-----|
| STOCKED 入库 | 已入库（采购入库/验收自动入库，OSS-006） | 入库单/验收通过 |
| ISSUED 领用 | 已出库领用，未绑定客户 | 出库扫码 |
| IN_USE 在用 | 绑定客户/端口，业务在用 | 装维开通扫码绑定 |
| FAULT 故障 | 故障返修 | 故障上报扫码/工单 |
| SCRAPPED 报废 | 报废处置 | 报废审批 |
| UNBOUND 解绑 | 拆机解绑（退订/拆机扫码后） | 拆机必扫码（AMS-002） |

### 1.4 库存（Inventory，对照 4.2）

**用途**：备件与在库资产管理（REQ-AMS-006）：多地点、出入库扫码、供应商、安全库存预警、批次质保；与"在网资产"统一（2.7 总体验收 #1：库存与在网统一）。

| 属性 | 说明 |
|:-----|:-----|
| materialId | 物料号 |
| locationId | 地点（多地点；按区域树归属） |
| quantity | 数量（出入库扫码实时变动） |
| batchNo / warrantyEnd | 批次 / 质保到期（临期 [3] 个月提醒，AMS-004） |
| supplierId | 供应商 |
| safetyStock | 安全库存：[50] 台/地点（默认，按物料类别参数化见 CHG-AMS-004） |

**关系**：出库（扫码）→ 生成/关联资产领用（ISSUED）；入库（扫码）→ 资产入库（STOCKED）或备件增量；"在库"= 未领用资产/备件，"在网"= 在用资产，同一物料跨两态可统计。

## 2. 规则实现说明（OSS-001~006、AMS-001~005，逐条含例外）

> 规则表 3.2.11 仅含 OSS-001~006（REQ-OSS-003 配置自动下发、REQ-OSS-006 纤芯光路无对应规则条目 → CHG-OSS-005）；本节按"规则原文 + 实现逻辑 + 例外"描述业务层面实现，不含技术选型/接口路径。

### OSS-001 端口状态流：空闲→预占→在用→故障；预占超时 [72]h 释放；故障不可预占

**实现逻辑**：
1. **状态机**：端口按 1.1 状态集流转：空闲→（预占成功）→预占→（装维完成+配置自动下发成功，REQ-OSS-003）→在用→（退订/拆机）→释放流程；空闲/预占/在用任一态可因故障上报（现场回传 OSS-003 例外 / 监控）转故障；故障修复验证后回空闲。
2. **预占时效**：预占成功即登记时效 **72 小时**（起算=预占成功时刻）；到期未转在用（订单未完成）→ 自动释放（走释放流程），并发布"预占超时预警"通知订单域催办/确认。
3. **故障不可预占**：FAULT 状态拒绝一切预占与核查推荐（核查可选方案不推荐故障端口）。
4. **释放流程（含取消竞态）**：任何释放（取消/超时/退订）统一走"释放中"状态：端口立即置 RELEASING（**先释放后通知**——先改端口状态、后通知订单域，杜绝"通知已发但端口未释放"竞态）；**满 [10] 分钟回空闲**；其中**前 [5] 分钟为冷却期**，任何预占请求明确拒绝（含紧急调配），冷却期语义与 10 分钟释放期的关系见 CHG-OSS-004。

**例外（订单取消与释放竞态）**：订单取消时执行"先释放后通知 + 5 分钟冷却"：端口状态先于订单侧通知变更，冷却期内不可立即预占（OSS-TC2 验证）；超时（72h）释放无并发订单竞态，但统一走释放流程保证状态可追溯。

### OSS-002 预占互斥：同端口同时仅一有效订单；并发仅一成功

**实现逻辑**：
1. **互斥键**：预占动作以"端口 + 订单"为唯一生效键；同一端口同一时刻只允许存在**一**个有效预占（RESERVED 状态即占用）；任何第二笔预占请求被拒并返回"占用 + 可选方案"（OSS-003 口径）。
2. **并发仅一成功**：并发预占同一端口时，仅一笔成功（成功者登记端口、订单与 72h 时效），其余失败（OSS-TC1 验证）；核查（读）与预占（写）分离——核查阶段允许多单并发读取同一结果，互斥发生在预占写入。
3. **释放即解除互斥**：释放（取消/超时/退订）后端口进入释放流程，满 10 分钟回空闲方可再次预占（期间互斥仍生效）。

**例外（跨区调配，REG-003/REG-005）**：区域/大区资源不足时，总部审批后可**借用他区（含跨岛）端口**：借用期间端口归属区不变（台账与区域报表口径不变，见 CHG-OSS-009），预占记录标注"借用"与审批依据，调配记录完整可追溯；跨岛灾备切换（REG-005）演练走同一调配机制并留有切换演练记录。

### OSS-003 核查结果 [有/无/需扩容]；无资源进待资源队列给可选方案

**实现逻辑**：
1. **核查**：订单提交（CT-002）→ 按目标地址经区域树定位（省→城市→Barangay→小区/楼栋→承载节点）→ 检索该节点空闲端口（排除故障/释放中/预占/在用）→ 返回三类结果之一：
   - **有**：返回空闲端口清单（含节点/端口标识）；
   - **无**：该地址无可用端口 → 订单进入**待资源队列**（先进先出），同时给出**可选方案**（相邻分光器/相邻小区可用端口、需扩容）；
   - **需扩容**：目标节点利用率 ≥80%（OSS-004）且无空闲 → 返回"需扩容"并触发扩容预警流程。
2. **待资源队列**：资源释放回空闲 / 扩容验收资产入库（OSS-006）后，队列自动匹配（按提交时间），匹配成功通知订单重新核查→预占；匹配阈值与超时升级见遗留事项。
3. **一致性保障**：核查结果与台账真实状态一致（REQ-OSS-001 误判率验收；台账实时准确性由 OSS-001 状态机 + 现场回传 + CONS 每日核对兜底）。

**例外（现场发现端口故障）**：装维现场发现预占/核查端口故障 → 回传异常 → 端口改 FAULT 并通知订单**重新核查**（原结果作废，按新结果处理）。

### OSS-004 利用率 ≥[80]% 预警进扩容流程（区域→总部→扩容→入库）

**实现逻辑**：
1. **利用率统计**：按承载节点（OLT 上联/分光器）统计端口利用率（在用+预占 / 总容量）；定时与事件（状态变更）双触发。
2. **预警与扩容流程**：利用率 **≥80%** → 自动预警 → 生成**扩容申请**：区域发起 → 总部审批 → 立项（建设项目，OSS-006）→ 扩容实施（设计→施工→验收）→ **资产自动入库**（验收后新设备/新端口进入台账，状态=空闲可分配）→ 待资源队列自动匹配消化积压订单。
3. **阈值口径**：80% 为规则阈值（OSS-TC3 用 85% 验证 85≥80 触发，口径一致）；精确统计口径（按端口数/按容量）见遗留事项。

**例外**：规则表无例外项；扩容申请审批时效与积压订单升级机制见遗留事项。

### OSS-005 静态 IP：申请→分配→绑定→回收（退订后 [7] 天）；同一 IP 同时一客户

**实现逻辑**：
1. **申请**：企业/大客户静态 IP 申请（订单/专线流程）→ 从目标区域+品牌可用子网（Subnet）选地址。
2. **分配**：地址状态 空闲→预占（申请受理）→绑定（随业务开通）→已分配；**分配无冲突**（预占/已分配/回收中均不可再分配；静态与动态池隔离）。
3. **绑定**：绑定客户/订阅（认证侧同步绑定生效，与 AG-05 联调，CHG-AAA-007 已记录：退订即解除认证侧 IP 绑定，回收期仅约束再分配）。
4. **回收**：退订事件触发 → **立即解绑**（发布事件供认证侧解除绑定，不等回收期）→ 地址置 **回收中 [7] 天**（期内不可分配）→ 7 天满回空闲可再分配。
5. **同一 IP 同时一客户**：分配/绑定强校验（已分配/回收中/预占即拒绝），保障任一时刻一 IP 仅一客户（AMS-003 同端口约束同源）。

**例外**：规则表无例外项；动态地址池（PPPoE/DHCP）由 AG-05 按池消费，本域仅管理池划分与统计，不参与会话级分配。

### OSS-006 建设管理：扩容/专线/灾备建设项目化（设计→施工→验收→资产入库）；建设工单与资源预占联动

**实现逻辑**：
1. **项目化**：扩容/专线/灾备三类建设统一为建设项目（ConstructionProject），状态流=立项→设计中→施工中→验收中→已验收→已关闭；各类项目走统一阶段（REQ-OSS-008 验收"建设项目闭环"）。
2. **设计→施工**：设计阶段确定新增端口/纤芯/机房设备清单；施工阶段建设工单执行；**建设工单与资源预占联动**——建设涉及的端口/纤芯在施工期间置"建设中"（不参与分配），专线项目可对目标端口先行预占登记。
3. **验收→资产自动入库**：验收通过 → 按施工清单自动生成资产（贴标/序列号，一资产一标签）→ 资产置"入库"（AMS-001 STOCKED）→ 关联端口资源激活为"空闲"进入可分配池 → 触发待资源队列匹配（OSS-003/OSS-004 闭环）。

**例外（建设与资源预占联动）**：验收后资产自动入库为硬性动作（不依赖人工补录）；验收不合格项目不触发资产入库，端口保持建设中并退回整改（与 CHG-OSS-010 同口径，见第 5 节）。

### AMS-001 状态流：入库→领用→在用→故障→报废/解绑；变更需触发条件与记录

**实现逻辑**：
1. **状态机**：资产按 1.3 状态集流转：入库（采购入库/建设验收自动入库）→领用（出库扫码）→在用（装维开通扫码绑定）→故障（故障上报扫码/工单）→报废（审批）/解绑（拆机扫码）；**非法流转被拒**（如未领用直接报废、在用直接报废）。
2. **触发条件**：每次状态变更必须携带触发条件（扫码/工单/审批单）并产生生命周期记录（变更前状态、变更后状态、操作人、时间、触发依据），全程留痕（REQ-CONS-005 历史可追溯）。
3. **与库存/在网统一**：入库=进入库存台账（STOCKED）；出库领用=库存数量扣减+资产 ISSUED；在用=在网资产；报废/解绑后资产退出在网（2.7 #1 库存与在网统一口径）。

**例外（标签损坏）**：标签损坏无法扫码 → **手工录入序列号**，与台账核验一致后**补打新标签**（一资产一标签保持），补标记录留痕；标签补打期间资产状态变更以序列号核验替代扫码（核验通过才允许变更）。

### AMS-002 拆机必扫码：未扫码拆机被拦截

**实现逻辑**：
1. **拆机前置**：拆机（退订/移机拆旧/故障拆回）操作必须先**扫码资产**完成"解绑"（资产-端口-客户-地址四码解绑）→ 资产置"解绑"（UNBOUND）→ 拆机流程方可继续。
2. **拦截**：未扫码执行拆机 → **拦截并提示"先扫码解绑"**（AMS-TC1 验证）；拆机工单不推进，资产状态不变（仍=在用），留拦截记录（时间戳、资产、操作人、提示信息）。
3. **联动**：解绑触发端口释放（OSS-001 释放流程）与四码关系解除（CT-009 同步）。

**例外（维修调换）**：旧 CPE 故障返修、新 CPE 调换时**沿用绑定**：走"先扫旧码解绑→领用新码绑定（客户/端口不变）→旧码登记返修"流程，客户侧绑定连续不中断（在线业务不中断为优先）；调换期间状态与绑定转移时点留痕口径见 CHG-AMS-005。

### AMS-003 四码关系 1:0..1:0..1:0..1；同端口同时最多 1 客户

**实现逻辑**：
1. **四码关系**：资产-客户-端口-地址四码绑定关系（FourCodeBinding），关系为 1:0..1:0..1:0..1（一资产至多一客户、一客户至多一端口、一端口至多一地址，双向可空）；**任一码反查其他三码**（REQ-AMS-003，秒级；反查时延与同步时延口径见 CHG-AMS-001）。
2. **唯一性约束**：**同端口同时最多 1 客户**（与 OSS-002 预占互斥、OSS-005 同一 IP 一客户同源）；端口-客户绑定变更必须经预占/拆机等受控流程，杜绝多客户并占。
3. **维护与核对**：绑定/解绑由扫码与受控流程驱动（AMS-001/002 触发条件）；关系变更发布 CT-009（15 分钟同步）；每日核对（CONS-004，REQ-CONS-002：冲突 0 或 [24]h 处理完）。

**例外（盘点期间领用）**：盘点单生成后资产锁定（AMS-005），盘点期间发生领用需求 → **领用走例外**：例外领用需区域资产负责人审批，被盘点资产不参与领用，盘入差异单独记录并纳入差异清单（流程细则见 CHG-AMS-002）。

### AMS-004 安全库存 [50] 台/地点；低于自动采购建议；批次质保临期 [3] 个月提醒

**实现逻辑**：
1. **安全库存**：按"物料 + 地点"维护安全库存，默认 **[50] 台/地点**（按物料类别参数化见 CHG-AMS-004）。
2. **自动采购建议**：库存检查（每日定时 + 出入库后触发）：任一"物料×地点"库存 **低于安全库存** → 自动生成**采购建议**（物料、地点、当前库存、安全库存、建议补货量）→ 通知采购岗（AMS-TC3 验证）；建议处理（生成采购单/关闭）留痕。
3. **批次质保**：按批次维护质保到期；**临期 [3] 个月**自动提醒（通知采购/仓管，可续保/置换处理）；质保信息随出入库扫码实时更新。
4. **账实一致**：出入库全程扫码，库存与实物一致率验收（REQ-AMS-006，参数见遗留事项），盘点（AMS-005）兜底。

**例外**：规则表无例外项。

### AMS-005 盘点单生成后资产锁定不可状态变更；盘盈/盘亏逐条处理，盘亏需审批

**实现逻辑**：
1. **盘点单**：按区域/小区/楼栋/机房批量生成盘点单（范围快照：资产清单+期望位置）；**生成即锁定**——范围内资产禁止任何状态变更（领用/报废/拆机等被拒，留拒绝记录）。
2. **扫码盘点**：按盘点单逐项扫码核对（实物存在性+位置）；差异（盘盈/盘亏/位置差异）自动生成**差异清单**（AMS-TC2 验证）。
3. **逐条处理**：差异逐条闭环——盘盈（实物在账不在/多出）→ 补录入库；盘亏（账在实物不在）→ **需审批**（审批层级见 CHG-AMS-003）后核销；位置差异→更正台账；处理完逐条置"已处理"，盘点单关闭并解锁资产。
4. **账实闭环**：盘点差异处理结果回写台账与库存（与 AMS-004 账实一致联动），支撑账实相符率验收（2.7 #1）。

**例外**：规则表无例外项；盘点期间领用例外见 AMS-003 例外（CHG-AMS-002）。

## 3. 用例通过记录（验证设计，未运行）

### OSS-TC1 预占互斥（2 单并发核查同一端口→仅 1 成功，另 1 返回占用+可选方案）

**验证场景设计（OSS-TC1-S01）**：
- **Given**：目标地址 A 定位到分光器 S1 端口 P1（状态=空闲）；订单 O1、O2 已提交（未预占）；两订单并发发起核查与预占。
- **When**：O1 与 O2 并发对端口 P1 执行核查→预占。
- **Then**：核查阶段两单均可读取（读不互斥，均返回"有"）；**预占仅 1 成功**（如 O1）：P1=预占、登记 O1+72h 时效；O2 预占失败，返回"**占用 + 可选方案**"（同分光器其他空闲端口/相邻分光器/需扩容）；并发冲突按 OSS-002；全程无"两单同占一端口"状态。

**预期证据**：预占成功记录（O1、P1、时间戳、72h 时效）；预占失败记录（O2、P1、冲突原因、可选方案清单）；端口状态留痕（IDLE→RESERVED）；并发预占测试（AG-06 任务卡验收基线）报告：并发预占下双占记录数=0。

**边界注记**：并发预占压测的性能阈值（并发量/响应时延）参数未回填，归入 P1（见遗留事项）；"核查并发读一致"为预占互斥的前置验证点（读-写分离设计）。

### OSS-TC2 释放冷却（订单取消→[10] 分钟回空闲，[5] 分钟冷却不可立即预占）

**验证场景设计（OSS-TC2-S01）**：
- **Given**：O1 预占 P1 成功（P1=RESERVED，时效未到）。
- **When**：O1 取消订单 → 触发端口释放。
- **Then**：先释放后通知（P1 状态先变更，再通知订单域）；P1 置"释放中"；**冷却期（前 5 分钟）内任何预占请求被拒**（含 O2 立即对 P1 预占→拒绝，提示"释放冷却中"）；**满 10 分钟 P1 回空闲**，此后可正常预占。

**预期证据**：释放记录（O1、P1、取消时间戳）；状态留痕（RESERVED→RELEASING→IDLE，时间戳 T / T+10min）；冷却期内预占拒绝记录（O2、拒绝原因=释放冷却）；释放流程参数（5/10 分钟）生效记录。

**边界注记**：用例"[10] 分钟回空闲"与规则"[5] 分钟冷却"的时间关系在基线中未明示 → 建议口径：冷却期含于释放期内（CHG-OSS-004），待需求方确认后固化。

### OSS-TC3 扩容预警（利用率 85%→自动预警生成扩容申请）

**验证场景设计（OSS-TC3-S01）**：
- **Given**：分光器 S1 端口利用率 **85%**（规则阈值 80%，85≥80 触发条件成立）。
- **When**：利用率检查执行（定时/状态变更事件触发）。
- **Then**：自动预警 → 生成**扩容申请**（区域发起→总部审批→扩容项目→验收→资产自动入库→新端口可用）→ 待资源队列（如有积压）自动匹配。

**预期证据**：利用率统计记录（S1、85%、阈值 80%）；预警记录（时间戳、节点、利用率）；扩容申请单（区域、目标节点、申请理由）；扩容流程各环节留痕（审批/立项/验收/资产入库记录）。

**边界注记**：规则阈值 80%（OSS-004）与用例 85%（OSS-TC3）一致；利用率统计口径（按端口数 vs 按容量）与扩容审批时效见遗留事项。

### AMS-TC1 拆机拦截（不扫码拆机→拦截并提示先扫码解绑）

**验证场景设计（AMS-TC1-S01）**：
- **Given**：CPE 资产 A1 状态=在用，关联端口 P1、客户 C1、地址 AD1（四码已绑定）。
- **When**：不扫码对 A1 执行拆机。
- **Then**：**拦截**并提示"先扫码解绑"；资产状态不变（仍=在用）；拆机流程不推进；留拦截记录。

**预期证据**：拦截记录（时间戳、资产号、操作人、提示信息）；资产状态无变更留痕（仍=在用）；拆机工单被拒/未推进记录。

**边界注记**：维修调换（AMS-002 例外）为合法免扫解绑场景，须走专门调换流程（CHG-AMS-005），用例不覆盖该例外。

### AMS-TC2 盘点差异（盘点单生成扫码→差异清单自动生成逐条处理）

**验证场景设计（AMS-TC2-S01）**：
- **Given**：盘点单已生成（范围=区域 R1 某小区/机房，含资产清单）；范围内资产已锁定。
- **When**：按盘点单扫码盘点（实物与台账逐项核对）；期间尝试对范围内资产做状态变更。
- **Then**：差异清单**自动生成**（盘盈/盘亏/位置差异分类）；逐条处理（盘盈→补录入库；盘亏→审批后核销；位置差异→更正）；锁定期间状态变更请求**被拒**（AMS-005）；处理完成盘点单关闭、资产解锁。

**预期证据**：盘点单（范围、锁定记录）；扫码记录（时间戳、资产、实物位置）；差异清单（差异类型、数量、处理状态）；盘亏审批留痕；锁定期间变更被拒记录。

**边界注记**：盘点期间领用例外（AMS-003 例外）流程细则见 CHG-AMS-002。

### AMS-TC3 库存预警（库存低于安全库存→自动生成采购建议通知采购岗）

**验证场景设计（AMS-TC3-S01）**：
- **Given**：地点 L1 的物料 M1（CPE）库存 30 台 < 安全库存 50 台/地点。
- **When**：库存检查执行（每日定时/出入库后触发）。
- **Then**：自动生成**采购建议**（物料 M1、地点 L1、当前库存 30、安全库存 50、建议补货量）并**通知采购岗**；建议处理留痕。

**预期证据**：采购建议单（M1、L1、30/50、补货量建议）；通知记录（采购岗、时间戳）；库存快照。

**边界注记**：安全库存按物料类别参数化建议见 CHG-AMS-004；批次质保临期 3 个月提醒为同机制补充场景（遗留事项中列入补充验证）。

| 要点 | 内容 |
