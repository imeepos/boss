## 二、逐维度评估

### 2.1 需求完整性（80/100）

**已覆盖（良好）**：CRM、产品资费+促销、订单、计费（预付/后付/批发）、支付（GCash/Maya/现金/券）、发票税务（VAT/预扣税/ARN）、应收信用、客服呼叫中心、渠道经销商、资产、资源（端口/IP/纤芯）、认证、设备 CPE（TR-069）、监控告警、GIS、经营分析、门户、通知、品牌区域、批发、系统管理——21 域对中小型+中大型定位是完整的。

**对照大型运营商标准（TM Forum eTOM/TAM）的缺失：**

| # | 缺失能力 | 大型运营商为何必需 | 影响等级 |
|:-:|:---------|:-------------------|:-------:|
| 1 | **营收保障（Revenue Assurance）**：话单/批价稽核、漏单检测、收入差异分析、重处理流程 | 大型规模下分钟级收入流失；菲律宾电信公司标配稽核团队 | 🔴 P0 |
| 2 | **防欺诈管理（Fraud Management）**：重复开户、佣金欺诈、账号共享、异常用量检测 | 预付市场欺诈高发；大型规模欺诈损失可达收入 3-5% | 🔴 P0 |
| 3 | **结算与互连（Settlement/Interconnect）**：对上游/对等互连网间结算 | 大型运营商必然有网间结算与对账（批发域只覆盖转售场景） | 🔴 P0 |
| 4 | **忠诚度/积分（Loyalty/Points）**：积分、兑换、等级权益 | 菲律宾预付竞争靠积分留存（对标 GFiber/PLDT 权益体系） | 🔴 P0 |
| 5 | 网络建设管理（NPM）：专线/扩容建设项目化 | 现仅在专线闭环提及，无独立域 | 🟡 P1 |
| 6 | 采购与供应链（Sourcing）：PO/收货/供应商绩效 | 仅库存含供应商字段，无采购流程 | 🟡 P1 |
| 7 | 营销活动端到端管理（Campaign）：目标→执行→归因 | 促销引擎有，活动效果归因弱 | 🟡 P1 |
| 8 | 集团聚合计费（Bundled/Group Billing）：多账户合并账单 | 大型企业客户常见 | 🟡 P1 |
| 9 | 营收预测与预算 | 经营分析有指标无预测建模 | 🟢 P2 |

### 2.3 AI 落地提示词可用性（72/100）

**已具备（框架层完整）**：
- 19 Agent 任务卡（AG-01~14 + XG-01~04 + AG-X）✅
- 三期调度 + 依赖关系 ✅
- Agent 执行提示词模板（角色/输入基线/职责/约束/验收/输出）✅
- 验收执行流程（域验收→契约联调→闭环→横切→非功能→当期验收）✅
- 里程碑 M1-M6 / 风险回滚 / Hermes delegate_task 协作规范 ✅

**执行层缺陷（导致 AI 直接开工有阻塞）：**

| # | 缺陷 | 后果 |
|:-:|:-----|:-----|
| 1 | **无上下文包机制**：全案 105KB 无法整体注入子代理（上下文有限），每个 Agent 需要"裁剪版输入包"（任务卡+对应章节+用例子集+契约切片），全案未定义此机制 | 子代理拿不到精准上下文，执行偏差/遗漏 |
| 2 | **无验收自动化方案**：85 用例是自然语言，未定义"用例→测试场景→自动化断言→执行框架"的映射与测试数据生成方案 | "逐条验收"无法自动执行，验收靠人工，成本高 |
| 3 | **无多代理协调协议**：并行子代理无法直接通信，契约联调（CT-001~010）缺少执行机制（契约测试/集中集成点/模拟桩） | 域间联调阻塞时无协议可依 |
| 4 | **无迭代/回归机制**：Agent 产出修改后如何回归验收、版本如何管理 | 后期改动破坏前期验收结果无法发现 |
| 5 | **任务卡颗粒度不足**：7.2 任务卡为概要（5-8 行），缺该域完整业务对象/状态机/规则/用例清单（需从全案自取） | 子代理提取成本高、易漏 |
| 6 | **无提示词工程细节**：无 few-shot 示例、无输出格式规范（结构化）、无错误处理与重试上限 | 产出格式不一致，难自动消费 |
| 7 | **无 human-in-the-loop 节点**：里程碑评审"谁批/批什么/怎么批"未定义 | 无人审节点，质量失控风险 |
| 8 | **无交付物规范**：各 Agent 产出格式（文档/代码/测试报告/联调记录）未定义 | 产出混乱，集成验证无法消费 |

### 2.4 结构一致性（85/100）

**发现 1 处矛盾（🔴）**：
- 第四篇 4.1 能力域边界表：资产管理为**独立能力域**
- 第七篇 7.2 AG-02（CRM 域）任务卡：职责仅 2.3.1/2.3.2/2.3.3（CRM/产品/订单），**不含资产**
- 附录 B 跟踪矩阵：REQ-AMS-001~007（资产）→ **AG-02（资产子域）**
- **矛盾**：资产域在任务卡中无归属 Agent，却在跟踪矩阵挂到 AG-02 名下 → 落地时资产域责任不清（且资产属 OSS 侧，挂 CRM Agent 不合理）

**其他一致性良好**：REQ 149 项 ↔ 附录 B ↔ 7.2 任务卡基本对应；CT-001~010 ↔ 7.3 联调表 ↔ 4.4 契约一致；三期划分 ↔ 2.6.6 ↔ 8.2 一致；性能档位 2.6.2 ↔ 附录 A 一致。

### 2.5 可执行性（75/100）

**已可执行**：参数回填（8.1 P1）→ 初始化 → 三期启动 → 域验收 → 闭环验收 → 总体验收，路径完整。

**阻塞点**：2.3 中 1/2/3 项（上下文包/验收自动化/多代理协调）未解决前，AI 无法真正"从需求直接落地"——这是与"可落地实施的 AI 自动化实施文档"定位的最大差距。

## 三、优化完善建议（按优先级）

### 🔴 P0（必改，不影响则"大型+AI落地"定位不成立）

**P0-1 补齐大型运营商 4 个能力域**（新增 REQ + 规则 + 用例 + Agent）：
| 新增域 | 核心需求要点 |
|:-------|:-------------|
| 营收保障（RA） | 批价稽核（话单费率重算）、漏单/少收检测、收入差异分析报表、异常订单复核流程；验收：稽核覆盖率 ≥[X]%、差异处理闭环 |
| 防欺诈（FMS） | 重复开户检测（证件/IP/设备指纹）、佣金欺诈检测、异常用量（超速/超量）告警、风控名单；验收：欺诈命中率/误报率指标 |
| 结算与互连 | 上游/对等结算合同、结算话单、网间对账、争议处理（可与批发域合并扩展） |
| 忠诚度/积分 | 积分规则（消费/续费/推荐）、积分账户、兑换（抵扣/礼品）、等级权益；验收：积分账实一致 |

**P0-2 新增"AI 落地执行包"章节（第八篇扩展）**：按 Agent 定义输入包模板——每个 Agent 启动时注入的裁剪内容 = 任务卡 + 对应 REQ 清单 + 规则/例外子集 + 用例子集 + 契约切片 + 输出格式规范。解决 105KB 无法整体注入的问题。

**P0-3 定义验收自动化方案**：85 用例 → 测试场景分组 → 测试数据生成规则（模拟客户/资产/端口/账单）→ 自动化断言标准 → 执行框架建议（不涉技术选型，只定义"验收必须自动化可复现"）。

**P0-4 修复资产域归属矛盾**：资产域（AMS）独立 Agent（AG-15 或并入 AG-06 资源域，二选一并全文一致）；同步修正附录 B 与 7.2。

### 🟡 P1（应改）

**P1-1 多代理协调协议**：契约联调执行机制（集中集成点/契约测试场景/模拟数据），并行 Agent 间以"契约+事件"为接口，联调由集成验证 Agent 统一执行。
**P1-2 迭代与回归机制**：变更→回归验收→版本升级流程；验收基线冻结规则。
**P1-3 提示词工程规范**：每个 Agent 输出结构化（业务对象清单/规则实现说明/用例通过记录/变更建议），附 1-2 个 few-shot 示例。
**P1-4 测试数据初始化方案**：模拟数据生成规则（数量级、字段分布、场景覆盖）。
**P1-5 human-in-the-loop 节点**：里程碑 M1/M2/M4/M6 评审机制（评审人/材料/通过标准）。
**P1-6 交付物规范**：Agent 产出物清单与格式（含验收自测记录模板）。
**P1-7 集团聚合计费 + FWA/5G 产品预留 + RA 7925 许可细节**。

### 🟢 P2（优化）

**P2-1** 术语表扩充（30→130+ 词条，覆盖全部 REQ 域）；**P2-2** 数据治理/MDM 流程；**P2-3** 营销活动归因；**P2-4** 网络建设域独立化；**P2-5** DPA 跨境细节；**P2-6** 营收预测建模。
