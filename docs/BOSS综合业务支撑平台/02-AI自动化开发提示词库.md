# BOSS 综合业务支撑平台 AI 自动化开发提示词库

> 版本：V1.0（2026-08-17）｜配套：《BOSS综合业务支撑平台-需求全案》V1.2 + 《01-开工检查单》
> 定位：按**软件开发流程**（启动→需求→设计→开发→测试→集成→运维）分模块分步骤，输出**可直接复制使用**的 AI 提示词
> 设计原则：每个提示词**自包含、上下文可控（≤15KB）、可并行、可验收**，适配 AI 子代理上下文能力

---

## 使用说明（上下文管理规范）

1. **输入包机制**：每个提示词的【输入】= 从全案裁剪的切片（≤15KB），不要求 AI 通读全案 105KB；
2. **执行方式**：可用 Hermes delegate_task 并行启动多个独立 Agent；依赖关系按【前置】标注，前置未完成不得启动；
3. **输出规范**：所有提示词要求结构化输出（8.12 格式），便于下一环节自动消费；
4. **验收不降级**：每步验收引用 REQ 编号 + 用例编号（Given/When/Then），不得自行降低；
5. **变更机制**：遇需求矛盾 → 提交"业务变更建议"（8.11），不得臆造规则；
6. **上下文预算**：每 Agent 单次执行上下文 ≤ [15]KB；超限时按【输入】优先级裁剪（先保 REQ+规则+用例+契约切片）。

## P0-1 参数回填与基线冻结

```
【角色】需求基线管理员
【任务】按《01-开工检查单》P1 的 26 项参数（已按全菲律宾覆盖 D 档给出建议值），
      回填《需求全案》全部方括号参数，输出冻结版基线。
【输入】开工检查单 P1 表 + 需求全案 V1.2（仅需检索 [ ] 位置）
【执行步骤】
1. 逐项确认 26 项参数（与需求方确认后采用）
2. 将确认值回填全案所有对应 [ ]（含正文与附录 A）
3. 检查全案是否仍有未确认 [ ]（允许保留的仅"以实际为准"项）
【输出格式】
- 参数确认表（26 项：参数/确认值/回填位置数）
- 未确认项清单（如有）
【验收标准】全案无未确认 [ ]；参数值跨章节一致（grep 抽查 ≥3 处）；基线版本 V1.2F
【约束】不改动任何业务规则与需求条目；参数与 D 档规模一致
```

# 模块 1 需求确认

## R-1 需求一致性审查

```
【角色】需求质量审计员
【任务】审查《需求全案》V1.2F 的 178 项 REQ，发现矛盾、遗漏、不可测项。
【输入】需求全案第二篇（全部 REQ）+ 第三篇规则/用例 + 第四篇契约（CT-001~012）
【执行步骤】
1. REQ ↔ 规则 ↔ 用例 ↔ 契约 四向对照，找出无规则支撑、无用例覆盖、契约悬空的 REQ
2. 检查跨篇一致性（性能档位/区域层级/灾备指标在 2.6/3.5/第五篇是否一致）
3. 输出问题清单（分级 🔴矛盾/🟡缺失/🟢建议）
【输出格式】问题清单表：编号/类型/位置/问题描述/修正建议/影响 REQ
【验收标准】178 REQ 全覆盖核对；🔴 问题为 0（修正后复审）；审查报告归档
【约束】只发现问题与建议，不直接改全案；修正需经变更评审
```
