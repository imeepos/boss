# Q4 容量压测报告

> 时间:2026-08-26｜环境:102 `http://192.168.0.102:28080`(生产部署形态)｜工具:k6(`scripts/load/api-load.js`)
> 场景:登录 → 管理端关键读链路(auth/me、orders、resources、gis/levels、analytics/indicators)
> 账号:admin(只读链路,无写放大)｜阈值(路线图 §2):读 p95<500ms、错误率<1%、登录 p95<800ms

## 1. 结果总表

| 档位 | 吞吐(rps) | 读 p95 | 登录 p95 | 错误率 | 阈值判定 |
|:-----|:---------|:-------|:---------|:-------|:--------|
| 20 VU(基线) | 76.4 | 162ms | 284ms | 0.22%(1) | 通过 |
| 60 VU | 203.5 | 352ms | 634ms | 0.00% | 通过 |
| 100 VU | 277.2 | 574ms | 858ms | 0.00% | 不通过(读/登录 p95 超阈) |

(1) 基线档 analytics/indicators 3 次失败(1343/1346 成功,99.8%),高并发档未复现,判断为慢查询偶发超时,已列为观察项。

## 2. 容量结论

- **满足 SLO 的安全容量:约 200 rps(60 VU)**,读 p95 余量 30%。
- 拐点在 60–100 VU 之间:100 VU 吞吐仅增至 277 rps(+36%)而 p95 劣化 63%,进入饱和区。
- 登录接口(bcrypt)是首要瓶颈:其 p95 随并发线性劣化(284→634→858ms),读接口中位仍在 40ms 内。
- 102 环境以当前配置支撑日常运营(预估峰值 <50 rps)余量充足。

## 3. 建议(进 backlog)

1. 登录链路降耗:bcrypt cost 评估 / 登录限流 + token 缓存(发布列车 §4 灰度观察项)。
2. analytics/indicators 慢查询定位,补索引或预聚合。
3. 复测节奏:每次发布列车全量后跑 20 VU 基线档,数值劣化 >20% 阻断发车。

## 4. 复跑方式

```bash
k6 run -e BASE=http://192.168.0.102:28080 -e LOAD_USER=admin -e LOAD_PASS=<pwd> scripts/load/api-load.js          # 基线 20 VU
k6 run -e TARGET=60 ...   # 容量档
k6 run -e TARGET=100 ...  # 饱和档(预期不通过,用于找拐点)
```
