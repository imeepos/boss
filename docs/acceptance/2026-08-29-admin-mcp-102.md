## 门禁固化

| 门禁 | 内容 |
|---|---|
| `make bossctl-routes-check` | openapi ↔ 三端路由目录漂移(含 admin 480 条) |
| `make route-perms-check` | 服务端 requirePerm 源码 ↔ 路由→permCode 映射漂移(genrouteperms) |
| `go test ./internal/apiroutes/` | 目录⊆注册(防 404 误导面)、过滤语义(全量/零权限/单权限)、user/worker 不受影响 |
| `go test ./cmd/bossmcp/` | admin 目录过滤/模板 key 子集/fail-closed/BOSS_API_KEY 不兜底 admin/跨端路径拒绝 |
| `go test ./internal/httpapi/admin/` | /auth/me 模板 key 回模板授权码集(Authz 同源真相) |

## 机制说明(为何暴露面=账号拥有面)

1. 路由→权限码映射来自服务端唯一 RBAC 装配点(`requirePerm` = 包内唯一 `Authz` 包装),
   `scripts/genrouteperms` AST 提取生成 `internal/apiroutes/admin_perms_gen.go`(491 条)。
2. `boss_routes(admin)` 经 `GET /auth/me` 取账号 permissionCodes(角色 RBAC 快照),
   逐条路由要求"账号持有其全部权限码"才列入目录,与 Authz 中间件语义严格一致。
3. 受限模板 API key 的 /auth/me 回模板授权码集(本批复配:模板主体不回角色全集),
   目录天然只见模板子集。
4. 数据范围不经 MCP 层:所有调用以账号 key 透传,服务端按组织/区域数据范围过滤
   (order list SQL 谓词等),越权单资源 403 `out of data scope`。
