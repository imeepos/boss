# 批量导入入口审计与范围清单

> 2026-09-03｜本期目标：主档列表页直接导入；数据导入中心只追踪记录。
>
> 后续收敛：地址和 Geo 的实际导入入口已迁移至各自业务页，中心页仅保留任务记录。

## 第一批：支持并已迁移

| 页面 | 实体 | 入口 | 依赖/原因 |
|---|---|---|---|
| `/base/account` | 账号 | `account` | 账号主档，依赖角色码；模板使用内置角色码 |
| `/org/company` | 子公司/法人 | `legal_entity` | 法人主档 |
| `/org/department` | 部门 | `department` | 依赖法人 ID |
| `/org/post` | 岗位 | `post` | 依赖部门 ID、角色码列表 |
| `/bss/product` | 产品资费 | `product` | 产品主档，依赖法人 ID |
| `/bss/customer` | 客户档案 | `customer` | 依赖法人、地址、经营区域 ID；需先完成地址与区域主档 |
| `/oss/odn` | 网格/局点/基础设施/核心设备 | `odn_grid` / `odn_site` / `odn_facility` / `odn_device` | 依赖 PRV、城市前缀、网格、局点及设备父级；入口随当前 tab 切换 |
| `/base/address` | 地址层级 | `addr` | 树形主档；父级路径必须先存在 |
| `/base/geo` | 国家与行政区划 | `geo` | ISO/CLDR 基础主档；国家和区划存在父级依赖 |

每个入口复用现有模板、附件选择、Excel/JSON 解析、预览、重复提示、逐行进度、失败行导出和 `POST /import-tasks` 记录登记能力。导入完成后由宿主列表刷新。

## 第二批评估：最终裁定（2026-09-03）

| 页面 | 裁定 | 理由与后续路径 |
|---|---|---|
| `/provision/template` 配置模板 | 永久排除普通导入 | 配置下发对象，字段变更直接影响生产网元下发；需版本化+灰度+回滚的专用流程（provision 域），平面批量行建会绕过兼容性校验 |
| `/boss/site` 官网内容 | 需专用流程 | 富文本/封面/分类/发布状态非平面主档；若做导入需草稿态入库+人工发布两段式（cms 域），不允许直接 PUBLISHED |
| `/ams/asset` 资产台账 | 永久排除普通导入 | 资产编码、生命周期（IN_STOCK/DEPLOYED/…）与四码关联受状态机和审计约束；现有置备接口是单条且有 FK 前置，批量建档需走资产域专用入库批次接口 |
| `/ams/tag` 电子标签 | 永久排除 | 标签绑定/激活属订单环节 5 预绑定与现场扫码（环节 9），普通批量建档绕过四码一致性 |
| `/oss/resource` 端口台账 | 永久排除 | 端口状态（IDLE/RESERVED/USED）受预占与订单状态机管理；批量建端口须走资源扩容流程（expand） |
| `/boss/worker` 师傅分组/师傅台账 | 永久排除 | 分组成员/队长/调度关系是动态组织数据；师傅主档必须经注册审核、实名核验后建立，需专门流程 |
| `/partner/staff` 企业员工 | 需专用流程 | 涉及企业归属（partner 域）、邀请/审核与权限边界；若做导入需 partner 域审核后建账号的专用端点 |
| `/org/region` 经营区域 | 需专用流程 | 四级树和覆盖关系只有查询及专用覆盖操作，无独立创建端点；必须按树/覆盖流程维护 |
| `/org/staff` 组织架构与人员 | 需专用流程 | 聚合页同时操作企业、部门、岗位和账号；应复用对应实体入口，不新增 staff 平面导入 |
| `/org/partner` 入驻申请审核 | 需专用流程 | 入驻申请、审核/驳回和企业开通是状态流程，不能批量写已生效主档 |
| `/boss/site/cats` 官网分类 | 需专用流程 | CMS 引用字典，分类 code 被文章引用时有修改/删除约束 |
| `/boss/knowledge` 知识库 | 需专用流程 | 内容正文、版本、状态和负责人需要内容编辑/审核链路 |
| `/boss/release` 版本发布 | 需专用流程 | DRAFT/GRAY/PUBLISHED/ROLLED_BACK 生命周期要求灰度、白名单、发布和回滚 |
| `/bss/marketing` 营销与积分规则 | 需专用流程 | 券、赠送、积分、等级、任务包含金额/期限/停用等规则语义 |
| `/base/backup` 数据备份迁移 | 需专用流程 | `.jsonl.gz` 归档恢复、选表和恢复任务是运维恢复链路，不是业务实体导入 |

补充永久排除：`/bss/user`（客户聚合派生视图）、`/oss/loaccount`（AAA 状态对象）、`/oss/device`（设备运维/指标列表）、订单/派单/拆机/账务/四码/日志/告警/统计/分析页面及敏感配置页面，均不提供普通批量导入。

裁定原则：主档型+已有单行创建端点+无状态机/审批耦合 → 支持普通导入；反之永久排除或要求域内专用流程。

## 全量排除规则

订单、派单、拆机、缴费、支付、出账、发票、欠费、工单、日志、审计、告警、统计、分析等流程或派生数据不支持普通批量导入。API Key、权限、数据范围、短信、推送、认证、存储和备份恢复等敏感或运维配置不支持普通批量导入。

## 后续开发清单与优先级

1. **P0（仅可靠性修复，不扩张范围）**：地址/Geo 入口按真实 `menu:importer`/`menu:geo` 做前端权限前置；任务登记失败不得静默返回成功；401 中止后刷新已成功写入的宿主列表；任务 kind 未知值原样显示。普通实体仍逐行调用既有创建端点，不能宣称后端事务批量。
2. **P1（专用流程设计）**：CMS 草稿导入→人工发布；资产/标签/端口置备批次（校验 FK、四码、状态机、审计）；企业员工邀请/审核后建号；区域树与覆盖；师傅注册/实名审核；配置模板版本/灰度/回滚。以上均须各域专用契约和任务追踪，不复用普通实体导入器。
3. **P2（契约治理）**：补齐 CMS、配置模板、置备 seed、师傅审核等 OpenAPI 的实际 required 字段、状态约束和响应 envelope；核对 API 与 handler 的 limit、权限和状态归一化漂移。此项先改契约/测试，再评估实现，不等同于增加导入。

## 审计发现与修复状态

- 已修复：地址/Geo 导入入口前端按端点权限置灰并在面板执行层再次阻断；实体导入在 401 中止后刷新已成功写入的列表；任务中心未知 kind 不再静默显示为地址。
- 已修复：地址/Geo 后端在批量写入成功但任务登记失败时返回错误，不再吞掉登记错误或发送完成通知。
- 未在本批修复：实体导入预检/参数读取失败仍采用安全降级；实体创建与任务登记不是同一事务且无补偿幂等；地址权限与地址 CRUD 的 `menu:address`/`menu:importer` 是否应统一，需权限设计确认后再改。
- 契约遗漏待治理：CMS limit 实现/声明不一致；配置模板及置备 seed schema 未完整声明 required 字段；部分列表响应 envelope 不统一。

## 已知边界

- 实体导入是前端逐行调用真实创建端点；重复由列表预检和后端约束共同防护，失败行可导出重试。
- 任务登记需要 `menu:importer`；实体创建还需要对应实体菜单权限。登记失败不会回滚已完成的实体创建，但会向用户显示明确提示。

## 已收敛事项（2026-09-03 复核）

- `import_tasks` 已增加 `total/skipped` 持久化列（迁移 000145），导入中心支持按类型/操作人/时间范围筛选。
- 地址批量导入已改为单事务原子提交，重复地址返回 409 冲突而非 500。
- `isUniqueViolation` 已按 SQLSTATE 23505 统一判定，全部实体唯一冲突均映射为 409。
- 数据库唯一约束核查结论（此前"客户手机号无 DB UNIQUE"为过时结论）：全部实体已具备库级唯一约束——
  `customers.phone`（uq_customers_app_login_phone，000043）、`legal_entities.code`、
  `uq_departments_entity_name`、`uq_posts_dept_code`、`uq_product_offers_entity_name`、
  `odn_device` 复合唯一(prv,city,code)+SNW 部分唯一（000081）、`odn_facility.code` 主键、
  `odn_grid`/`odn_site` 复合主键、`addresses.path` 唯一。预检仅为体验优化，约束即最终防线。
